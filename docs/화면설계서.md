# 화면설계서

> 문서 ID ERGO-UI-001 · 설계 버전 2.0 · 개정일 2026-10-16 · 완성 목표 2026-10-23(Asia/Seoul)

## 1. 화면의 목적과 공통 원칙

사용자가 “다음에 무엇을 확인할지” 알 수 있도록 입력 근거 → 계산 초안 → 조사자 결론 → 설명 → 출력의 순서로 구성한다. 상자 들기도 같은 화면을 사용한다. 작업 종류별 별도 15슬롯 화면이나 자동 사건 하중은 신규 화면에 두지 않는다.

화면은 Electron renderer이며 계산·저장은 Python 서비스에 요청한다. API의 null은 빈 값/미입력, 실제 0은 숫자 0으로 보여 준다. UNKNOWN을 NO로 표시하지 않는다. 필수 누락이 있어도 저장·다른 화면 이동·초안 출력은 가능하며, 실행 오류와 계산 미완성을 구분한다.

이전 1.3 SVG 시안과 목업 실행 경로는 제거했다. 현재 화면은 frontend/desktop.html과 기능별 ES module로 구현한다. 이 문서와 API 계약서가 화면 계약의 기준이며, 구현·실행 증거와 남은 제약은 [검증 대조표](local-verification.md), 모듈 경계는 [모듈 지도](module-map.md)를 따른다.

| 공통 표시 | 의미 |
|---|---|
| 분석 없음 / 최신 / 이전 입력 결과 | NONE / CURRENT / STALE |
| 미요청 / 미계산 / 진행 / 완성 / 미완성 / 실패 / 취소 | 모듈 상태를 그대로 표시 |
| 계산: 해당 / 비해당 / 입력 필요 / 검토 필요 | 호별 규칙 초안 |
| 조사자 결론·사유·근거 | 계산과 별도 영역 |
| GPT 생성 / 대체 설명 / 비활성 / 이전 결과 설명 | 설명의 출처·현재성 |
| 다음 확인 | 규칙 엔진의 누락·진단·검토 사유에서 생성 |

진행/오류는 색상과 문구를 함께 쓴다. 단위를 입력 옆에 고정하고 kg와 kg-equivalent, count/min와 count/hour를 구분한다. 긴 근거는 펼쳐 읽고 편집할 수 있다. 각 화면은 저장 상태와 현재 조사/작업명을 유지한다.

### 공통 시각 스타일

Pretendard와 로고의 보라색(#5C61DB)을 공통 기준으로 쓴다. 주요 실행 버튼과 선택 상태는 보라색, 경고·오류·완료는 각각 의미 색상과 문구로 구분한다. 기본 입력 높이 42px, 카드 모서리 16px·안쪽 여백 24px, 컨트롤 모서리 9px, 카드 제목 18px를 적용한다. 표 내부와 사진 행 보조 버튼은 밀도에 맞춘 작은 크기를 유지한다. 상단 비선택 메뉴의 불투명도는 50%이며 hover·키보드 focus 시 85%, 선택 메뉴는 100%다. 알림은 상단 메뉴 아래에 표시한다. 화면별 열 구성과 이동·저장 계약은 유지한다. 공통 색상·크기 토큰은 `frontend/design-system.css`, 화면별 배치는 각 workspace CSS에서 관리한다.

## 2. 탐색 구조

S01 대시보드 → S02 조사 목록·생성 → S03 작업 목록·개요 → S04 작업 조건·11개 기준 → S05 사진 등록·배정 → S06 분석 결과/수동 확인 → S07 조사자 검토·GPT → S08 출력·전후 비교다. S09는 분석 진행 패널이다. S10 설정은 내부 화면으로 유지하되 사용자용 상단 메뉴에서는 숨긴다.

S04만 완료하고 S07·S08로 이동하는 직접입력 경로를 제공한다. 사진/REBA를 사용하려면 S05·S06을 선택한다. 11개 기준과 REBA는 병렬 결과 카드이며 한 점수로 합치지 않는다.

Windows 창과 실행 중 작업표시줄 아이콘은 기존 LOCO 로고의 원형 심볼을 사용한다. 가로형 로고는 화면 헤더에 유지하며 정사각형 앱 아이콘은 PNG·다중 크기 ICO로 제공한다. 아이콘 변경은 앱을 다시 실행한 뒤 반영한다.

## S01. 대시보드

최근 조사, 작업 수, 최신 결과 여부, 미입력/미검토 작업과 재열기 동작을 보여 준다. 간편 홈의 설정 영역과 고급 대시보드 상단의 설정 탭은 사용자에게 표시하지 않는다. “새 조사”, “조사 열기”를 주 행동으로 둔다. 조사 0건은 빈 상태 안내다. 입력 필요 호 수를 위험 작업 수나 질환 확률로 표현하지 않는다.

## S02. 조사 목록·생성

최초/정기/수시, 조사일, 조사자, 부서, 공정, 제목과 이전 조사일을 입력한다. 수시조사 사유·작업장 상황·근로자 참여·증상조사는 입력받지도 보여주지도 않는다(2026-10-27 소유자 지시: REBA 계산과 그 값을 Excel로 주는 것까지만 한다). LOCO Excel은 빈 고시 서식이나 법정 완성본을 만들지 않으며, 법정 조사 완료를 증명하지 않는다. 목록은 저장한 조사 정보와 작업 수·검토 현재성을 보여 준다. 삭제는 확인창에 조사명·ID·포함 작업 수와 등록 사진 정보·분석·검토·출력 기록의 삭제 영향을 표시한다. 원본 사진과 이미 생성한 Excel 파일은 보존됨을 알린다. 취소와 Esc는 API를 호출하지 않으며, 처리 중에는 확인·취소와 배경 조작을 막는다. 서비스 성공 뒤에만 화면에서 제거하고 실패하면 입력과 선택을 유지한다. 작업 삭제도 작업명·ID와 사진 정보·분석 이력의 삭제 영향을 확인하며, 기존 조사 출력 기록은 보존됨을 안내한다. 백업 선택은 백업 서비스 연결 후 추가한다. 메타 정보 수정 시 기존 검토가 과거 정보에 대한 검토가 되었음을 표시한다.

## S03. 작업 목록·개요

작업명·작업자 코드·방법·자세·작업 높이·하루 작업시간·인원수, 근로자 면담 기반 작업강도/빈도 자기평가, 관찰 유해요인·원인과 개선 제안을 입력한다. 작업강도/빈도는 보고서 설명용이며 법정 11개 계산값으로 사용하지 않는다. GENERAL/OFFICE/REPETITION/POSTURE/HAND_FORCE/LIFTING/IMPACT 선택은 질문 순서만 바꾼다는 도움말을 제공한다. 어떤 템플릿에서도 11개 기준으로 이동할 수 있다.

상자 들기를 선택한 경우에도 중량은 기준별 조건 행, 관찰 하중은 사진별 입력이라는 안내를 보여 준다. “상자 무게 하나”로 모든 들기/사진 결과를 채우지 않는다.

작업 목록 행은 최신 분석, 입력 필요 호 수, 검토 필요 호 수, 사진/REBA 사용 여부, 첫 다음 입력을 보여 준다. 과거 결과 보기와 재분석을 구분한다. 이름 변경도 snapshot과 다르면 이전 결과로 표시한다.

## S04. 작업 조건·11개 기준 입력

상단은 하루 작업시간(min/day), 일회성(YES/NO/UNKNOWN), 예정 기간(month), 연간 작업일(count/year), 공통 근거다. 단기간/간헐적 제외 초안과 비교값을 바로 보여 주되 해당 이유를 펼쳐 읽을 수 있다.

11개 호를 모두 나열한다. 각 카드에는 질적 조건의 YES/NO/UNKNOWN, 단위가 있는 수치, 근거·관찰 시각, 계산 초안·비교값·누락/해석 사유가 있다. 조건 없음은 사용자가 명시하며 템플릿으로 자동 입력하지 않는다.

| 호 | 입력 화면 |
|---|---|
| 1 | 집중 자료입력 등 시간 |
| 2 | 목/어깨/팔꿈치/손목/손의 반복시간 5칸, 합산하지 않는 안내 |
| 3 | 해당 자세의 중복 제거 시간 |
| 4 | 비지지/자세 제한, 4종 자세 시간과 직접 합집합 |
| 5 | 쪼그림/무릎 굽힘 시간과 직접 합집합 |
| 6 | 비지지·집기 중량/힘·시간의 조건 행 |
| 7 | 비지지·한 손 중량/힘·시간의 조건 행 |
| 8 | 중량·하루 횟수의 조건 행 |
| 9 | 중량·위치별 횟수·중복 제거 횟수의 조건 행과 적격 중량 전체 집계 |
| 10 | 중량·분당 빈도·시간의 조건 행 |
| 11 | 실제 충격·시간당 빈도·시간의 조건 행 |

6~11호에는 “조건 추가/삭제”, “하루 조건을 모두 기록했는가”, 집계에 포함한 행 선택, 중복 제거 직접 집계값·근거를 둔다. 한 행의 중량·빈도·시간이 하나의 조건이라는 안내를 제공한다. 여러 행을 자동 더하지 않는다. 합집합과 개별값의 모순·미선택 잠재 적격 행을 관련 칸 옆에 표시한다.

4·5·9호의 결합 쟁점과 자세 해석은 “해석 확인 필요”로 표시한다. 다음 입력 안내를 누르면 해당 호/행/필드로 이동한다. 저장 후 계산을 명시적으로 요청하며 미입력을 0으로 채우는 버튼은 두지 않는다.

## S05. 사진 등록·배정

파일 선택/드롭으로 등록하고 미리보기·파일명·크기·읽기 오류·동의 상태를 보여 준다. 등록 목록과 분석 행을 구분한다. 분석 행은 0..N개이며 표시명·사진 선택·분석대상 체크·행 삭제를 제공한다. 내부 slot_no는 삭제로 재번호를 매기지 않는다.

행마다 카메라 좌우, 화면 전방, 측면 확인, 단일 작업자/전신/통상 작업 여부를 확인한다. 관찰 하중은 무하중/측정/모름과 측정 kg·근거다. 상자 들기도 똑같은 항목을 쓴다. 사진 이름이나 순서에서 사건·하중을 추정하지 않는다.

“같은 사진 경로 연결”은 기존 photo_id와 확인값을 보존한다. “다른 사진으로 교체”는 해당 행 관찰·수동값을 다시 확인하게 한다. 배정 변경의 영향은 저장 전 행 옆에 표시한다. 사진 0건으로 분석 범위를 요청하면 요청 대상 없음 안내를 제공하고 직접입력 흐름은 유지한다.

## S06. 자세 결과·수동 확인·REBA

상단에 pose/tags/reba 요청 여부, 유효 사진 수/N, 모델·전처리 버전, 상태·진단을 보여 준다. 선택 사진 위에 EXIF 보정 좌표·관절·신뢰도를 겹쳐 볼 수 있다. 유효하지 않은 각도는 “측정 불가”와 이유를 표시한다.

몸통/무릎/좌우 위팔·아래팔의 6개 자동 후보를 표시하고 사용자가 고른 후보만 적용한다. 경계 ±5°와 촬영조건 미확인을 표시한다. null 후보를 누르면 기존 수동값이 지워지는 동작을 만들지 않는다. 목/손목/비틀림/쥐기/충격/활동은 현장 확인 칸에서 입력한다.

공통 13개·좌우 각 8개 점수 입력과 추가 사진 태그 관찰을 분리한다. 각 값에 출처·근거·시각을 남긴다. 복사 기능은 대상 사진·필드 선택 후 직접 확인값을 복사한다. 사진 전체에 무조건 같은 값으로 채우지 않는다.

좌우 REBA 구성점수와 누락 항목을 보여 준다. 한쪽만 완성되면 그 결과는 참고이며 사진 총점은 미완성이다. 사진별 관찰 하중과 하중 점수를 함께 표시한다.

간편 흐름의 2단계 1차 REBA와 4단계 최종 REBA는 점수 아래에 1~15 색상바를 표시한다. 구간은 1점 무시 가능(녹색), 2~3점 낮음(연두), 4~7점 보통(노랑), 8~10점 높음(주황), 11~15점 매우 높음(빨강)이며, 범례는 점수 칸과 같은 15열 그리드를 사용해 각 색상 구간 바로 아래에 점수 범위와 위험명을 가운데 정렬한다. 구간 폭에 맞춘 색상선을 함께 표시하고, 좁은 구간의 위험명은 줄바꿈한다. 큰 점수 숫자는 해당 색상 구간과 동일한 색으로 표시한다. 연두·노랑 숫자에는 읽기 쉬운 얇은 윤곽선을 더한다. 현재 점수는 해당 칸의 테두리와 삼각형으로 표시하고 숫자·위험명과 접근성 텍스트를 함께 제공한다. 미계산 점수를 0이나 최저점으로 표시하지 않으며 현재 위치를 표시하지 않는다. 1차 점수의 부담 없음 가정 안내는 유지한다. 최종 설명 생성 시 1차 총점·위험수준과 사진 수를 서버에 전달해 최종 REBA 요약에 연결한다. 점수 차이는 같은 단일 사진 범위와 완성된 최종 점수가 함께 있을 때만 표시하며, 다중 사진 결합·범위 불일치·미완성 또는 현재 작업 입력과 다른 과거 분석에서는 차이와 원인 귀속을 표시하지 않는다. 과거 분석은 STALE 상태와 함께 보인다. 최종 입력과 계산 점수는 변경하지 않는다.

완성 수/N, available_max(완성 사진 최대), full_max(전체 사진 완성 최대)를 구분한다. N=0이나 미완성에서 전체 최대를 0으로 표시하지 않는다. 대표 사진은 완성 사진 중 자동/사용자 선택 여부를 표시하고 최대 집계를 바꾸지 않는다. 기술태그는 관찰 수·비율·분모와 “표본 사진 결과” 문구를 붙인다.

## S07. 조사자 확인·GPT 설명

11개 호별로 계산 초안·비교값·근거·누락/해석 → 조사자 결론 → 유효 결과의 순서로 보여 준다. 조사자 결론은 해당/비해당, 사유·근거·검토자·시각이다. 계산과 다를 때 양쪽 결과와 차이 경고를 함께 표시한다. 조사자 결론을 입력해도 계산 초안의 미해결 사유를 숨기지 않는다.

GPT 영역은 생성 요청, 생성/대체 설명의 출처, 편집, 적용을 구분한다. 입력/검토 상태와 설명 생성 상태는 별개다. 생성 시 전송하는 정보 범주를 안내하고 실패 시 원인과 로컬 대체 설명을 표시한다. 기존 적용문은 실패/비활성 때문에 사라지지 않는다.

summary·1차/최종 REBA 비교 설명·기준별 설명·추가 확인·개선 제안에 근거를 연결해 계산 근거로 이동한다. 제안은 현장 확인이 필요한 선택지로 표시한다. 계산이 변경되면 이전 요약에 대한 설명임을 표시하고 다시 생성/검토할 수 있다.

간편 흐름의 5단계는 사람의 최종 검토 단계다. AI 사진 관찰의 9개 결과와 상태, MediaPipe 사진별 상태·2D 각도·추정 3D 각도·모델 후보·전체 관절 좌표, 좌우 REBA 구성점수·누락·확인 사유와 기술태그를 분석대상 사진별로 확인한다. 3D 추정값과 사진 표본은 REBA 계산·하루 노출량과 구분한다. 자세 결과와 11개 기준 요약을 담은 AI 설명을 읽고 전체 문장을 수정할 수 있다. `생성 원문 확정` 또는 `수정본 확정`을 눌러야 해당 설명이 확정본이 되며, 미확정 초안은 Excel에 넣지 않는다. 새 초안을 만들면 이전 확정본이 남아 있는지와 Excel 반영 상태를 구분해 보여 준다.

“③ 쉬운 설명”은 읽기 화면을 기본으로 한다. 구조화된 설명의 summary와 확인할 항목을 먼저 보여 주고, 1~11호 기준별 상세 설명과 개선 제안은 필요할 때 펼쳐 읽는다. 생성·대체 설명의 출처와 현재성을 함께 표시하며, 내용을 짧게 보이기 위해 원문을 잘라내거나 저장된 설명을 다시 요약하지 않는다.

원문 편집은 별도의 접기 영역에서 펼친다. 편집 영역은 본문 글자 16px·줄 간격 1.8, 최소 높이 320px로 표시하고 내부 스크롤과 세로 크기 조절을 제공한다. 읽기 화면을 나누어 보여 주더라도 편집·적용에는 기존 전체 원문을 사용하며 생성본·편집본·적용본의 저장과 API·계산 계약은 유지한다.

전체 조사 검토는 선택한 분석 ID와 조사 메타 revision에 묶인다. 검토자·시각·메모를 남기며 입력·결론 변경 시 현재 검토 표시가 해제되는 이유를 보여 준다. 미입력 상태에서도 검토 기록·초안 출력은 가능하며 “미완성 포함”이 함께 표시된다.

## S08. Excel 출력·전후 비교

간편 화면과 고급 화면의 기본 출력은 Excel로 유지한다. PDF 모드·출력 카드·버튼·미리보기는 사용자에게 표시하지 않는다. 출력할 조사·작업별 분석을 선택한다. 기본은 각 작업의 최신 분석이고 과거 분석 선택 시 이전 결과로 표시한다. 분석 없는 작업도 선택한 경우 작업 정보는 포함한다. 앱 조사화면은 입력 필요·검토 필요 호 수와 다음 입력을 계속 안내하지만, Excel 미리보기와 저장 파일에는 기록값과 계산 가능한 결과만 보여 준다.

대표 이미지 포함 여부·저장 경로를 선택하고 출력한다. 미리보기는 파일·로그를 만들지 않는다. 실제 출력은 호출 시점 snapshot을 고정하므로 변경된 결과가 있으면 실제 receipt를 보여 준다.

같은 snapshot으로 조사 결과 시트는 실제 기록한 조사 개요·작업 정보와 계산 가능한 결과만 담는다. 부담작업 해당 여부 시트는 입력 이력이 있고 계산 결과가 정해진 기준만 행으로 표시한다. 빈 유해요인조사표·증상조사표 양식은 만들지 않는다. 자세 분석(REBA), 입력한 값, AI 사진 관찰은 실제 데이터가 있을 때만 추가하고, 사람이 확정한 설명이 있으면 쉬운 설명, 비교를 골랐으면 개선 전후 비교를 붙인다. Excel에는 확인사항 시트나 미질문·미입력 항목을 출력하지 않는다. 간편 흐름의 미리보기와 저장 파일은 같은 시트 정의를 사용한다.

전후 비교는 같은 조사의 서로 다른 분석 두 개와 메모를 선택한다. 같은 작업의 과거/현재 또는 같은 조사 내 개선 전/후 작업을 비교할 수 있다. 입력 조건 차이, 호별 계산·조사자·유효 결과, 규칙/촬영 호환성을 나란히 보여 준다.

REBA 규칙·프로토콜·대상 수가 같고 양쪽 전체 완성일 때만 최대 점수의 후−전 차이를 표시한다. 그 밖에는 차이를 공란으로 두고 이유를 적는다. 호별 상태를 합산한 위험 점수·개선율은 표시하지 않는다. 비교 대상이 출력의 최신 선택과 달라도 snapshot에 별도로 포함한다.

## S09. 분석 진행

분석 범위 선택과 시작·취소·상태 조회를 제공한다. 요청하지 않은 모듈은 미요청이며 진행률 100%로 표시하지 않는다. pose는 대상 N 중 처리 수를 표시한다. 전체 처리 종료와 모듈 미완성·입력 필요·검토 완료를 구분한다.

분석/GPT 수행 중에도 저장·다른 작업 조회가 가능하다. 취소·실패해도 입력과 이전 분석을 보존한다. 늦게 끝난 이전 분석은 이력에서 볼 수 있고 최신 포인터를 되돌리지 않는다. 같은 대상의 같은 쓰기 요청이 처리 중이면 해당 동작만 중복 실행을 막고 조회·작업 이동·취소는 허용한다. 응답은 요청 당시 작업·분석·설명 선택에 연결하며, 이후 화면 선택이 바뀌면 현재 화면·선택·안내를 되돌리지 않는다. 분석 진행 상태 조회는 화면이 소유한 분석 한 건에 대해 겹치지 않게 수행한다.

### 공통 저장 연결 안내 · N02 일부

일반 작업 화면에는 DB 경로와 파일 동작을 상시 표시하지 않는다. 저장 연결 확인에 실패할 때만 상단 공통 안내와 다시 확인 동작을 표시하며, 연결을 다시 확인하면 안내를 숨긴다. 상세 경로와 연결 확인 상태는 내부 설정의 “데이터 저장 위치”에서 확인한다. 사용자용 연결 오류 안내는 다시 확인 동작을 제공한다. DB 선택·전환 화면은 이번 구현에 포함하지 않는다.

## S10. 내부 설정과 안내 위젯

MoveNet 모델/전처리·기술태그 기준·REBA/법령 규칙 버전, GPT 사용 여부·모델, API 키 존재 여부, LOCO 안내 위젯 표시/quiet 설정을 보여 준다. 키 원문을 renderer에 전달하지 않는다. 설정의 분석값 변경과 GPT/UI 변경의 영향을 구분한다.

설정 진입은 사용자용 간편 홈과 상단 메뉴에 표시하지 않는다. 내부 S10의 “데이터 저장 위치” 창은 유지한다. 저장된 분석·AI·UI 설정은 기존 계약대로 계속 적용한다. 실제 Python에 지정한 경로와 연결 확인 상태, 경로 복사·폴더 열기·다시 확인 버튼을 이 창에 표시한다. 긴 경로와 한글·공백은 줄바꿈한다. 연결 조회 실패 시 지정 경로를 유지하고 복사·열기를 막으며, 연결된 파일 DB에서만 파일 동작을 허용한다. 작업 중 중복 클릭을 막고 실제 성공 후 안내한다. 브라우저 미리보기에서는 경로를 추정하지 않고 Electron 전용 안내를 표시하며, 메모리 DB에는 파일 동작을 제공하지 않는다.

기존 LOCO 안내 위젯은 누락 항목으로 이동하는 보조 역할을 유지한다. quiet 모드에서는 반복 안내를 줄이며 결과·오류 문구는 본문에도 남긴다. 위젯이 판정·저장·출력을 대신하지 않는다.

## 3. 기존 자료와 화면 검증

1.3 자료는 “이전 형식”과 당시 버전을 표시해 읽는다. 과거 15슬롯은 역사적 화면 의미로만 보여 준다. 일반 작업으로 편집할 때 기존 사진/알려진 수동값을 보존하되 새 관찰 항목은 재확인한다. 명시 저장 전에는 기존 데이터를 바꾸지 않는다.

검증할 화면 흐름은 사진 없는 11개 입력, 상자와 다른 작업의 동일 흐름, 조건별 행 혼합 중량, 사진 0/1/여러 건, 미완성/이전 결과, GPT 실패/편집, 같은 사진 재연결, 조사자 결론 차이, 과거 분석 선택 출력·전후 비교다. 세부 일정·수용 기준은 [요구사항](requirements.md)을 따른다.

로컬 구현 연결: 사진 화면의 단계 버튼은 저장 후 자세 결과·조사자 검토·출력으로 이동한다. 누락 안내는 기준 행/필드 또는 해당 사진의 관찰·하중·경로 입력칸으로 이동한다. 분석 보조 설정 저장과 설명 목적별 생성·편집·적용을 화면에서 제공한다. 과거 결과는 당시 snapshot의 사진 행을 표시해 현재 행 삭제로 열람 내용이 사라지지 않는다. ES module 구성은 module-map.md, 실제 검증은 local-verification.md를 따른다.

## 화면 조작 보완 (2026-10-16)

상단 메뉴와 중복된 작업·사진 화면의 내부 단계 탭은 제거한다. S02는 조사 목록을 전체 폭으로 표시하고 새 조사·목록 항목·선택 조사 수정에서 중앙 편집창을 연다. 편집창은 기본 정보·이전 조사를 좌측 항목으로 전환한다. DOM 입력값은 항목 전환·닫기 시 유지하고 DB 저장은 기존 저장 API로 수행한다. 저장 중 닫기·Esc를 막고 실패하면 창 안에 오류를 표시한다. 저장 시 숫자 범위·형식 오류가 숨겨진 항목에 있으면 첫 오류의 항목과 접힌 상세 입력을 열어 브라우저 검증 안내를 볼 수 있게 한다. 저장 성공 시 닫고 기존 작업 등록 흐름으로 이동한다. TOP 버튼은 각 고급 편집 페이지 오른쪽 아래에 고정하고 움직임 줄이기 설정을 따른다. 고급 편집의 로코 안내 캐릭터는 TOP 버튼 위에 간격을 두어 기본 배치한다. 생성·수정 편집창에는 TOP 버튼을 두지 않는다.

## 간편 흐름 · 적응형 추가 확인 (2026-10-23)

사진·작업 설명 → AI 자동 정리·저장 → 대화 팝업 → 결과 → 검토·설명 → Excel 순서다. 사진 없이 설명으로 시작할 수도 있다. AI가 기존 설명·MoveNet 정보를 먼저 채우고, 실제로 부족한 내용만 팝업에서 한 번에 하나씩 질문한다. 선택지가 있는 질문은 선택지와 ‘모르겠어요’를 기본 표시하며 답변창·답변 보내기는 감춘다. ‘직접 설명하기’를 선택하면 해당 버튼 대신 답변창을 열고 문장을 보충할 수 있다. 선택형 작성 중 ‘모르겠어요’를 중복 표시하지 않는다. 숫자·텍스트 질문은 답변창·답변 보내기·모르겠어요를 기본 제공한다. 답변이 정상 처리되어 다음 선택형 질문으로 넘어가면 작성 영역을 다시 접는다. 초기 작업 설명이나 답변이 AI 실패로 미처리 문장 초안으로 남으면 질문이 달라져도 작성란을 열어 유지한다. AI 오류 재시도는 접힌 작성 영역 밖에서 계속 제공한다. 기본 화면에 항목별 숫자칸이나 질문 목록을 펼쳐 놓지 않는다. 선택값만 답하면 저장 후 다음 질문을 로컬 계획하고, 자유문장 추출과 빈 재시도는 AI로 처리한다. 사용자 화면에는 모델·추론 강도·연결 성공 상태를 표시하지 않고 처리 중·실패만 일반 안내로 제공한다. 모름은 반복하지 않는다. Esc/닫기/나중에 확인과 현재 정보로 결과 보기로 이동할 수 있다. 값·출처·근거는 접힌 요약에 보관하며 사용자가 ‘수정’을 선택할 때만 직접 편집칸을 연다. AI 실패 시 답변을 보존하고 팝업에서 재연결한다. 세부 계약은 [적응형 계약](adaptive-intake.md)을 따른다.

AI 입력 정리·후속 질문·설명·사진 관찰은 공통 설정 계약(ergo/ai_config.py, API 계약서 §6)과 같은 프로세스의 OpenAI client/HTTP 연결 풀을 공유한다. 모델·추론 강도·토큰 한도는 변수이며, 설정 화면은 서버 필드 정의로 렌더링한다. 앱은 AI 요청 한 번을 120초까지만 기다리고 답이 없으면 같은 요청을 다시 보낸다(처음 포함 최대 3번). 시간 초과가 아닌 오류는 다시 보내지 않는다. 구버전 timeout 값은 무시하며, APP_SETTINGS의 기존 JSON·테이블·이전 분석 snapshot 형식은 변경하지 않는다.

## MediaPipe 자세 엔진 개정 (2026-10-22)

자세 엔진·설정·출력의 현행 계약은 [자세 엔진 계약](pose-engine.md)을 따른다. MoveNet 고정 입력/관절/해시 표기는 이전 엔진에 해당한다. 기본 엔진은 MediaPipe Heavy(33점), Full은 비교/선택 가능하며 과거 MoveNet snapshot의 의미는 보존한다. 설정과 프론트는 공통 registry를 소비하고 REBA/11개 계산은 기존 규칙을 유지한다. world_points/3D 분절각은 별도 추정 후보이며 점수에 자동 혼합하지 않는다.

## 내부 PDF 미리보기·저장 구현 (2026-10-22)

S08과 간편 보고서 단계는 Excel 시트 미리보기·저장을 유지한다. 간편·고급 화면 모두 PDF 모드·출력 카드·버튼·작업 선택 체크박스·미리보기를 노출하지 않는다. 원본 PDF API와 서식 자산은 내부 호환 구현으로 유지하며, 사용자 화면의 Excel 흐름을 대체하지 않는다. 내부 `preview_pdf`는 생성 PDF와 페이지 수·미확정/과거 결과 정보를 반환하고, `export_pdf`는 호출 대상 snapshot과 저장 영수증을 반환한다. 세부 계약은 API_계약서.md의 PDF 출력 절을 따른다.

내부 PDF 구현에서도 요청 시작 대상을 고정하고 같은 대상의 중복 요청은 합치거나 기존 요청 관리로 막는다. 사용자 화면에서 호출하지 않으며, 화면 이동 뒤 늦게 온 미리보기/저장 응답이 새 화면을 덮지 않도록 한다. 미리보기 뒤 입력이 바뀌면 저장 시점 snapshot·영수증이 기준이다. 원본 칸을 넘는 긴 작성 내용만 별첨으로 출력하며 분석 상세·빈 슬롯·보완사항은 자동 별첨하지 않는다. 긴 내용의 별첨 처리는 API_계약서.md의 PDF 출력 절을 따른다.

## 추가 확인 진행률과 팝업 배치 (2026-10-22)

추가 질문 팝업 상단에 현재 확인 진행률을 가로 막대와 퍼센트로 표시하고, 확인한 항목·전체 항목·남은 항목 수를 함께 보여 준다. 작업 종류나 조건을 알게 되면 필요한 항목 수가 달라질 수 있으므로 현재 기준임을 안내한다. 모름으로 넘긴 항목도 질문 확인 진행에 포함하며 100%를 계산 완성이나 모든 입력 확보로 표시하지 않는다. 남은 질문이 없어도 입력·검토가 필요하면 결과 화면에서 확인하도록 안내한다. 이전 응답에 진행 정보가 없으면 남은 항목 수만 표시한다.

팝업의 제목·닫기와 하단 이동 버튼은 본문 스크롤과 분리한다. 전역 헤더·푸터·입력창 고정 높이가 팝업에 적용되지 않도록 범위를 나누며 답변창은 글자 16px·최소 높이 120px로 제공한다. 작은 창과 긴 질문에서는 팝업 본문을 스크롤하고 제목·닫기·현재 정보로 결과 보기 버튼은 계속 사용할 수 있게 한다.

## 좌우 묶음 질문 (2026-10-23)

같은 사진 자세 항목의 좌우나 좌우 사진 방향이 모두 미확인 후보이면 한 질문 화면에 왼쪽·오른쪽 선택 영역을 나란히 배치한다. 폭이 좁으면 한 열로 전환한다. 각 영역의 선택 상태를 색상과 `aria-pressed`로 구분하고 ‘모르겠어요’도 각각 선택할 수 있다. 양쪽 응답이 모두 있어야 ‘선택한 답변 저장’을 활성화하며 두 답변을 한 번 저장한다. 미선택 쪽을 0·NO나 반대쪽 답변으로 추정하지 않는다. 알려진 쪽이나 USER 모름은 다시 묻지 않는다. ‘직접 설명하기’, 현재 정보로 결과 보기와 필드 수 기준 진행률은 유지한다.

## 관련 질문 묶음과 처리 대기 (2026-10-23)

현재 미확인인 몸통·목(최대 6개), 다리(3개), 움직임·힘(4개), 양팔·손목 추가 자세(8개), 작업 특징(최대 9개)을 관련 묶음으로 표시한다. 각 행은 항목 설명과 선택 상자로 구성하며 좁은 폭에서는 두 요소를 줄바꿈한다. 기본 ‘선택 안 함’을 실제 NO·0·모름으로 저장하지 않고 하나 이상 선택하면 선택한 항목만 저장한다. 진행 막대의 남은 수는 확인 필드 수이므로 남은 40개가 40번의 질문 화면을 뜻하지 않는다.

처리 중에는 팝업 제목 아래 또는 일반 페이지에 작업 문구·회전 표시·이동 막대·실제 경과 초를 표시한다. 15초/45초 이후에는 대기 안내를 갱신한다. 이 막대는 완료율과 구분하며 임의의 퍼센트·남은 시간을 만들지 않는다. 움직임 줄이기 설정에서는 애니메이션을 멈추고 시간 표시는 유지한다. 팝업 제목·진행률·하단 버튼을 보존하고 긴 목록은 본문에서 스크롤한다. 구조화한 선택값만 저장할 때는 외부 AI를 다시 호출하지 않으며 자유문장 추출·빈 재시도는 AI를 사용한다. 이전 실패로 남은 문장 초안은 선택값 저장과 별도로 보존한다.

## 간편 사진 선택 대화상자 (2026-10-22)

‘1. 사진·작업 설명’에서 사진을 선택/드롭하면 크롭 대화상자를 연다. 초기 선택은 사진 전체이고 드래그로 새 사각형을 그린다. 이동·크기 조절 모드에서는 내부 드래그로 이동하고 네 모서리를 끌어 크기를 조절한다. 좌표·크기 숫자 입력과 원본·선택 영역의 픽셀 수치는 표시하지 않고 마우스로 조절한다. 전체 선택·취소·선택 영역 등록 버튼을 제공하며 크기가 0이거나 사진 밖인 영역은 확인할 수 없다. 취소/Esc는 기존 사진을 유지한다. 작업자의 머리와 발이 포함되도록 안내하며 화면 좌표는 EXIF 보정 원본 픽셀로 변환한다. 확인 뒤 등록된 크롭만 사진 카드·분석·보고서에서 사용한다.


### 간편 1단계 사진 표시 (2026-10-23)

사진이 등록된 칸과 미등록 빈 칸의 표시 영역은 가로 폭을 기준으로 높이를 동일하게 맞춘 1:1 정사각형으로 통일한다. 카드의 제목·설명·버튼은 표시 영역 밖에 둔다. 배경색은 #F5F6FA로 통일하고 등록 사진은 object-fit: contain으로 비율을 유지하며 전체 표시한다. 이는 화면 표시 변경이며 사진 원본·등록된 크롭 파일·분석 입력·좌표·보고서 이미지에는 적용하지 않는다. 다른 단계의 분석 사진 표시는 이번 범위에 포함하지 않는다.


### 간편 작업 설명 입력칸 (2026-10-23)

1단계 ‘어떤 작업인가요?’ 입력칸은 카드 폭에 맞추되 높이를 120px로 고정한다. 글꼴은 본문을 따르고 글자 크기 14px·줄 간격 24px·기본 자간을 적용한다. 긴 내용은 줄바꿈하며 세로 내부 스크롤로 확인한다. 입력 중 높이 자동 확대나 사용자의 크기 조절은 제공하지 않는다. 다른 단계의 답변/설명 입력칸과 저장·AI 요청 동작은 변경하지 않는다.


## 간편 이동 버튼과 임시 저장 (2026-10-23)

1단계의 ‘뒤로 가기’도 하단 버튼 줄의 왼쪽 끝에 두며 ‘자동 정리 보기 / 사진·작업 설명 정리’는 오른쪽에 유지한다. 기존 임시 저장 후 홈 이동 동작은 유지한다.

‘사진·작업 설명 정리’를 눌렀을 때 사진이 있고 사진 측정만으로 1차 점수가 나오면, 그 점수를 AI 정리 결과를 기다리지 않고 곧바로 2단계 ‘자동 정리·1차 점수’ 화면에 보인다. AI가 사진과 작업 설명을 정리하는 동안에는 “AI가 사진과 작업 설명을 정리하고 있어요. 1차 점수는 먼저 보여 드려요.” 상태 줄과 경과 시간을 표시하고, 같은 화면의 뒤로 가기·사진 바꾸기·부족한 부분만 확인·현재 정보로 결과 보기·설명 반영과 저장값 수정은 쓸 수 없다. 처리 중에는 새 요청을 보내지 못하게 하는 기존 잠금이며 요청이 겹치지 않는다. AI 응답이 오면 이전과 같이 대화 팝업을 연다. 응답을 받지 못하거나 연결이 끊기면 1차 점수 화면을 그대로 두고 오류를 알리며, 직접 입력으로 이어 갈 수 있다. 정리 중에 다른 작업이 화면을 차지했다면 늦게 온 응답은 그 화면을 바꾸지 않고, 이 문장을 다른 작업으로 보내지도 않는다. 사진이 없거나 사진 측정만으로 점수를 내지 못하면 이전처럼 상태 줄만 보인다. AI 요청의 시점과 내용은 바뀌지 않으며 ‘정리’ 버튼을 누르기 전에는 AI로 아무것도 보내지 않는다.

2단계 ‘사진·작업 설명’과 5단계 ‘결과 보기’ 버튼의 이름을 ‘뒤로 가기’로 통일한다. 각각 기존의 1단계·4단계 이동 동작을 유지한다. 2·4·5단계의 뒤로 가기는 버튼이 속한 박스의 왼쪽 하단에 두고, 나머지 진행 버튼은 오른쪽에 유지한다.

3단계 ‘추가 확인’ 카드에는 왼쪽에 ‘뒤로 가기’를 두고 오른쪽의 추가 질문·현재 정보로 결과 보기 버튼을 유지한다. 뒤로 가기는 기존 입력과 답변을 유지하며 2단계 ‘자동 정리·1차 점수’로 돌아간다. AI 요청·재계산은 실행하지 않으며 답변 저장·분석 처리 중에는 이동하지 않는다.

간편 화면에서 상단 LOCO 로고 클릭은 ‘홈으로’ 버튼과 같은 이동 함수를 사용한다. 작성 중 내용 임시 저장 후 홈으로 이동하고 저장 실패·처리 중에는 이동하지 않는다. 이미 홈일 때도 대제목은 ‘사진으로 빠른 분석’을 유지한다.

간편 1~6단계 오른쪽 하단에는 위쪽 화살표(TOP)·집(홈으로)·폴더(임시 저장) 아이콘 버튼을 위에서 아래로 세로 배치한다. 위쪽 화살표는 현재 페이지의 맨 위로 스크롤하며 단계나 입력 내용을 변경하지 않는다. 페이지 본문의 기존 ‘홈으로’ 버튼은 ‘뒤로 가기’로 바꾸어 이전 단계 이동으로 연결한다. Excel 페이지에는 기존 검토 이동과 중복되지 않도록 뒤로 가기 버튼을 하나만 둔다. 마우스 올림과 키보드 포커스 시 버튼 왼쪽에 연한 회색 배경으로 기능 이름을 표시하며 각 버튼에 접근성 이름을 제공한다. 대제목 오른쪽에는 같은 버튼을 두지 않는다. 간편 화면의 기존 TOP 버튼은 이 세 버튼으로 대체하고 고급 편집의 TOP은 유지한다. 화면설계 버전과 단계 이름을 반복한 소제목, 단계 목록 옆 홈 버튼은 제거한다. 간편 화면·고급 편집·추가 확인 팝업의 모든 버튼에서 TOP을 제외한 화살표를 제거한다. 본문 설명과 비교 수치의 화살표, 접기·펼치기 표시는 유지한다. 화살표 제거 자체는 버튼의 클릭 동작을 바꾸지 않는다. 중복 정리로 4단계 결과의 ‘입력 보완’과 추가 확인 팝업 상단의 ‘닫기 ×’는 제거한다. 결과 화면은 ‘뒤로 가기’로 추가 확인 화면에 돌아가며, 팝업은 하단 ‘나중에 확인’ 또는 Esc로 닫는다. 첫 단계에서 뒤로 가기는 홈으로 이동하며, 이전 입력 화면이 없는 재열기 결과에서는 사진·작업 설명으로 돌아간다.

임시 저장은 현재 단계와 작성 중 설명·답변·검토자·검토 메모·설명 편집본을 이 PC의 앱 저장소에 한 건 보관한다. 처리 중에는 이동·임시 저장을 막고, 이미 시작된 항목별 자동 저장은 끝낸 뒤 보관한다. 홈으로 이동할 때도 같은 임시 저장을 수행한다. 저장 실패 시 성공으로 안내하거나 홈으로 이동하지 않는다. 홈의 ‘이어서 하기’는 저장한 화면을 복원하며, 작성 중 텍스트를 AI에 자동 전송하거나 재계산·검토 확정·파일 출력을 실행하지 않는다. Excel 단계의 미리보기만 다시 조회한다. 다른 PC에 임시 내용이 자동 동기화되지는 않는다.

기존 미완성 분석의 자동 임시 기록과 수동 임시 저장을 분리한다. 새 분석 시작·자동 임시 기록 버리기로 수동 임시 저장의 조사를 삭제하지 않는다. 복원은 조사·작업·분석의 식별번호와 생성 시각, 작업 입력 revision, 사진 존재를 확인한다. 간편 목록에서 조사를 삭제하는 데 성공하면 같은 식별번호·생성 시각의 조사에 연결된 임시 저장도 제거한다. 삭제 실패나 다른 조사 삭제에는 임시 저장을 유지한다. 홈을 다시 열 때 현재 DB에 조사·작업이 없거나 교체된 기록의 이어서 하기 카드는 숨긴다. 화면 표시 후 기록이 삭제된 경우에도 이어서 하기에서 내부 NOT_FOUND 코드 대신 읽기 쉬운 안내를 표시하고 카드를 숨긴다. DB 전환으로 현재 DB에서 찾을 수 없는 기록은 원래 DB로 돌아갈 수 있도록 임시 내용을 지우지 않으며, 연결 오류나 입력 revision 변경도 임시 메모 삭제의 근거로 쓰지 않는다. 실제 입력·분석은 기존 SQLite 저장과 불변 snapshot 계약을 유지한다. 임시 저장은 조사자 검토 완료 표시를 대신하지 않는다.

## 간편 분석 사진 탭 (2026-10-23)

저장된 분석 재열기에서는 사진 슬롯의 LEFT·RIGHT·FRONT 코드와 기존 ‘왼쪽 사진 / 오른쪽 사진 / 정면·후면 사진’ 이름을 모두 읽어 각 첨부 칸에 복원한다. 복원 방향은 촬영 자세 추정값과 구분하며 정면 사진을 좌우 칸으로 대체하지 않는다. 재열기 후 사진 입력으로 돌아가도 등록된 세 방향을 유지한다. DB·원본 사진·기존 분석 snapshot은 수정하지 않는다.

사진 방향은 상단 선택 버튼으로 표시하며 사진 내부의 중복 방향 라벨은 두지 않는다. 이미지의 접근성 대체 설명은 유지한다.

간편 분석의 공통 사진 영역은 왼쪽·정면/후면·오른쪽 사진을 세로로 나열하지 않고 ‘왼쪽 사진 / 정면·후면 사진 / 오른쪽 사진’ 버튼으로 한 장씩 표시한다. 선택 버튼은 기본 보라색 배경·흰 글자, 미선택 버튼은 흰 배경·보라색 글자로 두 색상 상태만 사용한다. 미등록 방향도 미선택 색상을 유지하되 선택은 막고 사진이 없음을 안내한다. 선택 사진이 없거나 삭제되면 등록된 첫 방향을 표시하며, 사진이 전혀 없으면 빈 상태를 안내한다.

사진 외곽은 가로 폭 기준 1:1이며 밝은 회색 여백 안에 전체 사진을 비율 유지로 표시한다. 관절선·점도 같은 영역에 맞춰 사진과 함께 정렬한다. 기존 공통 사진 영역이 있는 2·4·5단계와 이전 추가 확인 화면에 적용하고, 1단계의 사진 첨부 카드는 유지한다. 사진 전환은 표시만 바꾸며 대표 사진·선택 분석·점수·원본/크롭 파일을 바꾸거나 API 계산 요청을 하지 않는다. 단계 이동과 수동 임시 저장·복원 시 선택 방향을 보관한다.

계산기가 이미 완료한 범위의 작업 특징은 후보와 묶음 서식 모두에서 제외한다. 원래 미확인 값을 NO로 저장하지 않는다. 작업 설명 문장 칸은 접힌 ‘문장으로 더 적기’ 안에 두고(질문 제목으로 앞세우지 않는다), 선택 서식이 페이지에 바로 보인다. 화면에 열거된 남은 작업 특징은 사용자가 명시적으로 한 번 확인하여 NO로 저장할 수 있다. 먼저 작성 중 설명과 직접 선택을 저장하며 새로 알려진 YES, 이전 USER 모름, 이미 확인된 값은 일괄 확인으로 덮지 않는다.

공통 intake POLICY.optional_photo_destinations는 사진 점수를 더 보완할 때의 항목을 정의하고 form_prompt_limit은 한 자연어 안내에 나열할 항목 수를 정의한다. 사진의 미확정 보완 항목만 남으면 기본 팝업을 강제하지 않고, 사용자가 선택해 더 확인할 수 있다. 해당 값은 미확인으로 보존하고 REBA 미완성/현재 정보 출력의 기존 의미를 유지한다. 작업 정보가 충분하거나 사용자가 모른다고 확인한 뒤에는 빈 단계를 건너뛴다. 미전송 설명/직접 수정은 결과 이동 전에 저장한다.

회귀는 test_question_minimization.py와 frontend-question-minimization.cjs에서 계산 완료 시 9개→0개, 남은 특징 한 번 확인, USER 모름/직접 YES 보호, 미전송 설명 우선 처리와 실패 보존을 검사한다. 실제 질문 수는 저장 필드 수 또는 접힌 사진 보완 수와 구분하여 사용자 답변 동작으로 검증한다.

## 사진별 관측값 소유권 (2026-10-23)

사진 자세 값은 같은 원본 사진·신체 부위에만 적용한다. `manual.<scope>.<field>@photo:<photo_id>`가 정식 식별자이며 `photo_id`, 사진 방향, 원래 각도·신뢰도·측정 정책·엔진 근거를 함께 보존한다. 대표가 아닌 사진에서 읽은 값도 저장하지만 대표 사진의 빈 자세를 대신 채우지 않는다. 같은 사진에서 이미 확인한 값과 직접 모름으로 남긴 값은 다시 묻지 않는다. 남은 질문·묶음 서식에는 ‘왼쪽에서 찍은 사진 · 오른팔’처럼 사진 방향과 신체 부위를 표시하고 내부 식별자는 노출하지 않는다.

기존 `@default` 자세 값은 당시 대표 사진에만 연결하는 호환 별칭이다. 이미 저장된 사진별 USER 값·모름을 옛 자동 추정 별칭으로 덮지 않는다. 사진 교체·삭제 시 다른 사진의 사용자 값과 원문·시각을 보존하고 제거된 사진 값은 현재 계산에 투영하지 않는다. 동일 원본·모델 설정·근거를 반복 조회하거나 재시작하면 저장 JSON·revision·근거 시각은 변하지 않는다.

정면·후면의 몸통·목 기울임과 팔 벌림 관측은 원래 사진·신체 좌우별로 보존한다. 한쪽 팔의 최대 각도를 양팔에 복사하지 않으며 확실한 양성 측정만 자동 변환한다. 낮은 신뢰도·점수 경계·손 가림·손바닥 방향 불명확은 확인 대상으로 남긴다. 참고용 목 각도와 추정 3D 좌표는 기존 REBA 확정값으로 승격하지 않는다. 하루 시간·하중 추정, 대표 사진 선택, 양팔 REBA 완성·최댓값 계산은 유지한다.

기존 여섯 테이블과 TaskInput 2.0을 유지한다. `TASK.conditions.intake_session`의 선택 `photo_observations`와 fact 소유권·근거 메타데이터로 저장하며 물리 migration은 없다. 분석·출력 snapshot은 불변이고 Excel 입력 근거는 각 행의 실제 사진 식별자로 조회한다. 같은 범주값인 두 사진도 각자의 각도·인용을 유지한다. 세부 계약과 검증 한계는 [사진별 검증](verification/2026-10-23-photo-ownership.md)을 따른다.

### 명시 총시간과 불필요 계산 메타데이터 (2026-10-23)

원문을 그대로 복사한 단일 확정 하루 총시간과 제안 수치의 단위 환산이 직접 일치하면, AI가 함께 붙인 불필요한 합산 메타데이터 때문에 그 값을 거절하지 않는다. `grounding.DIRECT_TOTAL_POLICY`가 이 우선순위와 부정·불확실 경계를 관리한다. 예: “하루 전체 실제 작업시간은 5시간입니다”의 300분은 직접 저장하며, 별도 작업 피연산자가 인용에 없다는 이유로 재질문하지 않는다. 원 AI 제안의 calculation과 결정·원문 연결은 이력에 그대로 보존하고, fact에는 검증하지 않은 합산 근거를 저장하지 않는다. 틀린 총값·단위·잘린 복합 시간·범위·부정·불확실 총시간은 이 우선 규칙으로 허용하지 않는다. 단일 명시 총시간이 없는 합산은 기존 원문 피연산자·단위·순서·중복·산술 검증을 계속 거친다. DB 스키마·기존 snapshot·USER 우선권은 바꾸지 않는다.



## 사진 각도 시각화 (2026-10-23)

공통 사진 영역은 선택 사진의 관절과 함께 측정 각도의 기준선·호·부위명·숫자를 표시한다. 측면은 몸통(골반→어깨와 수직), 위팔(어깨 기준 몸통 하향선→팔꿈치), 아래팔(팔꿈치 기준 위팔 연장선→손목), 무릎(무릎 기준 허벅지 연장선→발목)을 사용한다. 아래팔·무릎은 관절 안쪽 각도가 아닌 기존 굽힘각이며, 화면의 수치와 다른 각도로 호를 그리지 않는다. 정면 후보는 어깨·골반 중점의 수직 대비 몸통 기울임, 몸통선 대비 어깨 중점→코의 목 기울임 추정, 몸통 하향선 대비 양팔 중 큰 벌림을 사용한다.

표시값은 기존 서비스 수치를 그대로 사용하고 원본 좌표로 같은 기준이 성립하는지 대조한다. 1차 점수 화면에서는 photo_id가 일치하는 미리보기와 사진별 대안의 수치만 사용한다. 사진 간 최대 요약값을 다른 사진에 붙이지 않고, 촬영 슬롯 이름을 관절 좌우로 간주하지 않는다. 결과·검토 등 공통 사진 탭이 있는 이후 화면에서도 같은 사진의 1차 측정 후보가 있으면 동일한 좌표·수치를 표시하고 사진 아래에 ‘1차 측정 후보’라고 명시한다. 이때 선택 분석 snapshot에 사진이 있는지와 크기 일치를 확인하며 저장된 최종 수치·점수는 변경하지 않는다. 후보가 없으면 선택 분석 snapshot의 같은 사진·행·촬영 방향에서 확인되는 저장 각도만 표시한다.

사진 번호·크기 불일치, 같은 사진의 여러 분석 행으로 출처가 모호함, 원본 값 null, 좌표 누락·프레임 밖·길이 0, 값과 도형 불일치인 각도는 표시하지 않는다. 저장 각도와 같은 사진의 1차 후보가 모두 없으면 새로 추론하지 않고 각도 근거가 없음을 안내한다. 기준선·호·라벨 테두리는 진한 핫핑크(#FF1493)를 유지하고 각도 선은 2px, 라벨 연결선은 1.4px, 테두리는 1.25px의 중간 두께로 표시한다. 글자는 굵게 유지하며 라벨의 가로·세로 중앙에 정렬한다. 라벨은 글리프별 좌표 보정 없이 SVG foreignObject 안의 HTML 영역에 CSS Grid place-items:center를 적용해 가로·세로 중앙 정렬한다. 좌우에는 화면 기준 각각 4px의 여백을 두고 별도 상하 패딩은 추가하지 않는다. 너비는 텍스트 폭에 좌우 여백을 더하고, 높이는 글자 크기의 1.65배로 정한다. 창 크기가 바뀌어도 좌우 4px을 유지한다. 글꼴 로딩 후 너비를 갱신할 때도 같은 중앙 정렬을 유지한다. 드래그 선택 영역의 사방 여백이 같다는 기준은 사용하지 않는다. 사진 아래에는 현재 사진의 각도 및 관절 좌우를 안내하고, 라벨은 사진 영역 안에서 관절·다른 라벨과 겹침을 줄여 배치한다. 사진·분석 데이터·점수·DB 구조·API는 변경하지 않으며 화면 표시만 추가한다.

작업 설명 더하기·수정하기 영역은 안내 문구와 입력란 사이 및 입력란과 설명 반영 버튼 사이에 각각 14px 여백을 둔다.

공통 사진 영역은 유효 좌표·신뢰도가 있는 관절 중 신뢰도 0.3 이상을 기존 점·실선으로, 0 초과 0.3 미만을 흐린 점과 연결 점선으로 표시한다. 낮은 신뢰도 관절이 있으면 ‘낮은 신뢰도 · 위치 확인 필요’를 안내한다. 양 끝 좌표가 있어야 선을 그리며, 신뢰도 0·누락·비정상 값 및 사진 밖 좌표는 표시하지 않는다. 이는 표시 구분이며 각도 후보 채택 기준·최종 점수·저장값을 바꾸지 않는다.

버튼만 담긴 간편 화면 패널은 버튼 행의 추가 상단 여백을 없애 패널 내부 상하 여백을 같게 유지한다.

간편 화면 카드의 첫 소제목은 위쪽 margin을 0으로 통일한다. 검토·설명의 조사자 결론·검토 표시·쉬운 설명과 Excel 카드도 카드 자체 padding만 적용하여 앞 단계와 상단 간격을 맞춘다.

헤더 위치 안내는 고급 편집에서 조사 관리와 현재 페이지, 간편 화면에서 간편 분석과 현재 단계(홈·사진·작업 설명·자동 정리·추가 확인·결과·검토·설명·Excel)를 표시한다. 위치 안내는 클릭 이동 메뉴가 아니며 모드 전환과 간편 단계 렌더링 때 갱신한다.

간편 화면 헤더의 위치 안내(간편 분석 › 현재 단계)는 13px로 표시한다.

간편 홈 최근 분석의 상태 배지는 작업 개수 뒤에 왼쪽 여백 10px을 두어 구분한다.

6단계 Excel 화면은 카드 사이와 미리보기 표 블록 아래 여백을 24px로 확보한다. 시트 탭 버튼 간격은 10px, 탭 아래 여백은 20px로 두어 상자와 표 영역을 구분한다.

Excel 미리보기의 표별 소제목(예: 3-1. 인간공학적 작업·분석 평가 결과표)은 위 여백 40px·아래 여백 16px로 두어 앞 표와 다음 평가 영역을 구분한다.

Excel 미리보기 표 아래 안내사항은 별도 영역으로 묶고, 상단 1px 구분선과 안쪽 여백 16px로 표 영역과 구분한다.

Excel 만들기 전 확인의 누락 항목은 서비스가 제공한 한글 항목명을 유지하며, 사진·기준별 제목 아래 부위별 카드와 항목 목록으로 표시한다. 목·몸통/다리/움직임·힘/왼팔·손목을 분리하고 기존 입력 이동 버튼을 유지한다. 검토 진단과 구조화할 수 없는 안내는 원문을 보존한다.
### 실제 사진의 AI 관찰 (2026-10-23)

사용자가 사진 분석을 요청하는 기존 intake_turn 계획 실행에서 등록된 현재 크롭 사진을 실제 Luna 이미지 입력으로 보낸다. 계약은 `ergo.vision.contract`, 서비스는 `service.photo_vision`이며 모델·추론 설정은 기존 ai_config를 공유한다. 사진별 동작·몸통·목·무릎·좌우 팔·좌우 손목·잡은 모습 9개 관찰과 보이지 않거나 모호한 이유를 보존한다. MediaPipe의 수치 각도와 구분한다. `conditions.intake_session.photo_vision` 및 동일 응답 경로에 사진별 원본/전송 JPEG SHA, task/photo 소유권, signature, raw_response, 연결·진단을 저장하고 base64/EXIF를 DB에 넣지 않는다. 여섯 테이블과 과거 snapshot은 유지한다.

등록 이미지/view/소유권·모델/추론/프롬프트·이미지 정책으로 캐시하며 읽기·재시작·직접 선택 답변·plan=false에는 이미지 API를 호출하지 않는다. 변경된 사진의 최초 요청은 사진별 병렬 실행하며 지연 응답을 시간으로 폐기하지 않는다. 다른 사진이나 삭제·교체된 작업에 이전 결과를 적용하지 않는다. 불확실/안 보임은 NO가 아니다. 허용된 분명한 boolean 자세와 4개 작업 특징의 YES만 별도 검증 경로로 source=VISION에 반영할 수 있다. USER(직접 모름 포함), 텍스트 AI, SAVED, 유효한 POSE를 우선한다. 사진에서 무게·힘·시간·횟수·정밀 각도·법정/의학 판정을 만들지 않는다. 상세는 [photo-vision.md](photo-vision.md)를 따른다.

### 사진 등록 세대와 사용자 사진 상황 우선권 (2026-10-23)

`photo_identity.REGISTRATION_KEY`는 새 PHOTO.metadata_json 행에 UUID를 부여하며 update로 교체하지 않는다. 물리 스키마는 유지한다. legacy 행은 경로/소유 ID로 결정되는 토큰을 읽고 조회 중 metadata를 쓰지 않는다. 사진 signature는 [view,photo_id,원본SHA,등록세대]이며 과거 triple을 호환한다. 같은 SQLite ID·파일경로·바이트·view로 재등록해도 이전 이미지 및 텍스트 사진 응답이 새 등록에 적용되지 않는다.

사용자가 context=NO로 사진 상황을 부정하면 raw 관찰과 캐시는 보존하되 VISION 소유 manual/작업특징 입력은 UNKNOWN으로 돌려 실제 투영값도 해제한다. USER·텍스트 AI·SAVED·POSE 소유 값은 건드리지 않는다. context=YES로 직접 정정하면 같은 이미지 관찰을 재사용하며 추가 이미지 API를 호출하지 않는다. 같은 turn의 텍스트 추출 뒤 저장에도 이 우선권을 적용한다.

### 현재 원문이 사진 AI 추정을 정정하는 경우 (2026-10-23)

원문 인용·대상·단위·사진 소유권 검증을 통과한 현재 텍스트 제안은 이전 source=VISION의 KNOWN/CONFLICT 추정보다 우선해 source=AI,state=KNOWN으로 저장한다. 다른 값은 충돌 재질문으로 만들지 않고, 같은 값도 텍스트 근거로 승격하여 사진 삭제 때 명시한 작업 특징이 사라지지 않게 한다. 과거 원문 인용만으로는 이 승격을 하지 않는다. USER(직접 모름 포함), 기존 텍스트 AI/SAVED/유효 POSE 값과 사진 변경·지연 보호는 유지한다. 사진별 manual 정식 조건과 대표 호환 alias는 같은 사진의 AI 근거를 가리키며 원래 사진 관찰 raw/cache는 수정하지 않는다.

context=NO이면 public 사진 관찰은 계속 보관·표시하되 계산·추출용 known_visual_observations는 빈 목록이다. YES로 직접 정정하면 기존 사진 캐시를 다시 사용할 수 있다. 사진과 무관한 직접 설명값은 유지한다.

## 결과 우선과 재질문 안내 (2026-10-26)

4단계 최종 REBA 패널은 점수를 확정하지 못하면 “아직 점수를 계산할 수 없어요. 빠진 항목: …” 문구를 그대로 둔다. 그 아래에 슬롯의 `score_so_far`가 있으면 “지금까지 확인한 값 기준 (확정 전)” 블록을 더한다. 점수·위험명·색상바와 함께 “확정 점수가 아닙니다” 문장과 “가정한 항목 N개”를 보이고, 사진 상황을 아직 확인하지 않아 사진에서 읽은 값을 빌려 썼으면(`unconfirmed_photo`) “사진 상황(한 사람·전신·평소 작업)을 아직 확인하지 않아 사진에서 읽은 값 K개를 임시로 썼어요”를 덧붙인다. 문장은 “실제 점수는 더 높을 수 있고”를 포함하고, 들고 있는 물건을 모르면 “없는 것으로 계산했어요”를 덧붙인다. 색상바의 접근성 설명은 “지금까지 기준 REBA N점”이며 1차 점수나 최종 점수로 부르지 않는다. 확정 점수 패널에는 이 블록을 붙이지 않고, `score_so_far`가 없으면 점수를 새로 만들지 않는다.

1단계 ‘어떤 작업인가요?’ 입력칸 위에 “이런 것을 말해 주시면 질문이 줄어요: 1년에 며칠 하는지, 하루 총 몇 시간 일하는지, 들기는 무게와 하루 횟수·1분에 몇 번인지, 충격·반복·같은 자세 유지가 있는지 없는지.” 안내를 한 줄 더하고, 입력 예시에 연간 일수와 하루 시간을 포함한다. 말하지 않은 값은 여전히 채우지 않는다.

묶음 서식에서 다시 묻는 항목(`reask`)은 항목 아래에 다시 묻는 이유를 보인다. 사진 자세 항목은 기존처럼 사유를 보이고, 사진 확인·물건 같은 다른 항목도 `reask`이면 사유를 보인다. 처음 묻는 항목의 모습은 바꾸지 않는다. ‘개선 후 다시 비교’ 시작 안내는 “작업 종류·시간·횟수 답변은 그대로 유지되고, 사진 자세 확인은 새 사진 기준으로 다시 물어봐요.”로 실제 보존 범위와 맞춘다.

## 한 페이지 입력 (2026-10-26)

사용자에게 입력을 요구하는 일은 한 페이지(대화상자 하나)에서 끝낸다. 그 페이지를 넘어가면 같은 것을 다시 묻지 않는다. 이전의 작업 특징 1/2 → 작업 조건 2/2 → 결과 → 다시 열기 흐름과 ‘이전’ 버튼, 단계 표시줄, “입력 단계 n/2 · x%” 진행 막대는 없앴다(옛 질문 창은 `form_fields`가 없는 과거 초안에만 쓴다).

- **제목·한 줄 안내.** 제목은 “작업 정보를 한 번에 확인해 주세요”. 그 아래 한 줄 “남은 확인 N개 · 모르면 비워 두세요(미확인으로 남아요)”. N은 아직 답하지 않은 칸의 수이며 자세 체크리스트 전체를 하나로 센다(체크 한 번이 아니라 ‘체크한 뒤 확인 끝’이 한 번의 결정이므로). 남은 것이 없으면 “남은 확인이 없어요 · 저장하고 결과를 확인해 주세요”. 비율(%)은 보이지 않는다.
- **구역과 순서.** 위에서 아래로 ① 작업 특징(아직 답하지 않은 작업 특징 선택 상자와 “선택하지 않은 나머지 작업은 모두 안 해요” 버튼) ② 작업 조건(켜진 작업의 조건·일수·시간·일회성 등) ③ 사진 확인(사진 상황 질문이 맨 위, 그다음 방향·물건 확인) ④ 자세 체크리스트(“확인 끝”과 복사 버튼 포함) ⑤ 사진 자세 직접 고르기(사진이 읽지 못한 각도). 답할 칸이 있는 구역은 열려 있고, 답할 칸이 없는 구역은 아예 나오지 않는다. 사진 확인·체크리스트·직접 고르기 구역은 처음부터 열려 있다(이전의 접힌 ‘사진 점수를 더 확인할 때’ 영역을 없앴다).
- **사진 상황 질문이 먼저.** 사진이 한 사람의 전신이 나온 평소 작업 모습인지 먼저 고르게 하고 “‘예’를 고르면 바로 아래에 자세 항목이 나와요” 한 줄을 보인다. 답하면 같은 페이지 안에서 체크리스트와 직접 고르기 구역이 이어서 나타난다. 작업 특징 선택 상자도 같은 방식으로, 고르면 그 작업의 조건이 같은 페이지에 나타난다(이런 ‘다음 칸을 열어 주는’ 선택 상자는 화면 코드가 알아볼 수 있게 표시한다).
- **선택으로 입력.** 모든 칸은 고르거나 체크해서 답할 수 있다. 숫자 칸(일수·시간·횟수·무게·개월)은 입력창에 추천값 목록을 달아 눌러서 고를 수 있게 하고 직접 입력도 허용한다. 추천값은 미리 채우지 않으며 칸의 허용 최댓값을 넘는 값은 목록에서 뺀다.
  | 칸 | 추천값 |
  |---|---|
  | 1년에 일하는 일수(일) | 100 · 150 · 200 · 220 · 250 · 300 · 365 |
  | 하루 작업 시간(분, 분/일) | 30 · 60 · 120 · 240 · 360 · 480 |
  | 하루 횟수(회/일) | 10 · 25 · 50 · 100 · 200 · 500 |
  | 1분당 횟수(회/분) | 1 · 2 · 3 · 5 · 10 |
  | 무게(kg) | 1 · 5 · 10 · 15 · 20 · 25 |
  | 예정 기간(개월) | 1 · 3 · 6 · 12 · 24 |
- **문장 칸은 질문이 아니다.** 이전의 “설명이 다르거나 더할 내용이 있나요?” 질문 제목과 열려 있던 글 상자는 없애고, 같은 기능을 접힌 “문장으로 더 적기”(글 상자와 “답변 정리” 버튼)에 둔다. 저장하지 않은 글이 남아 있으면 숨기지 않도록 그때만 열려 있다. 이미 정리된 값은 닫힌 “이미 확인한 정보 N개 · 수정하기”에 있다.
- **아래 버튼.** 왼쪽 “나중에 확인”(저장 없이 닫기), 오른쪽 주 버튼 “저장하고 결과 보기 →” 하나. 바로 위에 대화상자 안 안내줄(채움·복사 결과)이 있다.
- **잠금.** 저장·정리 중에는 선택 상자·체크 칸·버튼이 모두 잠긴다.

## 자세 체크리스트와 한 번에 채우기 (2026-10-26)

한 페이지 서식의 ‘자세 체크리스트’·‘사진 자세 직접 고르기’ 구역에는 위에서 아래로 다음이 나온다(체크리스트 구역은 ①②③, 직접 고르기 구역은 ④). ① 사진이 이미 잰 값이 있으면 “사진이 잰 값 N개는 이미 반영했어요. 아래에서 해당하는 것만 알려 주세요.”. ② **자세 체크리스트** 상자: 제목 “해당하는 자세에 체크해 주세요”, 안내 “체크하지 않은 항목은 아래 버튼을 눌러야 ‘해당 없음’으로 채워져요. 저장하기 전에는 아무것도 기록되지 않아요.”, 네 묶음(몸통·목 / 어깨·팔·손목 / 다리 / 작업 중 움직임과 힘)에 체크 칸이 있다. 팔·손목 항목은 한 줄에 왼쪽·오른쪽 칸이 나란히 있다. 맨 아래 버튼 “확인 끝 · 체크 안 한 항목은 해당 없음”과 상태 줄(“체크하지 않은 N개는 아직 비어 있어요. 해당 없으면 위 버튼을 눌러 주세요.” / “모든 항목을 확인했어요. 저장하면 반영돼요.”). ③ 제목 “한 번에 채우기” 점선 상자의 복사 버튼 “왼쪽 팔·손목은 오른쪽과 같아요”·“오른쪽 팔·손목은 왼쪽과 같아요”(비어 있는 쪽과 반대쪽 항목이 서식에 있을 때, 아직 복사할 값이 없으면 흐리게 보이고 위에 올리면 이유가 나온다). ④ 제목 “사진이 읽지 못해 직접 골라야 하는 항목” 아래에 사진이 읽지 못한 각도·상태와 사진 추정·충돌 칸이 선택칸으로 나온다. 체크리스트에 칸이 없으면 ②와 ④의 제목은 나오지 않는다.

체크 칸은 누르는 즉시 값이 되고(저장 전) 체크를 풀면 비어 있는 상태로 돌아간다. 버튼·체크·상태 줄은 화면을 다시 그리지 않고 입력에 맞춰 바로 바뀐다. 정면·후면 사진에서 읽은 값이 있는 항목 아래(체크 칸은 같은 줄 아래)에는 “정면·후면 사진에서 몸통이 옆으로 기울어 보여요 (12.3°). 맞나요? [맞아요, 체크]”, 추정이면 “…보여요, 확신은 낮아요 (9.1°). 맞나요?” 한 줄이 나온다. 사용자가 그 칸을 정하면 줄이 숨고 비우면 다시 나타난다. 확인을 기다리는 충돌 칸 옆에는 보이지 않는다.

버튼을 누르면 대화상자 아래 안내줄에 “N개 항목을 채웠어요. 저장하면 반영돼요. 다르면 직접 고쳐 주세요.”를 보인다(페이지 알림은 대화상자 뒤에 가려져 쓰지 않는다). 사용자가 이미 고른 칸, 사진 추정이 남은 칸, 충돌 칸은 바뀌지 않는다. 채울 칸이 없으면 이유만 안내줄에 알리고 아무것도 바꾸지 않는다. 채운 칸을 사용자가 고치면 그 칸은 사용자가 직접 고른 값이 된다. 저장은 기존 ‘저장하고 … →’ 버튼 하나이며 별도 확인 창은 없다.

입력은 한 페이지에서 끝난다. 그 페이지를 저장하거나 ‘나중에 확인’으로 닫은 뒤에는 입력 창이 저절로 다시 열리지 않고 같은 것을 다시 묻지 않는다. ‘최종 REBA 점수’가 아직 계산되지 않았으면 결과 화면이 ‘지금까지 확인한 값 기준 (확정 전)’ 점수와 가정한 항목 수를 보여 줄 뿐이고, 고치고 싶은 사용자는 ‘입력 수정하기’로 같은 한 페이지를 직접 다시 연다(권유 문구 없음). 적응형 서식이 없는 옛 결과에서는 이 버튼이 없다. 사진 상황(한 사람·전신·평소 작업) 확인에 답하면 같은 페이지 안에서 자세 항목이 이어서 나타난다.

체크리스트 칸의 정직한 안내(2026-10-26 독립 검토 반영). ① 칸마다 그 칸에만 해당하는 이유(사진·측정 설정이 바뀌어 다시 확인, 사진 측정값을 쓰지 않기로 함, 앞면 사진만으로는 확인할 수 없음 등)가 있으면 칸 아래에 글로 보이고 체크 칸과 `aria-describedby`로 이어진다. 두 칸이 같은 이유면 한 번만, 한쪽만이면 “왼쪽: …”으로 쓴다. “결과 계산에 필요한 정보가 아직 없어요” 같은 공통 문장은 18칸에 되풀이하지 않는다. 좌우로 나뉜 칸의 이름은 “항목 · 왼쪽/오른쪽”이다. ② ‘확인 끝’은 정면·후면 사진에서 읽은 값이 줄(“맞나요?”)로 떠 있는 칸을 정하지 않는다. 그 칸은 비워 두고 안내줄과 상태 줄이 “사진이 본 N개는 위에서 ‘맞아요, 체크’나 ‘아니에요’를 눌러 주세요”라고 알린다. 체크 칸에는 ‘아니’로 답할 선택 칸이 없으므로 그 줄에 [맞아요, 체크] 옆 [아니에요](해당 없음으로 직접 선택)가 함께 있고, 좌우 칸의 줄은 “왼쪽 · …”처럼 쪽을 밝힌다. ③ ‘왼쪽/오른쪽은 …과 같아요’ 복사는 ‘확인 끝’을 먼저 누르든 나중에 누르든 같은 결과다. 상대쪽에서 사용자가 고른 값(체크 포함)만 복사하고, 이쪽에서 사용자가 체크·입력·선택한 칸이나 ‘모름/미확인’으로 둔 칸은 바꾸지 않으며, ‘확인 끝’이 대신 채운 ‘해당 없음’은 복사 값으로 바꿀 수 있다. 안내줄의 개수에는 체크 칸이 들어간다. 복사할 칸이 없으면 버튼이 흐려지고, 그 이유(“복사할 값이 더 없어요.” 또는 “오른쪽 값을 먼저 정해 주세요.”)가 버튼 옆에 글로 보인다(마우스를 올려야만 보이는 말풍선에 의존하지 않는다). ④ 사진 상황 확인에 ‘아니오’나 ‘모름’으로 답해 사진을 쓰지 않으면 “사진이 잰 값 N개는 이미 반영했어요”와 “사진이 읽지 못해 직접 골라야 하는 항목” 제목은 나오지 않는다. ⑤ 상태 줄의 “모든 항목을 확인했어요”는 사진 추정이나 충돌로 체크리스트 밖 선택 칸으로 나간 예/아니오 칸까지 모두 정해졌을 때만 쓰고, 남아 있으면 “사진 추정·충돌 N개는 아래에서 직접 골라 주세요.”로 개수를 알린다.
