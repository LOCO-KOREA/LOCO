# 기능정의서

> 문서 ID ERGO-FD-001 · 설계 버전 1.4 · 기준일 2026-10-14 · 데모 개발 기준

## 1. 기능 경계

지원 작업은 `FLOOR_TO_SHELF_BOX_SINGLE_PERSON` 하나다. 같은 작업자 한 명이 같은 중량의 상자를 바닥에서 앞 선반으로 올리고 손을 놓는다. 걷기·몸 돌리기·공동 들기는 데모 범위에 포함하지 않는다. 조건이 다르면 별도 작업이다.

Windows Electron 데스크톱 화면에서 로컬 Python Application Service를 호출한다. Electron은 사진/저장 위치 선택과 화면 표시를 맡고 Python은 pose/reba/burden/explanation/report/storage를 포함한 기존 기능 모듈을 실행한다. preload/main과 Python의 메시지 연결은 API §1.1을 따른다. 사진15장 분석/REBA/고시/SQLite/Excel은 같은 PC에서 수행한다. GPT 설명 요청은 Python explanation이 담당한다.

테스트·가드·운영 차단장치·보안·암호화는 이번 단계에서 추가하지 않는다. 입력 부족/관찰 불명확/분석 실패는 해당 결과에 표시한다. 저장·분석·검토·초안 Excel을 일괄 차단하는 정책으로 만들지 않는다. 수치를 계산할 수 없는 경우 null을 반환하는 것은 계산 의미이며 승인/운영 게이트가 아니다.

## 2. 촬영 프로토콜

### 2.1 작업·카메라 준비

1. 상자 전체 중량을 저울/표기 근거로 `box_mass_kg`에 기록한다. 바닥에서 선반 **상판 윗면**까지 수직 높이를 `shelf_height_cm`에 기록한다. 중량·높이는 양수이며 인원은1이다. 모르면 비워 두고 무게를 추측하지 않는다.
2. 바닥을 높이0으로 잡는다. 줄자/높이 표시로 선반 높이의 절반을 확인한다. 중간 사진은 상자 **바닥면**이 그 높이를 통과하는 순간이다. 상자 중심이나 손 높이가 아니다.
3. 카메라는 작업자 왼쪽/오른쪽 **정측면**에 고정한다. `camera_side`와 작업자 앞쪽이 화면 오른쪽/왼쪽인지 `forward_direction`을 기록한다. 렌즈 축은 수평이며 작업자의 시상면에 직각이다. 기울거나 정면/측면이 섞이면 각도 해석이 달라지므로 위치를 바로잡는다.
4. 삼각대 높이는 무릎/허리 부근에서 전체 동작을 담을 수 있도록 잡는다. 시작·숙임·올림·종료 동안 머리·어깨·팔꿈치·손목·골반·무릎·발목·양발 전체, 상자 전체, 바닥과 선반 상판이 프레임 안에 들도록 거리를 잡고 여백을 둔다. 고정 미터 수를 임의로 요구하지 않는다.
5. 15장 동안 카메라 위치·줌·방향을 유지한다. 가까운 쪽 필수 관절이 상자/선반에 가려지면 그 순간을 다시 찍는다. 먼 쪽 팔은 가려질 수 있으며 자동 각도를 비워 두고 현장 관찰로 수동 범주를 확인한다. 안 보이는 값을 추측하지 않는다.
6. 한 장에 대상은 한 사람이다. 촬영을 위해 동작을 멈추거나 느리게/과장되게 수행시키지 않는다. 같은 조건의 연속된 정상 작업3회를 회차별로 기록한다. 연사에서 지정 사건의 개별 사진을 고를 수 있다. 앱의 동영상 입력은 없다.

### 2.2 회차별 다섯 순간

| 순서 | phase | 촬영 순간·관찰 조건 | load_state | effective_load_kg |
|---|---|---|---|---|
| 1 | CYCLE_START | 상자는 바닥에 있고 손이 상자에 닿기 직전의 시작 자세 | UNLOADED | 0 |
| 2 | LIFT_OFF | 상자 바닥 전체가 바닥에서 처음 떨어진 직후. 바닥 접촉 없고 손이 중량 전부를 받음 | FULL_BOX | box_mass_kg |
| 3 | MID_LIFT | 상자 바닥면이 shelf_height_cm / 2 높이를 통과. 바닥·선반의 외부 지지 없음 | FULL_BOX | box_mass_kg |
| 4 | SHELF_APPROACH | 선반에 처음 닿기 직전. 선반과 틈이 있고 손이 아직 중량 전부를 받음 | FULL_BOX | box_mass_kg |
| 5 | CYCLE_END | 선반에 완전히 놓고 양손을 놓은 후, 다음 작업 전 종료 자세 | UNLOADED | 0 |

cycle_no1..3, slot_no=(cycle_no−1)×5+순서, 총15개. 순서는 위 순서다. 파일명·선택 순서·EXIF 시각은 배정 보조이며 조사자가 사건을 배정한다. 시간 간격을 맞추지 않는다. **10분 관찰이나 일정 시간 간격 촬영을 요구하지 않는다.**

선반40cm·상자높이60cm라면 MID_LIFT는 **상자 바닥20cm**다. 상자 중심20cm라는 불가능한 기준을 쓰지 않는다. LIFT_OFF/SHELF_APPROACH는 실제 하중이 손에 있는 순간을 고른다. 바닥에서 잡기 직전/선반에 닿은 후 사진에 상자 전체 중량을 적용하지 않는다.

사건·지지 상태가 불명확하면 load_state UNKNOWN, effective_load_kg null이다. 점수에 사용할 하중은 phase_verified=YES이며 관찰 load_state가 사건표와 일치할 때만 0/box_mass_kg로 정한다. 불일치는 해당 사진의 하중을null과진단으로 표시하고 다른 사진은 계속 계산한다. 시작/종료가 실제로 무하중인지 조사자가 확인한다. 부분 지지는 교체를 안내하며 임의 보정 하중을 만들지 않는다. 15장은 제품 입력 표준이고 법정 최소 표본 수/시간 대표성을 뜻하지 않는다.

### 2.3 사진 등록·배정

JPG/PNG를 다중 등록하고 EXIF 방향을 적용한 미리보기를 표시한다. 원본은 복사하지 않고 사용자 경로를 참조한다. PHOTO의 기본 키는 photo_id이며 경로·이름·너비·높이·동의 기록을 보관한다. 이번 데모에서 파일/픽셀 해시, 중복 차단, 동의 게이트를 구현하지 않는다.

Electron의 다중 파일 선택창 또는 끌어놓기에서 절대경로를 얻어 import_photos로 전달한다. EXIF 적용 미리보기는 capture의 get_photo_preview(PhotoInfo)→PhotoPreview로 읽고 data_url을 화면에 표시한다. 현재 사진목록/선택 분석 snapshot의 PhotoInfo를 사용하며 표시 이미지와 pose 좌표는 EXIF 적용 후 원본 픽셀 기준을 맞춘다. 화면용 미리보기는 원본 복사·DB 이미지 저장을 뜻하지 않는다.

같은 파일/사진을 여러 슬롯에 배정한 경우 중복 사용 안내를 표시하고 분석은 수행한다. 대표성 부족을 결과에 표시하며 서로 다른15사진을 권장한다. 파일이 없거나 읽히지 않으면 해당 슬롯 ERROR, 나머지는 계속 처리한다. 경로 변경은 재연결하고 사진 내용 교체는 새 photo_id로 등록한다. 원본 변경 자동 감지는 구현 이후 검토다.

## 3. 포즈·각도·사진 태그

### 3.1 좌표와 유효성

MoveNet Lightning singlepose TFLite float16 v4, 입력192×192, 출력17개의(y,x,confidence). 모델/전처리 버전을 분석 snapshot에 기록한다. EXIF 적용→비율 유지 패딩→모델 입력 후 원본 픽셀로 역변환한다. 종횡비를 무시한 정규화 좌표로 각도를 계산하지 않는다. 관절 순서는 [MoveNet 공식 문서](https://www.tensorflow.org/hub/tutorials/movenet)를 따른다.

confidence_min0.5는 제품 품질 기준이다. camera_side의 가까운 쪽 ear/shoulder/elbow/wrist/hip/knee/ankle이 프레임 안이고 모두≥0.5이면 포즈 VALID다. 먼 쪽 관절이 부족하면 해당 각도만 null. 가까운 쪽 불량/카메라 방향 미입력은 INVALID 및 진단을 반환하되 다른 사진 처리는 계속한다.17개 전부가 보여야 한다는 조건은 없다. 여러 사람/전신 가림/비정상 작업 확인은 별도 촬영 주의사항으로 표시한다.

### 3.2 각도 수식

원본 픽셀(x,y)에서 계산 좌표는(forward_sign×x,−y). 앞이 화면 오른쪽이면 sign+1, 왼쪽이면−1. 위는+Y, 앞은+X. tilt_up(v)=atan2(v.x,v.y), tilt_down(v)=atan2(v.x,−v.y)를 도 단위로 계산한다. 각 차이는−180..180으로 정규화한다. 좌우 각각 계산하고 필요한 관절의 최저 confidence를 저장한다.

| angle_code | 정의 | 범위·부호 | 활용 |
|---|---|---|---|
| TRUNK_TILT_VERT | hip→shoulder의 tilt_up | −180..180°, 앞굽힘+, 신전− | 몸통 후보·태그 |
| NECK_TILT_VERT_PROXY | shoulder→ear의 tilt_up | −180..180°, 앞+ | 참고만 |
| NECK_FLEX_TRUNK_PROXY | NECK_TILT_VERT_PROXY − TRUNK_TILT_VERT | −180..180°, 몸통 대비 앞+ | 참고만 |
| UPPER_ARM_RAISE_VERT | shoulder→elbow의 tilt_down | −180..180°, 앞+, 뒤− | 기술 태그 |
| UPPER_ARM_FLEX_TRUNK | UPPER_ARM_RAISE_VERT + TRUNK_TILT_VERT | −180..180°, 몸통 대비 굴곡+, 신전− | 위팔 후보 |
| ELBOW_FLEX | 180−acos(두 벡터 내적/길이곱), elbow→shoulder와 elbow→wrist | 0..180°, 편팔0 | 아래팔 후보 |
| KNEE_FLEX | 같은 수식, knee→hip와 knee→ankle | 0..180°, 편무릎0 | 다리 후보 |

길이0은 null/진단. acos 입력은 수치 오차에 한해−1..1 제한. 몸통은 가까운 쪽을 쓰며 좌우 평균/최댓값으로 바꾸지 않는다. 팔 REBA는 양쪽 각각 계산한다. 목 프록시는 해부학적 목 굴곡각이 아니므로 목 기본점수를 자동 산출하지 않는다.

점수 경계 ±5°는 BOUNDARY_REVIEW 표시다. 오차 보증/확정 차단이 아니다. 자동 후보는 조사자가 ‘값 적용’을 누르거나 수동 범주를 입력한다. 후보를 적용하지 않고 수동값도 없는 범주는 미확인으로 표시하고 총점을 비워 둔다.

### 3.3 태그와 분모

태그는 YES/NO/UNKNOWN. 목 프록시≥20°, 몸통 굴곡≥20°/신전≤−20°, 위팔 수직 올림≥45°는 POSTURE_TECH_V1의 기술 태그다. 고시의 확정 각도라고 표시하지 않는다. 머리 위 손·어깨 위 팔꿈치·몸통 뒤 팔꿈치·비틀림·쪼그림·무릎 접촉은 수동값. 모델에서 손가락/발끝/접촉을 만들어내지 않는다.

태그마다 yes_count, observed_count(YES+NO), valid_pose_count, manual_observed_count, total_slot_count15를 표시한다. sample_ratio=yes_count/observed_count, 분모0이면 null. UNKNOWN은 분모에서 제외한다. 현장 수동 확인은 포즈 INVALID여도 관찰값으로 집계할 수 있으며 manual_observed_count로 구분한다. **사진 비율을 하루 노출시간으로 환산하지 않는다.** 자동 태그는 가까운쪽 각도가 계산될 때만 YES/NO이며 부호를 반대로 해석하지 않는다. 비틀림은 neck_twisted/trunk_twisted, 나머지 수동태그는 같은 이름의 ManualField를 사용한다.

## 4. REBA 모듈

### 4.1 필수 인자

자동 각도는 후보, 적용/수동 범주는 사진별 ManualValue다. 공통 인자와 좌우 팔을 구분한다. 무게는 작업 입력을 참조하며 사진마다 다시 입력하지 않는다.

| scope | field | 값·계산 |
|---|---|---|
| COMMON | trunk_base | 수직1; 0초과..20° 굴곡/신전2; >20..60° 굴곡 또는 >20° 신전3; >60° 굴곡4 |
| COMMON | trunk_twisted, trunk_side_bent | 둘 중 하나라도 YES +1. 둘 다여도 한 번만 |
| COMMON | neck_base | 중립/0..20° 굴곡1; >20° 굴곡 또는 신전2; 관찰불가null. 신전은 크기와 무관하게2. 프록시로 자동 추천하지 않음 |
| COMMON | neck_twisted, neck_side_bent | OR +1 |
| COMMON | legs_support, seated, knee_band | 양발안정1/한발·불안정2. 서기 <30° +0,30..60° +1,>60° +2. 앉음 가산0. 무릎은 양쪽을 관찰한 큰 범주이며 한쪽만으로 큰 값을 확정하지 않음 |
| COMMON | shock_force | 급격한 힘 증가/충격 YES +1, NO +0. 사진 한 장에서 추정하지 않음 |
| LEFT/RIGHT | upper_arm_base | −20..20°1; <−20° 또는 >20..45°2; >45..90°3; >90°4 |
| LEFT/RIGHT | arm_abducted_or_rotated, shoulder_raised, arm_supported_or_gravity_assisted | 앞 둘 각각+1, 마지막−1. 위팔 최종점수 하한1 |
| LEFT/RIGHT | lower_arm_base | 60..100°1, 그 외2 |
| LEFT/RIGHT | wrist_base, wrist_deviated_or_twisted | 절댓값≤15°1/>15°2, 편위/비틀림 OR+1. 수동확인 |
| LEFT/RIGHT | coupling | GOOD0/FAIR1/POOR2/UNACCEPTABLE3 |
| COMMON | static_over_1min, small_repeat_over_4min, rapid_change_or_unstable | 각각YES +1, 합계0..3.>1분 정적/>4회/min 작은반복/급격변화·불안정, 현장 기록 |

UNLOADED는 하중0, 물체를 잡지 않는 coupling NOT_APPLICABLE(적용값0)을 확인한다. FULL_BOX는 전체 box_mass_kg와 네 coupling 범주를 사용한다. 중량을 손 수로 나누지 않는다. 하중이 UNKNOWN이거나 필수 인자가 없으면 INCOMPLETE, 해당 total/risk null. 확인하지 않은 부울은 UNKNOWN, 범주는 null.

사진별 좌우 모두 완전하면 높은 total, 동점LEFT. 한쪽 미완전이면 전체 total/risk도 null이며 완전한 쪽은 참고로만 표시한다. 포즈 INVALID라도 현장 수동 범주가 모두 있으면 수동 REBA 계산 가능하다. 사진 자체가 없으면 사진별 점수는 null이다. 누락값을0으로 계산한 잠정 총점은 없다.

### 4.2 자동 후보·세 가지 편집 범위

reba가 각도에서 RebaSlotResult.candidates를 만든다. 각 슬롯에 아래6개 후보 자리를 반환하고 slot_no/photo_id/scope/field/proposed_value/angles/min_confidence/review_reasons/diagnostics를 담는다. 다른 수동값이 없어도 후보는 반환한다. UI는 점수 구간을 다시 계산하지 않는다.

| scope·field | 근거 각도·제안 규칙 |
|---|---|
| COMMON.trunk_base | camera_side의 TRUNK_TILT_VERT, §4.1 몸통 구간 |
| LEFT/RIGHT.upper_arm_base | 해당 측 UPPER_ARM_FLEX_TRUNK, §4.1 위팔 구간 |
| LEFT/RIGHT.lower_arm_base | 해당 측 ELBOW_FLEX, §4.1 아래팔 구간 |
| COMMON.knee_band | 양쪽 KNEE_FLEX의 큰 값, UNDER_30/FROM_30_TO_60/OVER_60 |

필요 각도는 필요한 관절이 프레임 안이고 confidence≥0.5일 때 사용한다. 무릎 후보는 양쪽 각도가 모두 있어야 하며 먼 쪽이 가려졌으면 proposed_value=null이다. 나머지 후보도 필요한 각도가 없으면null과 진단을 반환한다. min_confidence는 근거 각도 전체의 최솟값이며 근거가 부족하면null이다. 포즈 전체 INVALID와 개별 각도의 사용 가능 여부는 구분한다. 몸통 −20/0/20/60°, 위팔 −20/20/45/90°, 아래팔60/100°, 무릎30/60° 경계 ±5°이면 BOUNDARY_REVIEW를 표시하며 제안값은 유지한다. 목·손목·비틀림·지지·손잡이·충격·활동은 자동 후보가 아니다.

‘값 적용’은 제안값을 해당 사진의 ManualValue에 source=AUTO_ACCEPTED로 넣는 일반 편집이다. evidence.source=OTHER, text에는 적용한 근거 각도/측/최저 confidence, observed_at에는 적용 시각을 기록한다. 후보 자체가 확정 인자를 자동 채우지 않는다. null 후보는 기존 수동값을 덮어쓰지 않고 아직 값이 없는 칸만 미확인으로 남기며 다른 사진의 적용은 계속한다. 직접 관찰/면담은 기존 DIRECT_OBSERVATION/INTERVIEW 출처를 사용한다. 목의 선택 자세문구는 neck_base의 evidence.text에 기존 근거와 함께 기록하며1/2 점수만으로 신전 여부를 추측하지 않는다.

S06은 세 범위를 제공한다. ① 사용자가 고른 사진들에 공통 관찰값 적용 ② 같은 촬영 순간의3회차 사진 편집 ③ 한 사진만 수정. 같은 순간은 CYCLE_START=1/6/11, LIFT_OFF=2/7/12, MID_LIFT=3/8/13, SHELF_APPROACH=4/9/14, CYCLE_END=5/10/15다. 자동 후보 일괄 적용은 **각 대상 사진 자신의 후보**를 사용한다. 직접 관찰값 복사는 사용자가 선택한 필드/대상에 같은 관찰이 성립할 때 사용하며, 다른 사진의 각도 범주를 자동 복사하지 않는다. NO/안정지지/좋은손잡이 등을 기본값으로 채우지 않는다.

편집 결과는 (slot_no,scope,field)로 현재 manual에 합치고 선택하지 않은 값은 보존한다. photo_id는 대상 슬롯의 현재 사진ID다. 과거 후보를 현재 입력에 사용할 때 사진·카메라·작업맥락·모델/전처리가 달라졌으면 대응 후보는null/재계산 안내로 취급하고 다른 값은 계속 저장한다. 빈사진 슬롯은 manual을 만들지 않고 미확인 안내를 남긴다. 전체 ManualValue[]를 set_manual_values로 저장한 후 recalculate_reba를 호출한다. 템플릿/그룹 DB 테이블이나 승인 단계를 추가하지 않는다.

## 5. 부담작업 모듈

### 5.1 수치와 입력

[고시 제2020-12호 제2·3조](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=2100000185793)가 수치 기준이다. 해설·KOSHA·REBA로 고시를 변경하지 않는다. 현행성/미확인 해설은 구현 이후 검토하며 현재 보고서에 근거 버전을 표시한다.

short_term/intermittent는 조건 입력에서 파생한다. one_off YES이고 planned_duration_months≤2이면 단기간YES. one_off NO 또는months>2이면NO, 나머지UNKNOWN. annual_work_days≤60이면 간헐YES,>60이면NO,null이면UNKNOWN. 음수/비정상 기간·일수는 해당 제외값을UNKNOWN과입력진단으로 표시한다. 유효한 입력에서 둘 중YES면11개 모두 NOT_APPLICABLE+제외사유다. 둘 다NO가 아니어도 확실한 수치 미달은 비해당으로 끝날 수 있다. 제외여도 REBA를 계산한다.

시간은 하루 소정+연장근로 중 조건을 실제 수행한 누적 min이다. 총 작업시간과 조건시간은 다르다. 중첩은 한 번만 센다. **사진 비율×작업시간 환산 금지**. 반올림 전 값으로 ≥/≤ 비교하고 표시만 두 자리다. 일일 시간0..1440, 조건시간≤daily_work_min. 범위밖/모순은 해당 기준의 INPUT_CONFLICT다. daily_work_min 누락은 시간범위 확인이 결론을 바꿀 수 있는 기준의 missing_fields에만 넣고, 시간과 무관한8/9호나 이미 확실히 미달한 기준까지 일괄 NEEDS_INPUT으로 바꾸지 않는다.

condition_present YES/NO/UNKNOWN과 근거를 기록한다. NO는 조사자의 해당 조건 없음 관찰이다. 비해당을 파일/작업종류만으로 자동 가정하지 않는다. 근거 미기입은 주의사항으로 표시하고 저장은 가능하다. condition_present는 각 기준의 AND조건 하나다. AND는 하나라도FALSE이면FALSE, 전부TRUE면TRUE, 나머지UNKNOWN. OR는 하나라도TRUE이면TRUE, 전부FALSE면FALSE, 나머지UNKNOWN이다. 예를 들어6호 집기중량 미달이어도 쥐기힘이 미입력이면 OR그룹은UNKNOWN이다.

각 기준 computed_status는 아래 순서에서 처음 성립하는 결과 하나로 정한다. 전체 입력을 먼저 필수로 요구하는 규칙을 만들지 않는다.

| 우선순위 | 조건 | 결과 |
|---|---|---|
| 1 | 유효하게 확인된 단기간/간헐 제외가YES | NOT_APPLICABLE, exclusion=SHORT_TERM/INTERMITTENT/BOTH |
| 2 | 해당 기준의 비교·제외에 사용하는 값에 범위밖/모순이 있음 | NEEDS_REVIEW, INPUT_CONFLICT |
| 3 | AND조건 그룹 중 하나가 확실히FALSE | NOT_APPLICABLE |

### 5.2 미확인 해석

4·5·9호의 자세별 시간/횟수 그룹은 개별 하나가 기준 이상이면TRUE, 유효하게 기록한 직접union이 미달이면FALSE다. 개별이 모두 미달이고 union만 기준 이상이면 합산 해석이 미결정이다. 최종 computed_status에는 §5.1의 제외/모순/다른 AND조건/누락 우선순위를 먼저 적용한다. 다른 조건과 제외NO가 확인되어야 이 합산 사례가 NEEDS_REVIEW/COMBINATION_RULE로 끝난다. 개별/union 누락으로 결론이 달라지면 NEEDS_INPUT이며 합산 사유도 함께 보존한다. 자세 정의가 미확인 해설에 의존하면 POSTURE_INTERPRETATION. 사진별 수동 관찰과 현장 근거를 보조 증거로 표시한다.

키보드 자율조절 제외 등 본문 밖 해설 규칙은 자동 적용하지 않는다. 공동 들기는 범위 밖이다. 사진/REBA 총점이 없어도 직접 입력으로 고시 초안을 계산할 수 있다.

### 5.3 조사자 결론·검토

computed_status는 APPLICABLE/NOT_APPLICABLE/NEEDS_INPUT/NEEDS_REVIEW.11개 결과를 항상 반환하고 비교값/단위/출처/누락/검토사유를 담는다. investigator_status는 APPLICABLE/NOT_APPLICABLE/null, 조사자 사유·근거는 별도다. 앱 초안은 덮어쓰지 않는다.

데모는 조사자 결론 입력과 검토 표시를 가드로 차단하지 않는다. 입력필요인 초안에 수동 결론을 붙여도 초안의 누락/미완전 표시는 남는다. 사유는 권장 입력이며 빈 값도 저장 가능하다. effective_status는 조사자 결론이 있으면 그 값, 없으면 computed_status. 해당 경고와 REBA 위험을 구분하고 ‘조사자 결론/앱 초안’을 표시한다.

## 6. 분석 스냅샷·재계산

### 6.1 실행 상태

start_analysis는 비어 있는 슬롯을 포함해 항상15결과 자리를 만든다. 각 슬롯은 PENDING→VALID/INVALID/ERROR, 취소 후 미처리는 CANCELED, 치명적오류 후 미처리는 NOT_PROCESSED. 빈 슬롯은 INVALID/MISSING_PHOTO. 포즈 추론이 실패해도 직접입력 고시 계산과 기존/수동 REBA 자료는 사용할 수 있다.

RUNNING→CANCELED(취소), FAILED(치명적오류 또는유효0), PARTIAL_REVIEW(유효1..14), DONE(유효15). terminal_error와15진단은 실패/취소에도 남긴다. DONE은 포즈 완료이며 REBA 완전/검토를 뜻하지 않는다. 이전 성공 결과는 역사 목록에서 그대로 볼 수 있다.

위 상태는 PoseResult.status다. Analysis.status는 RUNNING/FINISHED/FAILED/CANCELED라는 별도 요청 실행상태이며 FINISHED는 요청 모듈 결과/진단을 반환했다는 뜻이다. 포즈FAILED여도 직접고시/수동REBA가 있으면 실행FINISHED일 수 있다.

Electron main은 분석 실행을 Python에 전달한다. Python은 시작 snapshot/분석행을 만든 후 RunHandle을 응답하고 계산을 백그라운드에서 계속한다. S05는 기존 get_analysis로 진행을 조회하고 cancel_analysis로 취소를 요청한다. 장시간 계산을 renderer/main에서 직접 수행하거나 전체15장이 끝날 때까지 진행 조회 요청 처리를 미루지 않는다. 별도 진행 이벤트/상태 테이블을 추가하지 않는다.

### 6.2 단순 버전·영향표

TASK 입력이 바뀌면 input_revision을1증가한다. 분석마다 입력 전체/15배정/수동값/모델/프로필 snapshot을 ANALYSIS에 저장한다. 현재성은 latest_analysis_id와input_revision 일치로 표시한다. 실행중 수정 잠금/예상버전 가드/완료승인 게이트는 없다. 처리중 수정해도 실행은 시작 snapshot으로 끝내며 과거로 표시한다.

| 변경 | 새 분석행에서 필요한 계산 | 재사용 |
|---|---|---|
| 사진/배정/카메라/작업자·방법·높이 | pose,태그,REBA | 직접 고시입력 자체가 그대로면 고시 초안 |
| 모델/전처리 | pose,태그,REBA | 고시 초안 |
| REBA 전용 수동값 | REBA | pose,태그에 영향없는 값이면 태그,고시 초안 |
| 수동 자세 태그 | 태그,공유 REBA인자도 바뀌면 REBA | pose,고시 초안 |
| 상자무게 | REBA,고시 | pose |
| 일일시간/제외/조건별시간·횟수·힘 | 고시 | pose,REBA,태그 |
| 기술태그 프로필 | 태그 | pose,REBA,고시 |
| REBA 규칙 버전 | REBA | pose,태그,고시 |
| 대표사진/설명문 | 표시만 | 계산 전체 |
| 작업명 | 새 표시snapshot | 계산 전체 |

재계산 명령은 현재 입력 snapshot으로 새 ANALYSIS행을 만들고 요청 모듈만 계산한다. 다른 모듈은 관련 입력이 같을 때만 복사하며 달라졌으면null/재계산 안내로 둔다. 포즈가 현재 사진/카메라/모델과 다르면 재사용하지 않는다. 완료 후 최신 요청의 행만 latest_analysis_id가 가리키며 오래된 완료가 이를 덮어쓰지 않는다. 이는 과거/현재 표시 규칙이다.

사진 교체는 해당 슬롯 수동값/사건확인을 비워 두고 새 입력을 받는다. 카메라/작업자/작업방법/높이 변경은 전체 사건확인·수동값을 비워 둔다. 모델/전처리 변경은 AUTO_ACCEPTED 수동값만 비워 두고 같은 사진의 직접관찰값은 남긴다. 고시 초안은 사진 빈도로 계산하지 않으므로 직접 입력이 같으면 유지한다. 이전 조사자 결론/검토는 새 분석에 자동 복사하지 않고 역사로 남긴다. REBA만 재계산한 경우도 초안은 같지만 새 검토 표시가 필요하다. 이 상태는 버튼을 막지 않는다.

재사용 비교 항목: pose는 배정사진/경로/카메라/작업맥락/모델·전처리, 태그는 pose·수동태그값·프로필, REBA는 pose·필수수동인자·사건하중·중량·점수표, 고시는 제외/일일시간·무게·LegalInputs·고시버전이다. 공유 수동필드(목/몸통 비틀림)는 태그와REBA 양쪽에 반영한다. 작업맥락은 작업자/방법/높이다. 미배정 후보사진 변화는 계산 입력을 바꾸지 않는다.

## 7. 검토 표시

기준별 조사자 결론과 조사 전체 ‘검토 완료/해제’를 제공한다. 작업/사진/점수 미완전이어도 사용할 수 있다. reviewed_analysis_ids에 검토한 분석ID와reviewed_metadata_revision을 기록한다. 이후 입력/분석/조사메타가 바뀌면 ‘이전 결과 검토’로 표시한다. 같은 분석의 조사자 결론을 변경/해제하면 전체 reviewed를false로 바꾼다. 대표사진/설명문 편집은 계산검토 표시를 바꾸지 않는다. 완전성은 별도 배지이며 법적 승인 상태로 표현하지 않는다.

## 8. GPT 설명 모듈

15사진은 로컬 pose/reba가 처리한다. GPT는 허용 수치 요약·고정 공개 규칙문으로 설명만 제안한다. 이미지/좌표/이름/경로/자유입력 근거는 DTO에 포함하지 않는다. 미완전 총점은null, 시간은 직접입력만. 별도 보안검증기/수치허용목록 가드를 데모에 추가하지 않는다. 설명은 조사자가 편집하며 계산값에는 반영하지 않는다.

NumericSummary에는 REBA의 NOT_CALCULATED/INCOMPLETE/COMPLETE와 실제 완전수, 고시의 NOT_CALCULATED/CALCULATED를 보낸다. REBA 미계산 완전수는null, 계산한 완전0개는0이다.11개 기준마다 computed_status/investigator_status/effective_status/effective_source, 제외사유, 누락 필드/수, 검토사유와 수치 근거를 보낸다. 미계산 고시의 기준 자리들은 상태/누락수null과 빈 근거배열로 남긴다. 누락 필드는 문서의 고정 입력 필드명이며 파일 경로가 아니다. 초안이 NEEDS_INPUT인데 조사자가 APPLICABLE로 기록했으면 그 두 상태를 구별해 설명한다. 조사자 결론을 입력 완전성이나 법적 승인으로 바꾸지 않는다.

API 키는 실행환경 OPENAI_API_KEY를 사용하며 OS 키관리/암호화는 이후 검토한다. timeout10초, 요청 실패는 고정 문장으로 대체하고 로컬 계산은 유지한다. 생성본/수정본/적용본을 구분한다. GPT 끄기는 새 요청만 끄고 기존 설명을 보존한다. 새 결과에 이전 설명을 자동 적용하지 않는다.

## 9. Excel·저장

### 9.1 구성·출처

시트는 SUMMARY/TASK_INPUTS/PHOTO_REBA/CRITERIA. 정확한 열·DTO는 API 계약서 §7, 배치·서식은 화면설계서 S08이다. 작업마다 사진15행·기준11행, 입력/근거/버전·초안/조사자 결론·현재/과거·완전성·검토 상태를 표시한다. 누락값은 빈칸/사유이며0/비해당으로 채우지 않는다.

미완성·과거 결과도 내보낼 수 있다. 보고서는 선택한 분석 snapshot을 고정하며 서로 다른 계산세대를 임의로 섞지 않는다. 사진 원본이 없으면 대표 이미지를 생략하고 이유를 표시한다. 고정 안내: ‘작업 분석 보조 보고서. 법정 유해요인조사표·증상조사표의 완성을 뜻하지 않습니다.’

SUMMARY는 제목/조사정보→작업결과→부족 항목 집계와 다음 입력→상세 설명/해석 안내 순서로 읽는다. 작업결과 표는14열로 고정한다: task_id/task_name/analysis_id/currentness/review_status/valid_pose_count/complete_reba_count/available_max/full_max/applicable_criteria/needs_input_count/needs_review_count/incomplete_reba_count/next_inputs. 조사정보는 표 위, 진단/적용 설명과 출처는 표 아래 작업ID·분석ID가 붙은 상세영역, 고정 안내는 아래 안내영역에 표시한다. 진단/설명/식별정보는 모두 보존한다.

출력 시각은 ExportSnapshot.exported_at, 보고서/저장 DTO 버전은 report_version/schema_version=1.3이다. 작업에는 선택 analysis_id를 표시하고 snapshot.input_revision과 모델/전처리/점수표/고시 버전은 TASK_INPUTS에 표시한다. 모델 버전은 해당 분석 snapshot을 쓴다. ExportSpec.include_representative를 ExportSnapshot에 복사하고 report.render(snapshot,destination)이 읽는다. 이 옵션은 이미지만 생략하며 대표 식별자/구성점수와 상태는 유지한다.

### 9.2 부족항목 집계·다음 입력

| 파생값 | 작업별 집계 단위·규칙 | 표시 이름 |
|---|---|---|
| needs_input_count | Judgment.computed_status=NEEDS_INPUT인 기준 수. 기준당 한 번,0..11 | 계산 입력이 부족한 기준 수 |
| needs_review_count | Judgment.computed_status=NEEDS_REVIEW인 기준 수. 기준당 한 번,0..11 | 추가 검토가 필요한 기준 수 |
| incomplete_reba_count | 15−RebaSummary.complete_count. 슬롯당 한 번,0..15 | REBA 미완료 사진 수 |

판정 결과가 없으면 앞의 두 수는 null, REBA 결과가 없으면 마지막 수는 null이다. 미분석/미계산을11건·15건·0건으로 추정하지 않는다. 조사 합계는 해당 모듈 결과가 모든 작업에 있을 때만 작업별 수를 합산하고, 하나라도 없으면 그 합계는 null과 ‘미분석/미계산 작업 있음’으로 표시한다. 작업이0개면 합계0이다. 이미 계산된 작업의 수는 작업행에 남긴다. 조사자 결론/전체 검토와 무관하게 computed_status로 센다. 여러 누락 필드/근거 때문에 기준 수를 늘리지 않는다. 사진 누락과 조건 누락을 한 건수로 합치지 않는다.

next_inputs는 report가 같은 ExportSnapshot의 누락/검토 사유를 읽어 만드는 안내다. 미분석은 분석 안내, 미계산 모듈은 pose/REBA/고시 각각 재계산 안내를 넣는다. 포즈는 VALID가 아닌 슬롯의 진단과 회차·순간을 표시한다. REBA는 슬롯별 missing_fields와 좌우 누락을 중복 제거해 회차·순간·좌우·범주를 붙이고, 고시는 기준별 missing_fields/review_reasons를 항목 이름으로 표시한다. 미분석/미계산 안내→슬롯1..15→기준1..11 순서로 모두 표시하며 SUMMARY의 긴 셀은 줄바꿈한다. 예: ‘2회차 선반 접촉 직전: 포즈 관절 가림 확인 후 사진 재분석’, ‘2회차 선반 접촉 직전: 오른쪽 손목 범주 입력’, ‘9호: 무릎 아래/어깨 위/팔 뻗음 조건별 하루 횟수 입력’, ‘4호: 조건 합산 해석 검토’. GPT로 안내를 만들지 않는다. 안내는 결론/조치 완료/저장 허가를 뜻하지 않는다.

상태는 report.build_overview(snapshot)에서 집계/안내와 함께 산출한다. 작업 reviewed는 선택 분석이 있고 SURVEY.review.reviewed=true이며 그 analysis_id가 reviewed_analysis_ids에 있을 때true다. review_current는 여기에 검토 metadata_revision 일치와 선택 분석 CURRENT까지 만족할 때true다. review_status는 분석없음NO_ANALYSIS, 검토목록에 없는 분석UNREVIEWED, 현재검토REVIEWED_CURRENT, 검토한 과거 분석/조사정보REVIEWED_HISTORY다. A2를 검토한 뒤 목록에 없는A1을 출력하면 미검토다. 조사목록의 최신 결과 검토 표시를 선택 결과에 그대로 사용하지 않는다.

작업 has_incomplete는 분석없음, pose 미계산/유효15미달, REBA 미계산/INCOMPLETE, 고시 미계산/초안NEEDS_INPUT·NEEDS_REVIEW 중 하나라도 있을 때true다. report가 원래 결과를 직접 읽어 산출하며 별도 미완전 사유 분류/배열을 만들지 않는다. 설명은 분석/모듈 결과 없음의 고정 문구, 포즈 상태·유효수·diagnostics[].message, REBA missing_fields/좌우 review_reasons, 고시 computed_status/missing_fields/review_reasons에서 next_inputs[].message로 만든다. UI와 Excel은 그 문구를 같이 사용한다. has_incomplete는 안내 항목 수로 계산하지 않고 저장·분석·검토·출력 허가 조건으로 사용하지 않는다. 수동REBA가 완전해도 포즈유효가 부족하면 그 상태는 따로 남는다. has_stale는 선택 분석 STALE일 때true이며 분석없는NONE을 과거로 세지 않는다. reviewed/review_current는 완전성과 독립이다.

조사 전체 reviewed/review_current는 작업이1개 이상이고 모든 작업의 해당 값이true일 때true다. has_incomplete/has_stale는 하나라도true면true며, 작업0개는 네 값 모두false다. UI·Excel·ExportReceipt는 같은 ReportOverview.state를 사용한다. SUMMARY의 고정 요약영역에 선택 결과 전체의 검토 여부/검토 현재성/미완전 포함/과거 포함을 표시하고 기존 결과 상태/진단/누락에서 만든 안내는 아래 작업ID·분석ID가 붙은 상세영역에 표시한다. 이 네 부울은 출력 당시 EXPORT_LOG.receipt_json에 기록하고 새 상태 테이블/컬럼을 만들지 않는다. 부분 결과도 검토/출력할 수 있다.

### 9.3 상세 결과 표현

PHOTO_REBA의15행과 별도로 대표사진 옆의 고정 상세블록에 작업ID·분석ID·슬롯번호·회차·사건·photo_id, 하중상태/적용kg, 좌우/선택점수, 선택한 쪽의 몸통·목·다리·위팔·아래팔·손목·표A/B/C·하중/손잡이/활동 가산점과 누락을 표시한다. 선택한 쪽이 없으면 총점 null과 이유를 보이며 임의의 한쪽을 대표로 채우지 않는다. 이 블록은 필터/정렬 가능한15행표 밖에 두어 사진과 다른 슬롯 점수가 섞이지 않게 한다. available_max/full_max와 대표사진 total은 각각 표시하고 의미를 합치지 않는다.

CRITERIA는11행을 유지하고 comparison_values에 Judgment.basis의 전항목을 순서대로 줄바꿈한다. 항목코드·값·단위·비교연산·기준값·출처를 각각 구별한다. 자동 초안·조사자 결론·effective_status, 계산근거와 조사자 근거를 분리한다. 사진 기술태그의 각도 출처를 고시의 법기준 출처로 바꾸지 않는다. 태그는 TASK_INPUTS에 분자/분모/수동관찰수/비율을 출력하며 시간으로 환산하지 않는다.

### 9.4 저장

SQLite6테이블과 JSON snapshot으로 저장한다. 복잡한 revision/FK/trigger/보안/보존차단/백업정책은 데모에 넣지 않는다. 작업/조사 삭제는 서비스가 관련 행을 순서대로 지우며 원본 사진/외부 Excel은 지우지 않는다.

보고서 집계/다음 입력/대표 상세는 이미 저장한 결과의 파생 표현이다. 별도 집계·경고 이력·완료상태 테이블을 추가하지 않는다. ExportSnapshot에 출력시점 원자료와 보고서 버전을 보관하고 출력 파생값은 report가 구성한다. Excel은 저장 수치를 표시하며 REBA/고시 재계산이나 수식 판정에 의존하지 않는다.

## 10. 문서 대조 항목
