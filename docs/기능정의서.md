# 기능정의서

> 문서 ID ERGO-FUN-001 · 설계 버전 2.0 · 개정일 2026-10-16 · 완성 목표 2026-10-23(Asia/Seoul)
>
> 구현할 동작을 정의한다. 현재 main e7b0cf1의 구현 완료를 뜻하지 않는다. 타입과 호출명은 [API 계약서](API_계약서.md)를 따른다.

## 1. 전체 흐름과 책임

조사 생성/유형 선택 → 작업장 상황·작업조건·근로자 참여·증상조사 기록 → 일반 작업과 근거 입력 → 11개 기준 초안 → 선택적 사진·자세 확인·REBA → GPT 설명 → 조사자 검토 → 저장·재열기 → 유형에 맞는 한글 Excel·전후 비교 순서다. 사진 없는 직접입력 작업도 정상 흐름이다.

상자 들기를 포함한 모든 작업은 GENERAL_TASK다. 입력 템플릿은 질문 순서를 바꿀 뿐 지원 기준·사진 수·판정식을 바꾸지 않는다. 신규 사진은 GENERAL_STILLS_V1의 가변 행으로 관리한다. 사건명·회차·사진 순서로 하중이나 자세를 확정하지 않는다.

| 기능 | 사실의 출처 | 산출물 |
|---|---|---|
| 작업 입력 | 조사자 관찰·면담·문서 | 하루 노출량, 중량·힘·횟수와 근거 |
| 조사 입력 | 설비·작업량·속도·업무형태 관찰, 근로자 참여, 증상조사 | 유형별 조사 맥락·참여기록·증상 응답/요약 |
| MoveNet | 분석대상 사진 | 관절·신뢰도·각도와 후보 |
| 규칙 엔진 | 확인한 직접입력·관찰값 | 11개 기준 초안, 별도 REBA |
| GPT | 저장된 계산의 허용 수치 요약 | 설명·추가 확인·개선안 |
| 검토/출력 | 선택한 분석과 조사자 기록 | 계산 근거·결론·검토 상태·Excel |

## 2. 입력과 사실의 의미

null은 모름/미입력이며 실제 0과 다르다. Truth는 YES/NO/UNKNOWN이다. 새 작업의 11개 기준은 UNKNOWN, 15종 직접시간은 null, 조건 행은 비어 있고 rows_complete는 UNKNOWN이다. 사진은 0건이며 기본 분석 범위는 judgment=true, pose/tags/reba=false다.

조사 공통값은 최초/정기/수시 유형과 사유 유형, 설비·작업량·작업속도·업무형태 변화, 근로자 참여여부/역할/방법/의견, 증상조사 방법·응답자 수·요약과 익명 응답이다. 조사 누락은 저장을 차단하지 않고 보고서의 SURVEY 보완 항목으로 표시한다. 수시조사 사유가 기존 질환자 발생/업무상 질병 인정일 때만 별지 1·2 기반 출력 시트를 추가한다. 신규 작업·설비 또는 작업환경 변경 수시조사는 LOCO 보조 기록으로 출력한다.

작업 공통값은 작업명, 작업자 코드, 작업 방법·자세, 선택적 작업 높이, 하루 작업시간, 근로자 면담 기반 작업강도/빈도 자기평가(각 1~5), 관찰 유해요인·발생 원인, 개선 제안, 일회성 여부, 예정 개월 수, 연간 작업일 수, 근거다. 강도/빈도 입력은 법정 11개 기준 계산에 사용하지 않는다. 기준의 물체 중량과 사진에서 관찰한 하중은 별도 입력이다. 공동 작업 인원수로 중량을 나누지 않는다.

근거는 출처(DIRECT_OBSERVATION/INTERVIEW/DOCUMENT/OTHER), 설명, 관찰 시각을 갖는다. 근거를 적지 않았다는 이유로 부분 저장·초안 출력을 막지 않되, 출력에서 미기록을 표시한다. 시간·중량·힘은 유한한 0 이상 수, 횟수는 0 이상 정수다. 음수·비유한 수·잘못된 enum·중복 행 ID는 관련 계산에 INPUT_CONFLICT를 만든다. condition_present=NO인데 같은 호의 적격 작업을 양수로 기록한 경우도 관련 모순으로 확인한다.

하루 시간과 노출시간은 0~1440분이며 하루 작업시간을 아는 경우 그보다 큰 노출/합집합 시간은 모순이다. 겹칠 수 있는 서로 다른 노출시간을 단순 합산해 하루 작업시간과 비교하지 않는다. 횟수·빈도·시간 중 하나에서 다른 값을 자동 만들어 직접값처럼 저장하지 않는다.

### 2.1 1~5호 직접시간 15종

| 호 | ExposureCode | 단위·의미 |
|---|---|---|
| 1 | C1_KEYBOARD_FOCUSED | 집중적인 자료입력 등의 키보드/마우스 조작 min/day |
| 2 | C2_NECK, C2_SHOULDER, C2_ELBOW, C2_WRIST, C2_HAND | 같은 동작을 반복하는 각 신체부위의 min/day |
| 3 | C3_UNION | 해당 손·팔 자세를 취한 중복 제거 min/day |
| 4 | C4_NECK_FLEX, C4_TRUNK_FLEX, C4_NECK_TWIST, C4_TRUNK_TWIST, C4_UNION | 각 자세 시간과 중복 제거 합집합 min/day |
| 5 | C5_SQUAT, C5_KNEEL, C5_UNION | 쪼그림/무릎 굽힘의 각 시간과 중복 제거 합집합 min/day |

총 15종이다. 4호의 법문은 목/허리 굽힘·비틀림이며 기존 C4_TRUNK_EXT는 새 법령 직접시간에서 제외한다. 허리 젖힘은 REBA/기술태그에서 관찰한다. 본문 밖 해설을 추가할 때는 별도 규칙 버전과 근거 검토가 필요하다. 2호의 서로 다른 부위 시간을 더하지 않는다. 4·5호의 합집합은 직접 관찰한 값이며 겹치는 시간을 더하지 않는다. C3_UNION도 사진 표본 비율에서 산출하지 않는다.

### 2.2 6~11호 조건별 행

| 호 | 한 행에 함께 기록하는 조건 | 하루 집계 |
|---|---|---|
| 6 | 비지지 여부, 한 손 손가락으로 집어 옮기는 중량 kg 또는 같은 손가락으로 쥐는 힘 kg-equivalent, 해당 시간 | 적격 행의 중복 제거 min/day |
| 7 | 비지지 여부, 한 손 중량 kg 또는 힘 kg-equivalent, 해당 시간 | 적격 행의 중복 제거 min/day |
| 8 | 그 조건의 물체 중량 kg와 드는 횟수/day | 적격 중량의 중복 제거 count/day |
| 9 | 중량 kg, 무릎 아래/어깨 위/팔을 뻗은 상태의 각 횟수와 합집합 횟수 | 적격 중량의 위치별/합집합 count/day |
| 10 | 중량 kg, 해당 구간의 드는 빈도 count/min와 시간 | 중량·빈도를 함께 충족한 구간의 중복 제거 min/day |
| 11 | 실제 충격 여부, 충격 빈도 count/hour와 시간 | 실제 충격·빈도를 함께 충족한 구간의 중복 제거 min/day |

row_id는 기준 안에서 안정적인 ID다. row_ids로 집계 대상 행을 지정하고 union.value 또는 9호 totals에 중복 제거 직접값·근거를 기록한다. rows_complete=YES는 해당 기준의 하루 조건들을 모두 기록했다는 관찰이며, 누락 수치를 0으로 바꾸는 옵션이 아니다.

예: 2kg 물체 99회와 30kg 물체 1회는 8호의 적격 횟수 1회다. 30kg × 전체 100회로 평가하지 않는다. 10호에서도 가벼운 물체를 빠르게 드는 시간과 무거운 물체를 천천히 드는 시간을 결합하지 않는다.

## 3. 11개 기준 규칙 엔진

버전 MOEL_2020_12_GENERAL_V2. 고정 근거는 [고용노동부고시 제2020-12호 제3조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000185793)다. 아래는 구현용 요약이며 최신 개정·현장 해석 검토의 완료 선언이 아니다. 조건의 “이상”은 같음을 포함한다.

| 호 | 확인할 질적 조건 | 수치 조건 |
|---|---|---|
| 1 | 집중적인 자료입력 등을 위한 키보드/마우스 조작 | 하루 240분 이상 |
| 2 | 목·어깨·팔꿈치·손목·손 중 같은 부위의 같은 동작 반복 | 해당 부위 하나의 하루 시간이 120분 이상 |
| 3 | 손이 머리 위/팔꿈치가 어깨 위/팔꿈치를 몸통에서 듦/팔꿈치를 몸통 뒤에 둠 등의 해당 자세 | 중복 제거 하루 120분 이상 |
| 4 | 지지되지 않거나 자세 변경이 제한된 상태의 목/허리 굽힘·비틀림 | 하루 120분 이상 |
| 5 | 쪼그리거나 무릎을 굽힌 자세 | 하루 120분 이상 |
| 6 | 지지되지 않은 상태에서 한 손의 손가락으로 집어 옮기기/쥐기 | 집기 중량 ≥1kg OR 힘 ≥2kg-equivalent, 하루 ≥120분 |
| 7 | 지지되지 않은 상태에서 한 손 들기/쥐기 | 한 손 중량 ≥4.5kg OR 힘 ≥4.5kg-equivalent, 하루 ≥120분 |
| 8 | 중량물 들기 | 중량 ≥25kg, 하루 ≥10회 |
| 9 | 무릎 아래/어깨 위/팔을 뻗은 상태의 들기 | 중량 ≥10kg, 하루 ≥25회 |
| 10 | 반복 들기 | 중량 ≥4.5kg AND 빈도 ≥2회/분, 하루 ≥120분 |
| 11 | 손 또는 무릎으로 물체에 반복적인 실제 충격 | 빈도 ≥10회/시간, 하루 ≥120분 |

condition_present는 해당 호의 질적 작업 조건 확인값이다. 4호는 추가로 unsupported OR posture_restricted를 확인한다. 6~11호의 중량·힘·비지지·빈도·충격은 같은 행 안에서 결합한다. 작업명이나 MoveNet 기술태그가 이 입력을 대체하지 않는다.

### 3.1 제외 조건과 3값 논리

- 단기간 작업: one_off=YES이고 예정 개월 수 ≤2이면 YES. one_off=NO이거나 개월 수 >2이면 NO. 나머지는 UNKNOWN이다.
- 간헐적 작업: 연간 작업일 수 ≤60이면 YES, >60이면 NO, 미입력이면 UNKNOWN이다.
- 단기간 또는 간헐적 작업이 YES이면 NOT_APPLICABLE이며 SHORT_TERM/INTERMITTENT/BOTH 근거를 남긴다.
- 일회성 여부·개월 수·작업일 수의 음수/잘못된 값은 UNKNOWN과 진단이다. 잘못된 -1일을 ≤60으로 비교하지 않는다.

AND는 하나라도 확정 거짓이면 거짓, 모두 참이면 참, 나머지는 UNKNOWN이다. OR는 하나라도 확정 참이면 참, 모두 거짓이면 거짓, 나머지는 UNKNOWN이다. 예를 들어 6호의 집기 중량 ≥1kg가 참이면 힘 미입력은 그 OR의 결정을 막지 않는다.

### 3.2 조건 행과 합집합 평가

1. 각 행의 수치를 검증하고 질적·중량·빈도 조건의 적격 여부를 TRUE/FALSE/UNKNOWN으로 평가한다. 실제 횟수/시간이 0인 행은 결과를 증가시키지 않는다.
2. 입력된 union/totals의 row_ids가 존재하는지, 중복되지 않는지 확인한다. 확정 부적격 행을 적격 집계에 넣으면 INPUT_CONFLICT, 적격 여부가 모르는 행을 넣으면 관련 missing_fields를 만든다.
3. 알려진 적격 행 하나의 직접 시간/횟수가 문턱 이상이면 그 호의 수치 조건은 참이다. 다른 행의 무관한 누락을 이유로 이 사실을 무효로 하지 않는다. 단, 관련 모순은 먼저 해결한다.
4. 완전한 단일 적격 행은 그 행의 값이 합집합이다. 여러 행은 자동 합산하지 않는다. 여러 행의 적격 집합에 대한 직접 union이 있고 문턱 이상이면 수치 조건이 참이다. 이때 나머지 미확인 행이 있어도 확인된 해당 사실은 유지한다.
5. 문턱 미만으로 확정하려면 rows_complete=YES, 결과를 바꿀 수 있는 모든 행의 적격 여부·시간/횟수, 적격 행을 망라하는 중복 제거 집계가 필요하다. 확정 적격 행이 없고 모든 행이 확정 부적격이면 합집합은 0으로 평가할 수 있다. 빈 행만 있고 망라성이 UNKNOWN이면 비해당으로 만들지 않는다.
6. 합집합은 알려진 개별값의 최댓값 이상이어야 한다. 포함한 모든 개별값이 알려진 경우에만 합계 이하도 검사한다. 일부 값이 모를 때 알려진 일부 합계를 전체 상한으로 쓰지 않는다. 9호의 위치별 합집합에도 같은 원칙을 적용한다.
7. union의 일부만 선택해 문턱 미만이 된 경우, 선택하지 않은 잠재 적격 행이 있으면 NEEDS_INPUT이다. 집계 근거·누락 필드·비교값을 결과에 함께 보존한다.

9호는 동일 중량 행의 위치별 횟수와 중복 제거 union_count_day를 관리하고, 적격 중량 행 전체에 대해 totals를 관리한다. 하나의 들기 사건이 두 위치 조건에 걸려도 두 번 세지 않는다. 단일 완전 행은 그 행의 위치별·합집합 값을 사용할 수 있다.

### 3.3 해석이 필요한 결합과 상태 우선순위

4·5·9호에서 각각의 자세/위치 값은 모두 문턱 미만인데 합집합만 문턱을 넘으면 COMBINATION_RULE로 NEEDS_REVIEW다. 한 종류가 이미 문턱을 넘으면 이 쟁점은 결정을 막지 않는다. 4호의 비지지/자세 제한 및 9호의 적격 중량 조건은 여전히 필요하다.

법령에 없는 정량 각도를 법적 확정 기준으로 쓰지 않는다. 자세 의미가 미확인된 경우 posture_interpretation_pending=true와 POSTURE_INTERPRETATION을 남긴다. 관련 수치가 확정 미달이면 무관한 자세 해석 때문에 비해당을 막지 않는다.

상태 판정 순서는 다음과 같다.

1. 확인된 제외 조건 → NOT_APPLICABLE.
2. 결정을 바꿀 수 있는 입력 모순 → NEEDS_REVIEW/INPUT_CONFLICT.
3. 질적·수치 조건의 확정 거짓 → NOT_APPLICABLE. 이때 무관한 미입력을 요구하지 않는다.
4. 참 여부에 필요한 값 또는 제외 조건이 UNKNOWN → NEEDS_INPUT.
5. 참 여부에 필요한 결합·자세 해석 미해결 → NEEDS_REVIEW.
6. 필요한 조건 모두 참, 제외 조건 모두 NO → APPLICABLE.

모든 호에 computed_status, 비교값 basis, missing_fields, review_reasons, 규칙 출처를 남긴다. 관련 없음으로 단락 평가한 필드는 필요 누락 목록에서 제외하되 원래 입력은 보존한다. 조사자 결론은 별도 필드이며 계산 초안을 덮어쓰지 않는다.

## 4. 사진·MoveNet·기술태그

### 4.1 가변 사진과 관찰

사진 등록과 평가대상 배정은 별개다. slot_no는 안정적 ID이며 다른 행 삭제 시 번호를 다시 매기지 않는다. 등록 사진 중 analysis_target=true인 행만 pose/tags/reba의 대상 N에 포함한다. 사진을 선택하기만 해서는 분석하지 않는다. 동일 photo_id를 여러 분석 행에 중복 배정하면 진단하고 중복 표본을 완성 결과로 세지 않는다.

각 행에 photo_id, 표시명, 카메라 좌우, 화면상의 전방, 측면 확인, 단일 작업자·전신·통상 작업 여부를 기록한다. 상자 들기에도 같은 항목을 쓴다. 관찰 하중은 UNLOADED이면 0, MEASURED이면 기록한 kg, UNKNOWN이면 null이다. 측정값 미입력이나 무하중과 양수 kg의 충돌은 확인 대상이다.

동일 사진의 경로 재연결은 photo_id·관찰·수동값을 보존한다. 다른 사진으로 교체할 때 새 photo_id를 사용하며 해당 행의 관찰·수동값을 비운다. 사진 동의만 바꿨을 때 입력 revision을 올리지 않는다. 실제 파일 내용의 동일성은 사용자가 확인하며, 경로만으로 내용 동일성을 보증하지 않는다.

### 4.2 추론과 각도

MoveNet Lightning TFLite, 입력 192×192 uint8, 출력 17개 (y,x,confidence)를 사용한다. 모델 파일·버전과 전처리 EXIF_OPENCV_LETTERBOX_V2를 snapshot에 기록한다. 신뢰도 0.5는 제품상 후보 채택 문턱이며 정확도 보증 수치가 아니다.

Pillow로 EXIF 방향 보정·RGB 변환 후 원본을 검정 정방형으로 패딩한다. 홀수 여분 픽셀은 아래/오른쪽에 두며 OpenCV INTER_LINEAR로 192×192 변환한다. 역변환 좌표는 EXIF 보정 원본 픽셀 기준이다. 패딩 밖·사진 밖·저신뢰도·벡터 길이 0은 관련 각도를 null로 만든다.

전방 부호를 f(화면 오른쪽 +1, 왼쪽 -1)로 두고 벡터를 (f·dx,-dy)로 바꾼다. up(v)=atan2(vx,vy), down(v)=atan2(vx,-vy), norm은 [-180,180] 정규화다.

| AngleCode | 정의 |
|---|---|
| TRUNK_TILT_VERT | 엉덩이→어깨의 up |
| NECK_TILT_VERT_PROXY | 어깨→귀의 up, 실제 경추 각도 대용 지표 |
| NECK_FLEX_TRUNK_PROXY | norm(목 대용 지표−몸통) |
| UPPER_ARM_RAISE_VERT | 어깨→팔꿈치의 down |
| UPPER_ARM_FLEX_TRUNK | norm(위팔 수직 기준+몸통 기울기) |
| ELBOW_FLEX | 180°−어깨/팔꿈치/손목의 내각 |
| KNEE_FLEX | 180°−엉덩이/무릎/발목의 내각 |

측면·전방·단일 인물·전신 조건이 확인되지 않으면 좌표와 진단을 볼 수 있어도 확정 REBA 자동 후보를 내지 않는다. 반대편 관절의 가림은 null일 수 있으며 억지로 좌우를 복제하지 않는다. neck proxy는 목 REBA 자동값으로 사용하지 않고 손목도 자동 채점하지 않는다.

몸통, 무릎, 좌우 위팔·아래팔의 6개 후보만 제공한다. 경계 ±5°는 BOUNDARY_REVIEW로 표시한다. 공통 몸통 후보는 camera_side에서 확인한 몸통 각도를 사용한다. 무릎 후보는 양쪽 굽힘의 큰 값을 사용하며 한쪽이 없으면 null이다. 후보는 조사자가 적용한 때에만 AUTO_ACCEPTED 수동값이 되고 null 후보는 기존값을 덮어쓰지 않는다.

### 4.3 사진 기술태그

POSTURE_TECH_V1의 neck/trunk/upper-arm 임계값은 AnalysisSettings에 숫자로 명시하고 버전을 고정한다. 초기 제품 기본값은 목 전방 대용 20°, 몸통 굽힘 20°, 몸통 젖힘 20°, 위팔 거상 45°이며 모두 기술 분류용이다. 새 기본값을 과거 snapshot에 소급하지 않는다.

목·몸통·위팔 기술태그는 유효 각도에만 적용한다. 머리 위 손, 어깨 위/몸통 뒤 팔꿈치, 비틀림, 쪼그림, 무릎 굽힘은 직접 확인한 태그로 관리한다. yes_count/observed_count와 sample_ratio=yes_count/observed_count를 표시하며 observed_count=0이면 null이다. valid_pose_count·manual_observed_count·대상 N도 함께 보여 준다. 이 비율을 하루 노출시간이나 법적 해당 확률로 표시하지 않는다. 공통 목/몸통 기술태그는 camera_side의 유효 각도, 좌우 위팔·직접 관찰 태그의 사진 집계는 어느 한쪽 YES이면 YES, 필요한 양쪽 모두 NO이면 NO, 그 밖은 UNKNOWN이다.

## 5. REBA

규칙 버전 REBA_TABLE_2000_V2. 채택한 점수표는 기존 문서의 REBA 표를 유지한 것이며 이번 문서 편집에서 원문 모든 셀을 독립 검증했다는 뜻이 아니다. 구현 수용 전 표 셀과 경계의 독립 대조가 필요하다. 근거: [INSST NTP 601](https://www.insst.es/documentacion/colecciones-tecnicas/ntp-notas-tecnicas-de-prevencion/17-serie-ntp-numeros-576-a-610-ano-2001/ntp-601-evaluacion-de-las-condiciones-de-trabajo-carga-postural.-metodo-reba-rapid-entire-body-assessment-2001), [INSST 자세 지침](https://www.insst.es/documents/94886/96076/Posturas%20de%20trabajo.pdf/3ff0eb49-d59e-4210-92f8-31ef1b017e66#page=31).

### 5.1 확인값과 계산

공통 13필드는 몸통 기본/비틀림/옆굽힘, 목 기본/비틀림/옆굽힘, 다리 지지/앉음/무릎 범주, 충격, 활동 3종이다. 좌우 각각 8필드는 위팔 기본/벌림·회전/어깨 상승/지지, 아래팔 기본, 손목 기본/편위·비틀림, 쥐기다. 사진 태그용 추가 관찰은 별도이며 13+8+8의 필수 점수 입력과 구분한다.

COMMON 범주의 trunk_base는 1~4, neck_base는 1~2, legs_support와 knee_band는 API enum을 쓴다. LEFT/RIGHT 범주의 upper_arm_base는 1~4, lower_arm_base/wrist_base는 1~2, coupling은 API enum이다. 나머지 보정·활동은 Truth다. 추가 태그의 squat/kneel은 COMMON, hand_above_head/elbow_above_shoulder/elbow_behind_trunk는 LEFT/RIGHT의 Truth다. 다른 scope·범위·자료형은 진단하며 점수를 만들지 않는다.

| 항목 | 계산 |
|---|---|
| 몸통 기본 | 수직 1, 0을 제외한 ±20° 이내 2, 젖힘 >20° 또는 굽힘 >20~60° 3, 굽힘 >60° 4 |
| 몸통 보정 | 비틀림 OR 옆굽힘이면 +1; 둘 다 있어도 한 번 |
| 목 기본 | 중립/0~20° 굽힘 1, >20° 굽힘 또는 젖힘 2; 직접 확인 |
| 목 보정 | 비틀림 OR 옆굽힘이면 +1 |
| 다리 | 양측 안정 1, 편측/불안정 2; 무릎 <30° +0, 30~60° +1, >60° +2; 앉음이면 무릎 보정 0 |

앉음 YES이면 무릎 범주는 점수 결정에 필요하지 않으므로 그 미입력만으로 총점을 막지 않는다. OR 보정도 한쪽 YES가 확인되면 다른 쪽 UNKNOWN이 가산 결정을 막지 않는다. 나머지 점수에 필요한 값은 확인해야 한다. 사진이 없으면 수동값이 있어도 총점을 계산하지 않는다.

양쪽 점수가 모두 완성되어야 사진 total을 계산한다. 높은 쪽을 selected_side로 선택하고 동점은 LEFT다. 한쪽만 완성되면 그 점수는 참고로 보여 주되 사진 total은 null이다. 높은 REBA와 11개 법적 기준은 별도 결과다.

### 5.3 집계와 대표 사진

대상 N>0이고 모든 사진의 양쪽 REBA가 완성된 경우에만 full_max를 제공한다. available_max는 완성된 사진만의 최댓값이며 반드시 complete_count/N과 함께 표시한다. N=0은 full_max/available_max가 null이며 요청한 REBA는 INCOMPLETE다. available_max를 하루 작업의 최악 자세로 표현하지 않는다.

대표 사진 자동 선택은 완성 사진의 최대 점수, 동점이면 작은 slot_no다. 사용자가 다른 완성 사진을 고르면 MANUAL 선택으로 남기고 available_max/full_max는 바꾸지 않는다. 미완성 사진을 대표 점수로 선택하지 않는다.

## 6. 분석 상태·revision·검토

분석을 시작할 때 불변 TaskSnapshot을 저장하고 latest_analysis_id를 설정한다. 재계산은 새 분석 행을 만든다. RUNNING인 이전 결과를 새 분석의 완료 결과로 복사하지 않는다. 늦게 완료된 이전 분석이 최신 포인터를 되돌리지 않는다.

| 조건 | 상태 |
|---|---|
| 범위 미요청 | NOT_REQUESTED |
| 범위 요청, 아직 결과 없음 | NOT_CALCULATED |
| 처리 중 | RUNNING |
| 요청 결과가 필요한 값까지 완성 | COMPLETE |
| 입력·해석·사진 결과 누락 | INCOMPLETE |
| 처리 실패/취소 | FAILED/CANCELED |

scope는 독립적이다. pose 없이 reba를 요청하면 확인한 수동값으로 평가하고 tags는 직접 관찰 태그만 사용한다. 다른 모듈을 자동 요청하지 않는다.

pose 대상 0건을 요청하면 FAILED, tags/reba 대상 0건을 요청하면 INCOMPLETE와 NO_ANALYSIS_TARGET이다. 빈 배열의 all() 결과로 완성 처리하지 않는다. judgment는 11개 초안에 입력/검토 필요가 없으면 COMPLETE다. pose의 VALID는 촬영조건이 확인되고 필요한 점들이 유효해 각도를 하나 이상 산출한 사진이다. 전체 대상이 VALID이면 pose COMPLETE/DONE, 일부 자세 확인이 불가능하면 INCOMPLETE/PARTIAL_REVIEW, 모든 대상의 파일/모델 처리 실패 또는 대상 0건이면 FAILED다. 취소는 CANCELED다. tags는 대상 N>0의 11개 기술태그가 모두 YES/NO일 때 COMPLETE, UNKNOWN이 남으면 INCOMPLETE다. reba는 대상 N>0의 모든 양쪽 점수가 완성되어야 COMPLETE다. JobStatus FINISHED는 요청 처리가 끝났다는 뜻이며 모든 모듈 완성이나 조사자 검토를 뜻하지 않는다.

CURRENT는 현재 input_revision과 분석 revision이 같고 latest_analysis_id도 같을 때다. 입력 수정은 revision을 한 번 올리고 검토를 무효화한다. 이름·설명도 snapshot에 남기므로 작업 입력 변경에 포함한다. 설정의 분석 값이 달라지면 관련 작업의 revision을 올린다. GPT/UI 설정만의 변경은 계산 revision에 영향을 주지 않는다.

| 변경 | 확인값 처리·재사용 |
|---|---|
| 동의만 변경 | 관찰/수동값·계산 revision 유지 |
| 같은 파일 경로 재연결 | 관찰/수동값 유지; 배정 사진 경로 변경은 revision 한 번 증가 |
| 다른 photo_id로 교체/배정 해제 | 해당 행의 관찰/수동값 제거 |
| 해당 사진의 카메라/전방/측면 조건 변경 | 해당 사진의 관련 수동값·관찰 재확인 |
| 작업자·작업 방법·작업 높이 변경 | 그 맥락에 의존한 사진 관찰/수동값 재확인 |
| 모델/전처리 변경 | AUTO_ACCEPTED 값 제거, 직접 확인값 보존 |
| 법령 입력 변경 | snapshot 갱신 후 새 계산; 관련 없는 사진 사실 보존 |
| 수동값·기준만 재계산 | 동일 입력·모델·촬영조건의 종료된 pose만 재사용 가능 |
| UI/GPT 설정 변경 | 분석 입력·관찰 유지 |

불변 결과와 별도로 조사자 결론·AI 적용본·대표 사진 등 표시/검토 데이터를 부분 저장한다. 계산 완료는 ai를 쓰지 않으며 AI 저장은 계산 키를 쓰지 않는다. 결론 저장과 조사 검토 해제는 한 트랜잭션으로 처리한다.

조사자 결론에는 호별 해당/비해당, 사유·근거·검토자·시각을 기록한다. 계산과 다른 결론은 경고와 양쪽 결과를 표시한다. 유효한 조사자 결론이 있으면 effective_status의 출처는 INVESTIGATOR이며 계산 초안은 그대로 남는다. 재분석 시 과거 결론을 자동 적용하지 않는다.

조사 검토는 선택한 분석 ID 집합, metadata_revision, 검토자·시각에 묶인다. 결과가 CURRENT이고 동일한 분석 ID·조사 메타 revision을 확인해야 review_current다. 과거 기록은 삭제하지 않고 현재 검토 여부와 구분한다.

## 7. GPT 설명과 개선안

GPT는 Python 서비스가 저장된 결과로 만든 NumericSummary만 받는다. 기준 11개의 계산/조사자/유효 상태, 출처 구분, 비교 수치·문턱, 누락·검토 사유, 모듈 요청/상태, 사진 유효 수, REBA 요약, 기술태그 수치, 공개 규칙 문구를 포함한다. 이름·작업자 코드·파일 경로·사진·좌표·자유입력 근거·내부 ID는 전송하지 않는다.

실제 Responses API와 Structured Outputs 대응 모델을 설정한다. 응답은 summary, criteria 설명, check_items, improvement_options의 고정 스키마이며 모든 필드를 required, additionalProperties=false로 지정한다. 점수나 판정을 쓰는 응답 필드는 없다. basis_refs는 제공한 기준별 item_code를 참조한다. criteria에는 1~11호가 각각 한 번 있어야 하며 Responses API의 text.format에 type=json_schema, strict=true를 지정한다. 알 수 없는 참조·누락/중복 호 번호·스키마 위반은 API_ERROR 진단과 로컬 대체 설명으로 처리한다. item_code는 서비스가 만든 비식별 코드이며 사용자 행 label/ID를 그대로 전송하지 않는다. rule_version은 고시/REBA/기술프로필 버전을 함께 나타내는 고정 문자열이다.

모델 문장은 사실에 틀릴 수 있으므로 생성→조사자 수정→적용을 구분한다. [OpenAI 공식 지침](https://developers.openai.com/api/docs/guides/structured-outputs)의 구조적 출력도 의미 정확성을 보증하지 않는다. 문장 속에 입력과 반대되는 판정이 있어도 계산·조사자 결론을 변경할 수 없다.

요청 전체 상한은 15초이며 자동 재시도를 끈다. 네트워크 작업은 서비스의 다른 요청을 막지 않는다. 키 없음·시간 초과·통신 오류·거절·불완전 응답은 FALLBACK과 원인, 기능 비활성은 DISABLED다. API 키는 환경 OPENAI_API_KEY로만 받는다. 모델 ID는 설정값이며 실제 계정의 성공 호출을 확인한다.

생성 요청마다 text_id가 다른 AiText를 추가하고 생성본·편집본·적용본, 모델·프롬프트 버전·시각·입력 요약을 보존한다. 생성은 기존 편집/적용 레코드를 덮어쓰지 않는다. 편집·적용은 text_id를 지정하고 edited_at/applied_at을 기록하며 적용 때 같은 목적의 활성 레코드 is_active만 원자적으로 전환한다. 과거 applied_text는 보존한다. 같은 목적의 현재 NumericSummary와 값이 달라지면 “이전 결과에 대한 설명”으로 표시한다. 실패나 비활성화가 기존 적용본을 지우지 않는다. AI 실패는 계산 불완전과 별도로 설명 상태에 표시한다.

개선안은 검토할 제안이다. 예를 들어 작업대 높이·동선·취급 방식 변경은 현장 적용 가능성을 확인하고 별도 작업/분석으로 다시 측정한다. GPT가 제안한 개선의 효과를 측정 결과 없이 확정하지 않는다.

## 8. 출력과 개선 전후 비교

보고서 버전 2.0의 한글 시트는 공식 유해요인조사 서식 구성을 따르는 `유해요인조사표`·`부담작업 해당 여부`·`체크리스트`·`증상조사표`(익명 응답이 있을 때)와 보조 시트 `자세 분석(REBA)`·`입력한 값`·`확인사항`, 조건부 `쉬운 설명`·`개선 전후 비교`다. 서식 구성은 고용노동부고시 제2020-12호 별지 제1·2호서식과 KOSHA GUIDE E-G-1-2025를 따른다. 앱에 입력란이 없는 칸(작업강도·작업빈도 점수가 비어 있는 경우, 근로자명, 증상조사표의 빈도·조치 문항 등)은 비워 조사자가 직접 쓴다. 시트별 내용 계약은 API 계약서 §8을 따른다. 출력할 분석 ID·조사 메타·검토·비교 분석을 ExportSnapshot에 먼저 고정하고 계산을 다시 하지 않는다. CURRENT/STALE/NONE, 요청 범위·상태, 확인할 첫 입력, 기준별 근거를 출력한다. 시트는 입력이 빠진 칸을 자동 확정하지 않고 "입력 필요"로 표시하며 공식 서식 파일을 대신하지 않는다. 원본 서식과 대조·서명·조사자 검토가 필요하다.

Excel은 일반인이 읽는 말로 쓴다. 판정 상태·출처·단위·값의 코드(예: APPLICABLE, MIN_DAY, INTERVIEW)와 저장 경로는 셀에 쓸 때 한글로 바꾸거나 쓰지 않으며 저장된 값은 그대로다(ergo/report/display.py, labels.py). 원시 입력·15종 시간·조건 행·사진 관찰·수동값·관절/각도·기술태그·좌우 REBA·규칙/모델 버전·AI의 생성/편집/적용본은 출력 snapshot(EXPORT_LOG)에 보존하며, 사용자 요청으로 Excel에는 이를 저장 이름 그대로 담은 전문가용 시트를 두지 않는다. 긴 텍스트는 순서가 있는 여러 행으로 나누고 자르지 않는다. 사용자 문자열은 Excel 수식으로 실행하지 않고 문자열로 기록한다. 대표 이미지는 `유해요인조사표`의 3단계 사진 칸에만 넣고 이미지 원본이 없으면 그 사실을 적고 수치 출력을 유지한다. 비교 요약은 정렬 가능한 데이터 표 밖에 둔다.

needs_input_count/needs_review_count는 계산 초안 computed_status 기준의 호 개수(작업당 0~11)다. judgment 미계산이면 null이며 조사 집계에 null이 있으면 합계도 null이다. 조사자 결론으로 계산의 누락/검토 경고를 숨기지 않는다. REBA 미완성 수는 요청 후 계산 결과가 있는 경우 N−complete_count, 미요청/미계산은 null이다. 요청 대상 0건은 수가 0이어도 INCOMPLETE와 진단을 유지한다. 여러 작업 집계에서 모두 미요청이면 null, 요청 작업 중 미계산이 있으면 null, 나머지는 요청·계산한 작업의 수를 합한다.

has_incomplete는 요청한 모듈의 미계산·진행·미완성·실패·취소 또는 분석 없음으로 정한다. 미요청 모듈은 제외한다. GPT 실패/이전 설명은 별도 확인사항이다. has_stale/has_incomplete는 어느 하나라도 있으면 true, reviewed/review_current는 작업이 1개 이상이고 모두 만족해야 true다. 작업 0개이면 네 플래그 모두 false다.

비교는 같은 조사의 서로 다른 before_analysis_id/after_analysis_id 두 개를 선택한다. 선택된 두 snapshot을 별도 보존하며 한 작업의 최신 분석만 출력하더라도 과거 비교 대상이 빠지지 않는다. 삭제된 ID는 조용히 대체하지 않고 오류를 반환한다.

호별 상태는 계산/조사자/유효 상태와 입력 근거를 나란히 보여 준다. 호의 숫자를 위험 점수로 합산하거나 개선율로 만들지 않는다. REBA는 규칙 버전 동일, 촬영 프로토콜·대상 수 동일, 양쪽 모두 전체 평가 완성일 때만 full_max의 after−before 차이를 제공한다. 조건이 다르면 null과 비교 제한 사유를 적는다. 이 조건만으로 표본 대표성·인과 효과가 증명되는 것은 아니며 작업 내용·촬영 조건과 비교 메모를 함께 확인한다.

## 9. 기존 자료와 검증

신규 작업·저장·출력은 2.0이다. 1.3 분석/ExportSnapshot은 변경하지 않고 이전 프로토콜 표시와 함께 읽는다. 기존 상자 15슬롯은 과거 읽기에만 적용한다. 새 입력 DTO로 열 때 사진·알려진 수동값은 보존하되 사건명은 사진 표시명으로 옮기고, 사건에서 계산했던 하중을 실제 관찰 중량으로 변환하지 않는다. 망라성·측면 확인·실제 측정 하중은 UNKNOWN/null에서 재확인한다. 편집 DTO의 legacy_input에 이전 TASK.input_json 원문 전체를 보존한다. 사진 비율 등 환산값은 새 직접수치에 null을 넣어 재확인한다. 사용자가 명시적으로 저장할 때 TASK만 2.0으로 바꾸고 revision을 한 번 올린다.

검증은 요구사항 §7을 따른다. 특히 혼합 중량, 합집합 누락, 임계값과 같음, 모르는 값의 0 처리, 0개 대상, 한쪽 REBA만 완성, 사진 재연결, GPT 생성 중 편집, 선택한 과거 분석의 출력과 비교를 독립 확인한다. 문서 정합성 확인은 앱 실행·법 해석·점수표 원문 대조를 대신하지 않는다.

## 로컬 보완 추적

일반 입력 템플릿은 입력값을 보존한 채 기준 질문의 표시 순서와 도움말만 바꾼다. 누락 안내는 현재 작업의 기준/조건 행/필드로 이동한다. 자동 후보는 선택한 필드만 해당 사진 자체의 후보로 적용한다. GPT 근거 링크는 생성 당시 NumericSummary를 보여 주고 현재 입력으로 이동할 수 있다. 전후 화면은 11개 호의 계산/조사자/유효 상태와 입력 조건 차이를 병렬 표시한다.

검토 이력 history는 이전 분석 ID·메타 revision·검토자·시각·메모와 변경 사유를 보존하며 현재 검토 여부와 분리한다. 로컬 실행·회귀·변이 검증의 실제 결과는 local-verification.md에서 관리한다.

전후 비교의 condition_changes는 작업 조건·분석 범위·법령 입력뿐 아니라 사진 배정/관찰, 수동 확인값, 분석 설정의 차이를 포함한다. 같은 프로토콜·양의 대상 수·양쪽 전체 완성·호환 REBA 규칙일 때만 후−전 점수 차이를 표시한다. 수동값/관찰/설정 변경을 생략해 동일 조건의 효과로 오인하게 하지 않는다.

## 적응형 입력 보완 (2026-10-22)

새 간편 흐름은 [적응형 추가 확인 계약](adaptive-intake.md)을 따른다. 검증된 사용자 진술과 사용할 수 있는 MoveNet 값은 같은 TaskInput에 자동 반영한다. 낮은 신뢰도 추정은 별도 후보이며, USER 수정·모름은 우선 보존한다. 실제 규칙/REBA 누락과 현재 사실을 AI에 전달해 다음 질문을 선택하고, 서버가 해결된 필드·잘못된 단위·조건 혼합을 제외한다. 전체 질문 목록이나 카드 전체를 다시 요구하지 않는다. 물건 무게별 조건 행, 전체 작업시간과 특정 노출시간, 사진별 하중은 서로 분리한다.

자동 정리 후 대화 팝업을 열어 질문 하나와 자연어 답변/빠른 응답을 제공한다. 항목별 빈 입력칸을 기본 동선으로 사용하지 않는다. AI가 추출값을 저장한 뒤 갱신된 누락에서 다음 질문을 고르며, 기존 진술을 재활용한다. 실제 응답 상태는 session.last_ai에 기록해 팝업에 표시하고, 오류 시 문장을 보존해 재시도한다.

AI 입력 정리·후속 질문·설명 생성은 공통 설정 계약(`ergo/ai_config.py`, API 계약서 §6)을 공유한다. 모델·추론 강도·요청 시간·토큰 한도는 변수이며, 두 설정 화면도 서버 필드 정의로 렌더링한다. APP_SETTINGS의 기존 JSON에 저장하며 테이블·이전 분석 snapshot은 추가/변경하지 않는다.

## 원본 서식 PDF 출력 (2026-10-22 개정안)

기본 출력은 PDF이며 기존 Excel API는 호환 기능으로 유지한다. 선택 Task마다 원본 1~3쪽을 만들고 작성방법은 한 번 붙인다. 실제 하위 단위작업 입력이 없는 Task는 전체 작업 한 행으로 표시한다. A/B는 면담 입력만 사용하고 누락은 공란이다. 근로자 식별값을 이름으로 쓰지 않는다.

원본 칸을 넘는 긴 작성 내용만 별첨에 보존한다. 원본에 대응하지 않는 입력·계산 초안·REBA 상세·빈 사진 슬롯·내부 식별번호·보완사항은 PDF 별첨에 나열하지 않고 앱에서 확인한다. 원본 부담작업 호는 조사자 해당 결론만 쓰며, 공란은 비해당 확정이 아니다. 미리보기는 파일/로그를 만들지 않고 실제 저장만 기존 EXPORT_LOG에 새 행을 남긴다. 상세 계약은 API_계약서.md의 PDF 출력 절을 따른다.
