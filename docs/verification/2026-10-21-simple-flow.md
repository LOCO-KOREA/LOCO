# 2026-10-21 간편 흐름(사진 우선) 구현·검증 기록

기준: `feat/photo-first-simple-flow`, 부모 `d5fe9d9`. 개발 PC(Windows, CPython 3.12, Electron 개발 실행)에서 실제 앱으로 수행했다.
**전체 수용 NOT ACCEPTED 판정은 바뀌지 않는다.** 아래는 이 브랜치가 추가한 흐름에 대한 기록이다.

## 바뀐 것

- 첫 화면이 **홈 → 사진(왼쪽/정면·후면/오른쪽) → 1차 REBA → 로코 질문 → 결과 → 검토·출력**의 한 흐름이다.
  조사 정보, 11개 기준 전체, 검토 표시, 조사자 결론, AI 설명, Excel, 개선 전후 비교, 재열기, 삭제가 이 흐름 안에서 끝난다.
  기존 10개 화면은 오른쪽 위 "고급 편집"으로만 연다.
- 서비스 `quick_preview`(저장하지 않음): 사진별 MoveNet 관절, 방향·정면 추정, 측면 근측 범주, 정면·후면 기울임 제안,
  부담 없음 가정 1차 점수, 규칙 기반 질문. 1차 점수는 저장하지 않고 최종 값은 기존 계산 엔진이 만든다.
- 규칙: 질문은 값을 미리 채우지 않는다. 모르는 값은 모름으로 남고, GPT는 판정·점수를 바꾸지 않는다.
- GPT 검증기·프롬프트·시간 제한 수정(별도 커밋). 새 DB 테이블·trigger는 없다.

## 후속 추가 (같은 날)

- **Excel 한글화:** 판정 상태·출처·단위·모듈·종류·값의 코드를 셀에 쓸 때만 한글로 표시한다(`ergo/report/display.py`). 저장 값은 그대로다.
  입력값 변경 줄은 `한글 이름 (저장 경로): 이전 → 이후`다. 독립 대조 도구(`tests/verify_local_artifacts.py`)를 같은 표로 맞췄고, 실제 앱 E2E가 만든 5개 통합 문서를 통과했다.
  남은 영문은 항목 코드 열의 기계 경로, 감사용 괄호 속 저장 경로, 근거 JSON, 고유명사(REBA)뿐이다.
- **GPT 어투:** 프롬프트 V5가 "판정되었다" 대신 "계산 초안으로는 해당"처럼 초안 표현을 쓰게 한다. 실제 OpenAI 6회 모두 형식 검증을 통과했고, 단정 표현이 남은 문장은 모두 "초안상"·"계산 초안으로는"을 달고 있었다.
- **UX:** 검토 단계 맨 위의 "Excel 만들기 전 확인"(입력 필요·검토 필요 수, 빠진 항목, 질문으로 돌아가기), 작성 중 분석 자동 보관과 "이어서 하기"·"버리기",
  모든 단계의 "홈으로", 질문 화면 Ctrl+Enter, 고급 편집 S03·S04의 Ctrl+S.
- **시험 창 숨김:** `LOCO_HIDDEN=1`이면 창을 화면 밖으로 보낸다. 완전히 숨기면(`show:false`) 화면 캡처가 멈추는 것을 확인해 이 방식을 택했다.
- 일반 기능 검증은 45개로 늘었다(이어서 하기 5개, 점검표 5개 추가).

## main(PR #20) 병합 후 재검증

`electron-ui`의 DB 위치 표시(PR #20)가 main에 먼저 병합되어 충돌 3곳(`package.json`·`desktop.js`·`README`)을 양쪽 내용을 모두 살려 해결했다.
간편 흐름에서도 DB 위치 줄(경로·복사·폴더 열기)이 보이도록 `#environment` 숨김을 뺐다. 병합본에서 Python 121개, 프론트 회귀 24개(DB 위치 시험 포함),
DB 위치 실서비스 통합 5개, 기존 화면 E2E 29단계와 Excel 독립 대조, 전체 흐름 E2E(실제 OpenAI), 일반 기능 검증 45개, 변이 시험이 모두 통과했다.
이 PR의 네이티브 창 배치·클립보드·폴더 열기는 여전히 mock 검증이며 실제 클릭은 검증하지 않았다.

## 오후 추가: 사진 인식 보정·AI 한 줄 입력·일반인용 Excel·공식 서식 구성

시연 사진 18장을 실제 화면에 넣어 보며 나온 문제와 Excel 가독성을 고쳤다. 변경 이유와 설계는 저장소 루트의 `Handoff(2026.10.21).md`에 있다.

- **사진 인식**: 비스듬한 "정면" 사진을 정면·비스듬·옆 3단계로 받아들이고 사용자가 고른 칸을 존중한다. 앉은 자세를 감지해 쪼그림 제안과 1차 점수 부풀림을 막고, 보는 방향으로 가까운 쪽 몸을 측정한다. "팔이 머리 위" 신호는 위팔 90° 이상일 때만 쓴다. 가상 좌표 반례 28개(`tests/test_quick_assess.py`).
- **AI 한 줄 입력**: 서비스 `quick_interpret`(저장하지 않음). 모델은 칸 목록에서 값을 옮기기만 하고 모든 값은 문장 속 근거 구절을 달아야 한다. 근거가 없거나 범위를 벗어난 값, 해당 작업 종류가 꺼진 예/아니오 답은 버린다(`ergo/engine/quick_intake.py`, 프롬프트 `LOCO_INTAKE_V2`). 첫 호출이 33초 걸리던 것은 openai import를 시작 때 미리 해 두어 줄였다.
- **화면**: 결과 / 검토·설명 / Excel 화면을 나누고, Excel 화면이 저장 전에 시트를 탭으로 미리 보여 준다(`preview_excel_sheets`). 미리보기와 파일은 같은 시트 정의에서 만든다.
- **일반인용 Excel**: 코드·내부 용어·저장 경로를 쓰지 않는다(법정 번호는 "이름(법정 N호)"로만). 사용자 요청으로 "전문가용 상세기록" 시트를 두지 않는다.
- **공식 서식 구성**: 고용노동부고시 제2020-12호 별지 제1·2호서식과 KOSHA GUIDE E-G-1-2025의 구성으로 `유해요인조사표`·`부담작업 해당 여부`·`체크리스트`·`증상조사표`(익명 응답이 있을 때)를 앞에 둔다(`ergo/report/form.py`). 앱에 입력란이 없는 칸(작업강도·작업빈도 점수, 근로자명 등)은 비워 직접 쓰게 한다. 공식 서식 파일을 대신하지 않는다.

## 수행하지 못한 것·제약

- **실제 정면·후면 사진**: 공개 예제에 정면 사진이 없어 정면 판별(어깨폭·엉덩이폭 비율 0.65/0.45)과 기울임 제안(몸통 10°, 목 15°, 팔 벌림 30°)은 가상 좌표로만 시험했다. 기준값은 실제 사진으로 보정해야 한다.
- 왼쪽 사진은 공개 예제를 좌우 반전해 만들었다(`.local/fixtures`, Git 제외).
- 현장 사진의 방향 추정 정확도, 별도 Windows PC 설치, 현장 조사자 사용 시간은 미수행이다. 포터블은 2026-10-21 깨끗한 커밋에서 다시 빌드해 개발 PC에서 패키지 검증을 마쳤다.
- 재열기 후 "개선 후 다시 비교"는 저장된 값에서 답변을 복원하므로, 처음에 "모름"으로 답한 기준은 다시 묻는다.
- 6~11호는 기준마다 가장 부담이 큰 조건 하나만 받는다. 여러 조건 행은 고급 편집에서 입력한다.
- 개발용 가상환경(`.venv`)으로 실행한 앱을 종료하면 Python 서비스 프로세스가 남을 수 있다(포터블 실행 파일은 해당 없음).
- Excel의 상태·단위·값은 한글로 쓰고 저장 코드와 경로는 쓰지 않는다. 저장된 원래 값은 출력 snapshot(EXPORT_LOG)에 그대로 있다.
- 공식 HWP 서식 원본과 칸 단위로 대조하지 못했고, 실제 프린터 출력은 보지 않았다. 간편 흐름은 작업강도(A)·작업빈도(B)를 묻지 않아 2단계 표의 그 칸이 비어 있다.
