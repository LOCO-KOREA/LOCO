# 2026-10-21 간편 흐름(사진 우선) 구현·검증 기록

기준: `feat/photo-first-simple-flow`, 부모 `d5fe9d9`. 개발 PC(Windows, CPython 3.12, Electron 개발 실행)에서 실제 앱으로 수행했다.
**전체 수용 NOT ACCEPTED 판정은 바뀌지 않는다.** 아래는 이 브랜치가 추가한 흐름에 대한 기록이다.

## 바뀐 것

- 첫 화면이 **홈 → 사진(왼쪽/정면·후면/오른쪽) → 1차 REBA → 로코 질문 → 결과 → 검토·출력**의 한 흐름이다.
  조사 정보, 11개 기준 전체, 검토 표시, 조사자 결론, AI 설명, Excel, 개선 전후 비교, 재열기, 삭제가 이 흐름 안에서 끝난다.
  기존 10개 화면은 오른쪽 위 "고급 편집"으로만 연다.
- 서비스 `quick_preview`(저장하지 않음): 사진별 MoveNet 관절, 방향·정면 추정, 측면 근측 범주, 정면·후면 기울임 제안,
  부담 없음 가정 1차 점수, 규칙 기반 질문. 1차 점수는 저장하지 않고 최종 값은 기존 계산 엔진이 만든다.
- 규칙: 질문은 값을 미리 채우지 않는다. 모르는 값은 모름으로 남고, GPT는 판정·점수를 바꾸지 않는다.
- GPT 검증기·프롬프트·시간 제한 수정(별도 커밋). 새 DB 테이블·trigger는 없다.

## 수행하지 못한 것·제약

- **실제 정면·후면 사진**: 공개 예제에 정면 사진이 없어 정면 판별(어깨폭·엉덩이폭 비율 0.65/0.45)과 기울임 제안(몸통 10°, 목 15°, 팔 벌림 30°)은 가상 좌표로만 시험했다. 기준값은 실제 사진으로 보정해야 한다.
- 왼쪽 사진은 공개 예제를 좌우 반전해 만들었다(`.local/fixtures`, Git 제외).
- 현장 사진의 방향 추정 정확도, 별도 Windows PC 설치, 포터블 재빌드, 현장 조사자 사용 시간은 미수행이다.
- 재열기 후 "개선 후 다시 비교"는 저장된 값에서 답변을 복원하므로, 처음에 "모름"으로 답한 기준은 다시 묻는다.
- 6~11호는 기준마다 가장 부담이 큰 조건 하나만 받는다. 여러 조건 행은 고급 편집에서 입력한다.
- 개발용 가상환경(`.venv`)으로 실행한 앱을 종료하면 Python 서비스 프로세스가 남을 수 있다(포터블 실행 파일은 해당 없음).
- Excel 판정 근거 시트에 `APPLICABLE` 같은 영문 상태 코드가 그대로 보인다(기존 동작).
