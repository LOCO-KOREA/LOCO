# 원문 전체의 독립 기대값 원장

앱 계산 코드를 수정하지 않고 `tests/field_case_scenarios.json`의 12개 원문과 최초/동결 `696f457` 실호출 기록을 읽었다. 기존 `case.expected` 63개만 재사용하지 않고, 수동 선언한 원장 115개로 비교 범위를 늘렸다. 추가한 것은 일회성 NO, 사진의 한 사람·전신·평소 모습 YES, 명시된 작업 특징, 사진 물건의 연결 YES/UNKNOWN·중량, 양손 손잡이, 지지 없음·충격 확인·모든 조건 확인 등이다. 사진에서 시간/중량을 만들거나 미언급 특징을 NO로 채우지 않는다.

`tests/live_statement_ledger.py`는 원문 전체 보존·115개 명시값·모름 USER 소유권·typed 사진 관찰값·첫 물리 DB JSON과 API 사실 일치를 비교한다. `tests/live_output_relations.py`는 중량·횟수를 독립 정렬하지 않고 condition으로 연결하며, 실제 저장된 export snapshot과 Excel 조건 행도 연결한다. 원래 5kg 99회/30kg 1회를 교차해도 값 집합은 같다는 반례를 검출한다. 문자열/숫자 표기와 boolean/null의 차이도 구분한다.

읽기 시점의 `.local/statement-ledger-audit-20261023/coverage.json` 결과:

| 기록 | 점검 사례 | 점검한 명시값 | 검사 | 실패 검사 |
| --- | --- | --- | --- | --- |
| 최초 10개 + 자세 2개 | 12/12 | 115/115 | 158 | 7 |
| `696f457` final-a/b | 11/12 | 95/115 | 135 | 2 |

실패 검사를 서로 다른 누락값으로 세면 최초 기록은 5개다. 06 오른쪽 손잡이 GOOD, 07 사진 연결 모름, 08 무하중, 11 손목/손 각각 180분이다. 07의 값과 UNKNOWN/USER 검사가 함께 실패하고 08은 사실과 관찰값이 함께 실패하므로 검사 개수와 누락값 개수를 구분한다. `696f457`의 현재 11개 기록은 07 모름의 값/소유권만 실패했다. 10은 첫 AI 체크포인트가 아직 없어 보류한 것으로 성공에 포함하지 않았다.

후속 원문도 모든 저장 단계와 대조했다. 최초 01에서 “이 20kg 조건이 모든 들기 조건입니다”라고 했지만 complete.lift=YES가 후속 직후부터 마지막 재시작까지 빠졌다. 최초 06의 오른쪽 손잡이는 첫 AI~재시작까지 빠지고 이후 수정 원문 처리에서 복구되었다. `696f457` final-a의 01/06은 이 추가 기대값도 통과했다. 원래 실패가 사라진 것으로 재작성하지 않는다.

최초 01/06 실패는 각각 `tests/fixtures/intake-recorded-completeness-omission-20261023.json`, `tests/fixtures/intake-recorded-bilateral-omission-20261023.json`에 보관했다. `tests/test_live_statement_ledger.py`는 이 원시 기록을 원장에 넣으면 누락을 실패로 판단하는지 확인한다. 이 시험의 녹색은 앱에서 누락이 고쳐졌다는 증거가 아니다. 추가로 API만 정상이고 물리 DB 모름 소유권이 다를 때, 원문이 잘렸을 때, null이 0으로 바뀔 때에도 오라클이 실패한다.

중량·횟수·사진 관계의 전체 단계 비교 산출물은 같은 폴더의 `relations/`에 있다. 01/06의 사진 중량, 07의 두 조건 짝과 실제 Excel/export snapshot에 새로운 불일치는 없었다. 07 모름 미저장은 기존 실패로 여러 단계에서 반복 검출했다. 0개 검사를 한 다른 작업을 이 관계 검증의 성공 사례로 세지 않는다.

`python -m tests.audit_statement_campaigns --cases <시나리오 JSON> --campaign original=<최초10폴더> --campaign original=<자세2폴더> --campaign frozen696f457=<final-a> --campaign frozen696f457=<final-b> --output <별도결과경로>`로 재실행한다. 원본 파일·DB에 쓰지 않고 지정한 결과 파일만 생성하며 미완성 체크포인트는 pending으로 남긴다. 체크포인트 SHA-256도 기록한다.

누락 재발을 줄이려면 유효한 다른 질문을 이미 골랐어도 새 자연어의 명시 사실을 질문 전에 다시 교차 확인해야 한다. 양손을 자동으로 서로 복사하거나 여러 사진의 소유권을 합치는 방식은 허용하지 않는다. 이 원장 커밋은 런타임 동작을 바꾸지 않는다.
