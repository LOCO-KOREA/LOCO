## 발견하고 수정한 반례

1. 무효화한 fact의 photo_proof만 같아 새 측정값 복구를 건너뛰어 재질문했다. 값·상태·reask까지 대조해 복구한다.
2. 목·경계·낮은 신뢰도 후보가 있어도 직접 선택을 요구했다. 추정 상태로 초안에 사용하고 수정 화면으로 모은다.
3. AI 관찰의 자세 범주가 응답 계약에서 빠져 있었으며, 서로 같은 뜻인 근거 문장의 문자열 차이로도 버렸다. 허용 범주·관찰·근거·확신도를 검사하고 두 근거를 보존한다.
4. 고급 입력의 기준별 다른 중량/해당 여부/망라성을 공유 카드가 덮었다. saved_criteria와 충돌 상태로 원본을 보존한다.
5. 사진별 하중·맥락·방향·분석 대상·고유 행 번호·라벨을 공통값이나 새 순번으로 덮어 수동값을 제거할 수 있었다. 동일 사진의 고유값과 수동값을 보존한다.
6. 동일 slot_no의 다른 사진 결과가 손상된 저장 분석에서 설명·Excel·검토 화면에 연결될 수 있었다. 사진 ID도 함께 확인한다. 실제 정상 저장 분석에서는 이 불일치가 관찰되지 않았다.
7. 전역 holding 관찰만으로 보이지 않는 반대 손의 쥐기 후보가 허용됐다. 해당 쪽 손목 가시성도 검증한다.
8. 사진 API 병렬 응답의 목록 순서만 재정렬해도 revision이 증가해 적용된 설명이 STALE로 표시됐다. 집합·내용이 같을 때 완료 순서를 보존하고 실제 관찰 변경은 계속 반영한다.

## 검증과 한계

- Python 전체 668개 시험과 기존 환경 의존 8개 건너뜀을 구분한다. 프론트 전체 37개와 추가 제목 시험을 포함한 38개 스크립트가 통과했다. 사진 순서 수정은 관련 23개 시험과 실제 DB 복사본의 CURRENT/source_current 유지로도 검증했다.
- 공유 값·외부 편집 병합·사진 슬롯 재구성을 과거 구현으로 되돌린 메모리 mutation 세 건이 각각 관련 회귀시험을 실패시킨다.
- 실제 사진 한 장을 새 V2 API로 호출해 목·팔·쥐기 범주 응답을 확인했다. 같은 이미지 SHA를 확인한 독립 서비스 재생에서 추정 저장·초안 계산·AI 요약·물리 Excel 전달과 USER/MediaPipe 우선권을 검증했다. 이 재생의 자세 추론은 통제된 fixture이며 실제 MediaPipe 실행과 구별한다.
- 실제 사용자 DB는 읽기 전용으로 확인하고 복사본에서 수정/출력 시험했다. 과거 분석 snapshot은 보존한다. 검증 산출물은 로컬 `.local/`에 있으며 사용자 DB·사진·키를 커밋하지 않는다.
- 실제 DB 복사본에서 MediaPipe를 실행하고 같은 사진의 저장 V2 응답을 적용한 후 새 분석과 새 V14 수치 설명 API 호출도 검증했다. 사용자 답변·20kg·과거 분석은 보존됐고 현재 10점·AI GENERATED/CURRENT 및 확정 설명의 물리 Excel 포함을 확인했다. 사진 응답 재생과 새 수치 설명 호출을 구분한다.
- MediaPipe가 현재 계산하는 3D 분절각은 팔꿈치·무릎이다. 다른 부위의 3D 각도까지 계산했다고 주장하지 않는다. 단안 모델의 신뢰도는 관절 검출/관찰의 지표이며 임상 측정 정확도나 법적 적합성의 검증이 아니다.
- 전체 작업시간과 특정 자세/들기의 노출시간은 구별한다. 별도로 말하지 않은 노출시간을 전체 작업시간으로 자동 채우지 않는다.
