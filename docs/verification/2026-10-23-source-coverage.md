# 질문 전에 원문 명시 정보 교차확인

최초 06에서 양손 손잡이가 좋다고 명시했는데 RIGHT coupling을 UNKNOWN으로 잘못 제안하고, 실제 기존 FOLLOWUP도 들기 시간 질문만 하여 복구하지 못했다. 최초 01 후속의 “모든 들기 조건”도 다른 유효 질문이 있다는 이유로 추가 점검 없이 빠졌다. 단순히 질문 후보만 고르는 것과 원문 전체를 다시 점검하는 것을 구분한다.

`contract.POLICY.source_coverage_passes=1`, `source_coverage.PURPOSE/PHASE/KNOWN_KEYS`를 공통 변수로 둔다. 새 자연어의 EXTRACT_AND_PLAN 뒤에는 유효한 다른 질문·남은 후보 유무와 관계없이 FOLLOWUP을 정확히 한 번 수행한다. 첫 요청 오류도 원문을 먼저 저장하고 한 번 교차확인할 수 있다. 기존 공통 모델·추론·요청 설정을 사용하고 새 시간/토큰/만료 값을 추가하지 않는다. 조회·직접 선택 답변만의 저장·plan=false는 추가 호출하지 않는다. 빈 수동 재시도의 기존 질문 계획은 유지한다.

두 번째 요청의 `purpose=SOURCE_COVERAGE`는 원문·모든 허용 targets·현재 known·원래 previous_proposals·previous_decisions를 함께 대조한다. 앞선 모델 제안은 사실 근거가 아니며 원문에 있는 사실만 추가한다. 명시한 양손은 양쪽을 각각 확인하되 한쪽의 값을 반대쪽으로 복사하지 않는다. 명시한 모든 조건의 complete도 missing 목록에 없다는 이유로 버리지 않는다. 원래 요청 객체는 수정하지 않고 새 payload를 만든다.

`source_photo_scope`는 원문 당시 사진 ID/방향/engine/quality/서명이며 `current_photo_scope`와 구분한다. 사진 픽셀을 AI에 보내는 기능이 아니다. canonical known에서 호환 alias와 비활성 사진 값을 제외한다. 지연 재조정은 각 요청에 기록된 원래 사진 서명을 사용하므로 중간에 바뀐 사진에 예전 자세 값을 붙이지 않는다. 비사진 새 사실·원문·제안·결정은 남기고 직접 값과 기존 snapshot을 지킨다. 첫 응답 중 revision이 바뀌어도 같은 회차를 복원해 한 번의 교차확인을 이어가며, 삭제/재생성된 다른 작업에는 붙이지 않는다.

`tests/test_intake_source_coverage.py`의 8개 핵심 시험은 06/01 기록에 기반한 제어 응답 재생, 유효 질문이 있어도 추가 사실 저장, 원래 제안 불변/재시작, 직접 답변·조회 no API, 첫 호출 실패, 첫 응답 지연 USER 우선권, 사진 교체 scope 보존·비사진 값 저장, alias/비활성 사진 제외, 반대 손 자동 복사 금지를 검사한다. 기존 지연 응답 시험은 EXTRACT와 새 교차확인의 결정을 각각 검사하여 원래 결정이 사라지지 않게 했다.

제어된 두 번째 응답의 정답을 주입한 회귀는 실제 Luna가 항상 누락을 복구한다는 증거가 아니다. 새 지침의 실제 응답은 통합 후보에서 01/06 원문을 새로 호출하고 115개 독립 원장과 실제 DB/Excel로 대조해야 한다. 최초 실패 fixture는 그대로 유지한다.
