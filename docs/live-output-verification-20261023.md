# 입력·AI·DB·Excel 실호출 대조 기록

기준은 `feat/mediapipe-heavy`의 f1296c876d592aa34bda8f06bd73421edea72026이다. 최초 10회가 끝날 때까지 앱 코드를 변경하지 않았다. 이후 수정 단계마다 소스 manifest를 고정하고 별도 DB/프로필로 재검증했다. 이 문서의 완료는 로컬 격리 스택의 지정 경로에 한한다.

총 25회, 실제 외부 `gpt-6-luna/xhigh` 요청/응답 116쌍, 실제 출력 75개다. 마지막 통과 사례 10종의 대조 24,018개에서 불일치 0개이며 값/출력 조합 537개에 출처·원문·응답 ID·DB 경로·실제 셀을 연결했다. **마지막 통과 근거는 여러 수정 단계의 회차 조합이며, 최종 단일 빌드에서 10회를 다시 실행했다는 뜻은 아니다.**

각 회차는 입력 전 원장 기록→초기 AI→추가 답변→초기 분석/출력→직접 수정→재시작→AI 재호출→최종 분석→실제 AI 설명 생성/직접 편집/적용→UI Excel 저장→과거 분석 재출력→재시작으로 진행했다. 화면 밖·초점 불가 Electron, 실제 Python/MediaPipe Heavy/SQLite/외부 AI를 사용했다. 파일 선택·저장 dialog만 시험 경로로 대체했다. OS 마우스·키보드 조작은 하지 않았다.

## 확인하고 고친 9건

1. 하루 시간·연간 일수 등의 Excel 출처와 근거 누락.
2. 같은 조건 행의 중량 근거를 횟수·시간에도 복제하는 오표시.
3. FOLLOWUP이 발견한 유효한 새 제안을 무시하여 계산/질문에 반영하지 않는 문제.
4. ‘겹치지 않아요’를 긍정 중복으로 오독하여 90+270=360분을 거절하는 문제.
5. 작업 NO일 때 입력한 노출 0을 Excel에서 숨기는 문제.
6. 저장한 모든 조건 기록 여부를 Excel에서 누락하는 문제.
7. 조회 시 파생 별칭을 fact로 생성하여 revision을 바꾸고, 다음 자연어를 실제 AI 호출 전에 거절하는 문제.
8. 소수점에서 최초 작업명을 잘라 12.5kg 작업이 ‘12’로 저장되는 문제.
9. 물건 없음의 파생 손잡이 근거 시각을 매 조회마다 바꾸어 DB와 선택 분석이 달라지는 문제.

후속 제안에도 동일 근거/USER 소유권 검증을 적용하고 미해결 CONFLICT를 보존한다. 오래된 자연어는 저장 후 최신 상태로 재조정하며, 직접 수정의 낙관적 경합을 미저장 성공으로 응답하지 않는다. 지연된 응답의 사진이 같으면 새 정보를 반영하고, 사진이 바뀌었다면 원문·제안·진단을 보관하여 다른 사진에 붙이지 않는다. 경과 시간에 따른 폐기를 추가하지 않았다.

## 스키마와 증거 경계

AI의 평면 제안 DTO와 DB의 중첩 TaskInput은 같은 외형이 아니다. 공통 catalogue의 target→destination을 기준으로 실제 DB→분석→출력 snapshot의 입력 필드를 비교하고, Excel에서는 표시 변환된 값·단위·조건·출처·근거의 실제 셀을 비교했다. JSON 숫자 120.0/120은 같은 숫자이며 bool/null/string과는 구분한다. 여섯 물리 테이블의 schema는 모든 캡처에서 동일하다. 새 테이블·migration·과거 snapshot 재작성은 없다.

최초 03의 driver 화면 동기화 복구, 최초 08의 과도한 load 기대값, JSON 숫자 표기 차이의 시험 보정은 별도 기록했다. 원문 08에서는 미는 힘을 배제하지 않았으므로 load를 임의 확정하지 않는다. 마지막 집중 시험은 ‘미는/당기는 힘도 없다’를 명시한 별도 입력이다. 실제 AI가 UNLOADED를 저장하고 반복 조회 revision과 수동 근거가 유지됨을 확인했다. 최초 30개 불변 출력 snapshot의 새 파일 재렌더링은 별도 0불일치이며, 실제 재호출이나 누락 정보 복구로 세지 않았다.

전체 증거는 `.local/live-output-evidence-20261023/REPORT.md`, `summary.json`, `schema-map.json`, `field-ledger-latest-passing.csv/.json`, 일관된 DB backup과 ZIP에 있다. 각 원본 폴더에는 입력 전 원장·SDK 원응답·단계별 실제 SQL 행·원본 Excel·실패 원본·소스 manifest가 있다. 실행 절차는 [실호출 대조 실행](live-output-e2e.md), 동작 계약은 [저장 계약](storage-persistence.md)을 따른다.

회귀 검증은 Python 전체 시험, 프론트 15개 시험 묶음/build, 서비스 48개·renderer 41개 계약 검사로 수행했다. 새 반례는 `test_live_output_findings.py` 18개, 독립 오라클 반례는 `test_live_output_audit.py` 4개다. origin/main의 최신 Excel/크롭/질문 UI 통합, 패키지 배포본, 현장 정확도는 검증하지 않았다. PR·push·main 병합·배포는 하지 않았다.
