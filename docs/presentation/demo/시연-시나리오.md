# LOCO 시연 시나리오

실제 앱으로 "사진 한 장 + 한 문장 → 첫 점수 → 한 페이지 입력 → 최종 점수·11개 기준 초안 → Excel"을 보여 주는 시연의 순서, 대본, 막혔을 때의 대처를 모았다. 아래 숫자와 화면은 2026-10-27에 이 PC에서 실제 앱·실제 AI로 두 번 리허설한 결과다(§7).

- **길이**: 보통 7분(AI 대기 포함). 4분 압축판은 §2 끝에 있다. 발표 시간이 정해지면 압축판을 기준으로 줄이거나 늘린다.
- **시연 사진**: Wikimedia Commons의 공개 사진(CC0)이다. 우리 현장 사진이 아니다. 시연을 시작할 때 이 한 문장을 먼저 말한다.
- **핵심 메시지 3개**: ① 첫 점수는 몇 초 안에 나온다 ② 입력은 한 페이지에서 끝나고 다시 묻지 않는다 ③ 해당 여부와 점수는 조사자가 검토해 정한다.
- 시연이 안 될 때를 대비해 같은 순서의 캡처가 슬라이드 8~13에 있다(각 단계에 번호를 적어 두었다).

## 1. 시연 전 준비

### 하루 전(시연할 PC에서)

1. 저장소를 최신으로 맞춘다. 브랜치 `fix/quickflow-score-so-far-20261026`의 `4fb3dc3` 이후여야 한다(`git log -1 --oneline`).
2. PowerShell에서 `docs\presentation\demo` 폴더로 가서 한 번 실행한다.

   ```powershell
   .\prepare-demo.ps1
   ```

   스크립트 실행이 막히면 `powershell -ExecutionPolicy Bypass -File .\prepare-demo.ps1`로 실행한다. 점검 항목이 모두 `[OK]`이면 된다: 가상환경, Electron, 자세 모델, 시연 사진, AI 키, 시연용 새 DB, **AI 연결 시험**(아주 작은 요청 1번, 이 PC에서 14.8초 걸렸다). `[!!]`가 나오면 뒤에 적힌 해결 방법을 따른다. 키는 화면에 찍거나 저장하지 않는다.
   - 다른 PC·다른 공급자 키를 쓰면: OpenAI 키를 `OPENAI_API_KEY`로 두고 `.\prepare-demo.ps1 -Model gpt-6-luna`.
3. `demo\photos` 폴더를 통째로 바탕화면(`LOCO-시연`)에 복사한다. 파일 선택 창에서 바로 찾으려는 것이다. 같은 폴더의 `시연-문장-키보드.txt`는 열어 두었다가 한 줄을 복사해 둔다(직접 치면 오타와 시간이 든다).
4. 앱을 한 번 열어 본다: `.\start-demo.ps1` (앱을 닫으면 창으로 돌아온다). 첫 분석에서는 자세 모델을 불러오느라 몇 초 더 걸릴 수 있으니, 하루 전에 한 번 끝까지 돌려 둔다.

### 시연 10분 전

1. 전원 연결, 절전·화면 보호기·알림 끄기, 다른 앱 닫기. 해상도는 1920×1080 이상, 앱 확대는 100%(`Ctrl+0`).
2. `.\prepare-demo.ps1`을 다시 실행해 시연용 DB를 새것으로 만들고 AI 연결을 확인한다(14.8초).
3. `.\start-demo.ps1`로 앱을 열어 첫 화면(`＋ 새 분석 시작`)에서 멈춰 둔다. PowerPoint와는 `Alt+Tab`으로 오간다.
4. 네트워크를 확인한다. 불안하면 휴대전화 핫스팟을 준비한다.
5. 슬라이드 8~13(백업 캡처)을 열어 둔다.

## 2. 시연 순서와 대본

### 시작 (20초)

> 지금부터 실제 앱으로 보여 드리겠습니다. 사진은 현장 사진이 아니라 공개 사진이고, 한 장과 문장 하나로 시작합니다.

### 1) 사진과 한 문장 (약 40초) · 슬라이드 8

- `＋ 새 분석 시작` → `왼쪽에서` 칸의 `사진 선택` → 파일 창에서 바탕화면 `LOCO-시연\01-키보드작업(CC0).jpg` → 자르기 창에서 `선택 영역 등록`.
- `어떤 작업인가요?` 칸에 문장을 붙여 넣는다.

  > 키보드와 마우스로 입력하는 작업을 하루 8시간 합니다. 1년에 220일 일하고 일회성 작업은 아니에요. 다른 작업은 하지 않아요.

> 사진 한 장과, 평소 말하듯이 쓴 문장 하나입니다. 서식을 채우는 게 아니라 이야기하듯 적습니다.

### 2) 분석과 첫 점수 (약 1~1.5분) · 슬라이드 9

- `사진·작업 설명 정리`를 누른다. **몇 초 안에** `2. 자동 정리·1차 점수` 화면이 나오고, 위쪽에 "AI가 사진과 작업 설명을 정리하고 있어요. 1차 점수는 먼저 보여 드려요."가 뜬다. 이 동안 버튼은 일부러 잠겨 있다(두 요청이 겹치지 않게 하려는 것이다).
- AI가 끝날 때까지 화면은 건드리지 않고 §3의 이야기를 한다. 끝나면 입력 창이 저절로 열린다.

### 3) 한 페이지 입력 (약 1~2분) · 슬라이드 10·11

입력 창 제목은 "작업 정보를 한 번에 확인해 주세요"다. 이 창이 시연 중 **처음이자 마지막** 입력 창이다.

| 순서 | 화면 | 고를 것 | 말할 것 |
|---|---|---|---|
| ① | `이미 확인한 정보 N개`(맨 아래 접힘) | 열어서 AI가 문장에서 채운 값(키보드 작업, 하루 8시간, 연 220일 등)을 잠깐 보여 준다 | "이 값들은 제가 입력한 게 아니라 문장에서 AI가 옮겨 적은 것입니다. 다시 묻지 않습니다." |
| ② | `작업 특징` 아래의 `선택하지 않은 나머지 작업은 모두 안 해요` | 한 번 누른다 | "나머지는 한 번에 '안 한다'로 채웁니다. 칸마다 답할 필요가 없습니다." |
| ③ | `사진 확인`: "올린 사진이 모두 한 사람의 전신이 나온 평소 작업 모습인가요?" | `예, 모두 맞아요` | "사진을 믿어도 되는지는 사람이 정합니다." → **같은 창에 체크리스트가 나타난다** |
| ④ | `이 순간 손에 든 물건이나 미는 힘이 있나요?` | `없음` | |
| ⑤ | `자세 체크리스트` | `앉아서 작업함`만 체크하고 `확인 끝 · 체크 안 한 항목은 해당 없음` | "해당하는 것만 체크하고 나머지는 한 번에 '해당 없음'입니다. 눌러야만 저장됩니다." |
| ⑥ | `사진이 읽지 못해 직접 골라야 하는 항목` | 아래 표대로 고른 뒤 `왼쪽 팔·손목은 오른쪽과 같아요` | "사진이 못 읽는 것만 묻습니다. 한쪽을 고르면 반대쪽은 복사합니다." |
| ⑦ | 아래 단추 | `저장하고 결과 보기 →` | "여기서 입력은 끝입니다. 이후 다시 묻지 않습니다." |

⑥에서 고를 값(발표자가 사진을 보고 고른 값이라고 말한다):

| 질문 | 고를 값 |
|---|---|
| 목은 어떤가요? | 똑바로·조금 숙임(20° 이내) |
| 몸통을 얼마나 굽히나요? | 똑바로 |
| 오른쪽 양팔 위팔을 얼마나 드나요? | 몸 옆(20° 이내) |
| 오른쪽 양팔 팔꿈치 각도는 어떤가요? | 60~100° |
| 오른쪽 손목을 앞뒤로 얼마나 굽히거나 젖히나요? | 15° 이내 |
| 오른쪽 손잡이나 잡는 상태는 어떤가요? | 좋음 |
| 왼쪽 팔꿈치 | (사진이 이미 잼: 88°, 묻지 않는다) |

`앉아서 작업함`을 체크하면 무릎 질문은 나오지 않는다(리허설에서 나오지 않았다). 화면에 나오는 질문만 고르면 된다.

### 4) 결과 (약 40초) · 슬라이드 12

- 리허설 결과: **최종 REBA 1점 · 무시 가능**, 왼쪽 1점·오른쪽 1점 중 높은 쪽, `법정 기준 11개 중 1개가 해당 초안`(키보드·마우스 집중 입력, 법정 1호). 입력에 따라 달라질 수 있다.

> 점수는 규칙 계산이고 AI가 바꾸지 않습니다. "해당 초안"은 입력한 값으로 계산한 결과이고, 최종 해당 여부는 조사자가 검토해 정합니다.

- 점수가 낮게 나온 것은 사진 속 자세가 양호했기 때문이다. "안전하다"고 말하지 않는다.
- 상자 들기 예(같은 방법, 다른 결과)는 슬라이드 12의 캡처로 보여 준다.

### 5) Excel (약 40초) · 슬라이드 13

- `Excel 미리보기` → 탭 `조사 결과` / `부담작업 해당 여부` / `자세 분석(REBA)` / `입력한 값`. **`입력한 값` 탭**으로 가서 각 값에 `직접 입력: …`, `자세 체크리스트에서 …` 같은 근거가 붙은 것을 보여 준다.

> 어떤 값이 사람이 고른 것이고 어떤 값이 AI·사진에서 온 것인지 근거가 함께 남습니다.

- 시간이 되면 `Excel로 저장`을 눌러 파일로 저장한다(저장 위치 창이 뜬다). 이 PC에 Excel이 없으면 미리보기까지만 한다.
- 이 화면 아래의 `Excel 만들기 전 확인` 상자는 `빠진 항목이 없어요. 그대로 Excel로 저장해도 돼요.`라고 나온다(리허설에서 확인, §7). `입력하러 가기` 버튼은 없다. 점수 계산에 쓰이지 않는 근로자대표 참여·증상조사·작업장 상황·수시조사 사유는 묻지도 보여주지도 받지도 않는다.

### 마무리 (20초)

> 정리하면, 첫 점수는 몇 초, 입력은 한 페이지, 판단은 조사자입니다. 한 페이지에서 비운 칸이 있으면 결과 화면의 `입력 수정하기`를 눌러야만 같은 창이 다시 열립니다. 스스로 다시 묻지 않습니다.

### 4분 압축판

2)의 대기 이야기를 30초로 줄이고, 3)에서는 ③⑤⑦만 말하며 ①④는 조용히 넘어간다. 5) Excel은 `입력한 값` 탭을 10초만 보여 주고, 4) 결과는 점수와 `해당 초안` 한 줄만 말한다.

## 3. AI가 도는 동안 말할 거리 (대기 60~90초)

화면에는 1차 점수·색 막대·사진 위 관절 표시가 떠 있다. 침묵하지 않도록 아래를 차례로 말한다. 가운데 것부터 쓰고 AI가 끝나면 그 자리에서 멈춘다.

1. **첫 점수**: "사진 한 장에서 관절 33개를 재서 먼저 낸 점수입니다. 아래팔이 88도, 왼쪽 1단계로 읽혔습니다."
2. **가정**: "사진에 안 보이는 항목은 '부담 없음'으로 가정했다고 화면에 적혀 있습니다. 확정 점수가 아니라서 '확정 전'이라고 표시합니다."
3. **AI가 지금 하는 일**: "지금 AI가 둘을 합니다. 문장에서 시간·일수 같은 값을 칸에 옮기고, 사진 속 동작을 말로 설명합니다. 점수는 AI가 만들지 않습니다."
4. **왜 몇 초 만에 점수가 나오나**: "예전에는 AI가 끝나야 화면이 나왔습니다. 지금은 사진 측정이 먼저 보이고, AI는 뒤에서 일합니다."
5. **시간**: "AI는 보통 1분 남짓 걸립니다. 120초 안에 답이 없으면 같은 요청을 자동으로 다시 보냅니다."

## 4. 문제가 생겼을 때

| 상황 | 대처 |
|---|---|
| 앱이 안 열린다·너무 느리다 | 슬라이드 8~13의 캡처로 같은 순서로 말한다. 대본은 그대로 쓴다. |
| 분석 뒤 AI 오류 문구가 나온다(키·네트워크) | 첫 점수는 정상이다. "AI 없이도 점수는 먼저 나옵니다"로 넘어간다. 입력 창이 열리면 `문장으로 더 적기`를 열어 문장을 지우고 직접 고른 뒤 저장한다(문장이 남아 있으면 저장 때 AI를 다시 부른다). 리허설에서 이 경로로 최종 점수까지 간 것을 확인했다. |
| AI가 90초를 넘긴다 | 첫 점수 화면을 계속 설명하고 질문을 받는다. 120초에 자동으로 다시 보낸다(최대 3번). 3분을 넘기면 슬라이드 10~13으로 넘어간다. |
| 입력 창이 실수로 닫혔다(`나중에 확인`·`Esc`) | 결과 화면의 `입력 수정하기`를 누르면 같은 창이 다시 열린다. 스스로 다시 열리지는 않는다. |
| 파일 선택 창이 사진을 못 찾는다 | 바탕화면 `LOCO-시연` 폴더를 연다. 파일을 끌어다 놓아도 된다. |
| 화면 글자가 너무 작거나 크다 | `Ctrl+0`으로 100%로 되돌린다. |
| 점수가 리허설과 다르다(예: 2점) | 정상이다. 입력한 값에 따라 달라진다. "그래서 조사자가 검토합니다"로 잇는다. |
| Excel이 없다·저장 창이 안 뜬다 | 미리보기 탭까지만 보여 준다. |

## 5. 예상 질문과 답

- **정확한가요?** 공개 사진으로 흐름을 시험했고 현장 사진 시험은 아직 하지 않았습니다. 사진이 못 읽는 각도는 사람이 고르고, 최종 판단은 조사자가 합니다. 의학적 효과나 법적 적합성을 입증한 것이 아닙니다.
- **AI가 틀리면요?** AI는 문장에서 값을 옮겨 적고 사진 속 동작을 설명할 뿐이고, 점수와 해당 여부는 규칙 계산(REBA, 법정 11개 기준)이 합니다. 사용자가 직접 고른 값은 AI가 덮어쓰지 않고, 사진에서 확신이 없는 값은 칸에 넣지 않습니다.
- **개인정보·키는요?** 분석 단추를 누르기 전에는 AI로 아무것도 보내지 않습니다. 누르면 자른 사진과 문장이 AI로 갑니다. DB는 이 PC의 SQLite이고 AI 키는 환경 변수로만 쓰며 저장하지 않습니다.
- **AI를 몇 번 부르나요?** 사진 한 장 기준 AI 요청이 3번입니다: 사진 판독 1, 문장 정리 1, 빠진 값 점검 1. 사진 판독과 문장 정리는 동시에 보냅니다.
- **시간이 얼마나 걸리나요?** 첫 점수는 4~10초, AI까지 끝나는 데는 보통 1~1.5분입니다. 가끔 더 걸립니다(§7).
- **다른 작업은요?** 같은 방법으로 상자 들기 등을 판정합니다. 슬라이드 12에 예가 있습니다.
- **근로자 참여나 증상조사는요?** 점수 계산에 쓰이지 않는 항목은 받지도 보여주지도 않기로 했습니다. LOCO는 REBA 계산과 그 값을 Excel로 드리는 데까지만 합니다.
- **앞으로는요?** 슬라이드 14·15: 현장 사진으로 시험, AI 응답 시간과 구조 개선, 덜 묻는 방향.

## 6. 시연 뒤 정리

1. 앱을 닫는다(창으로 돌아온다).
2. 시연 기록을 지우려면 `Remove-Item ..\..\..\.local\demo.db`. 다음 시연 전에는 `.\prepare-demo.ps1`이 새 DB를 만든다.
3. AI 키는 어디에도 저장되지 않았다. 창을 닫으면 환경 변수도 사라진다(사용자 환경 변수 `AI_GATEWAY_API_KEY`는 그대로 있다).

## 7. 리허설 기록 (2026-10-27)

실제 앱(Electron + 자세 모델 MediaPipe Heavy), 실제 AI(`gpt-6-luna`, 추론 강도 `high`), `prepare-demo.ps1`로 만든 시연용 DB, 시연 사진·시연 문장 그대로. 두 번을 동시에 돌렸다.

| | 첫 점수 보임 | 전부 끝남(AI 포함) | 입력 창 열림 | 조작 횟수 | 최종 |
|---|---|---|---|---|---|
| 리허설 1 | 9.9초 | 87.3초 | 1번 | 18회 | REBA 1점 · 무시 가능, 11개 중 1개 해당 초안 |
| 리허설 2 | 7.4초 | 65.0초 | 1번 | 18회 | 같음 |

- 조작 18회: 새 분석·문장·사진 선택·자르기·분석 5회, 나머지 작업 안 해요 1회, 물건 없음·사진 상황 2회, 체크 1회, 확인 끝 1회, 각도 선택 6회, 복사 1회, 저장 1회. 시연에서는 문장을 붙여 넣으므로 키보드로 치는 시간은 없다.
- 저장된 사용자 답의 근거: `직접 입력` 12, `자세 체크리스트에서 해당한다고 직접 체크` 2, `…해당 없음으로 직접 확인` 34, `왼쪽은 오른쪽과 같다고 직접 선택` 4.
- AI 대기 시간은 변동이 크다. 같은 작업을 `high`로 돌린 6번: 55초·65초·73초·73초·87초·**256초**. 한 번은 첫 AI 요청이 235초 만에 "불완전 응답"으로 끝나고, 이어진 후속 호출이 같은 값을 채워 결과는 정상이었다(120초 재전송 규칙은 그 뒤에 넣었고 실제 AI로 120초 초과를 만들어 보지는 못했다). 두 번을 동시에 돌려 첫 점수가 단독 실행(3.6~6.1초)보다 늦었다.
- 점수에 쓰이지 않는 항목(근로자 참여·증상조사·작업장 상황·수시조사 사유)을 뺀 뒤 같은 시연을 실제 AI로 한 번 더 돌렸다: 첫 점수 4.2초, 전부 끝남 81.9초, 입력 창 1번, 조작 18회, 최종 REBA 1점 · 무시 가능. Excel 단계의 확인 상자는 `빠진 항목이 없어요`였고 `입력하러 가기`는 없었다.
- 한계: 공개 사진이고 현장 사진이 아니다. 리허설의 각도 값은 §2 표대로 사진을 보고 고른 값이지 측정이 아니다. 앱 창을 눈으로 보며 사람이 눌러 본 것이 아니라, 같은 화면을 시험 스크립트로 눌렀다(실제 클릭 순서·문구·화면은 같다). 시연 PC에서 하루 전 한 번 직접 눌러 보고 시간을 재 둔다.
