# 발표 자료 생성 (deck-src)

`../LOCO-발표.pptx`를 만드는 스크립트다. 발표 PPT는 PowerPoint에서 직접 고쳐도 되지만, 시험 숫자나 문구가 바뀌면 여기서 다시 만들어야 슬라이드·발표자 노트·그림이 함께 갱신된다. 이 폴더의 파일은 앱 실행과 무관하다.

## 만들기

```powershell
cd docs\presentation\deck-src
npm.cmd install
node build-deck.mjs
```

- 기본 입력은 `..\assets\`의 앱 화면 캡처(`demo-*.png`)이고, 기본 출력은 `..\LOCO-발표.pptx`, 임시 파일은 `.work\`(git 제외)다.
- 경로를 바꾸려면 `--assets <폴더> --out <파일> --work <폴더>`를 준다.
- Node.js가 필요하다(만든 PC는 v24). 한글 글꼴은 Windows 기본 "맑은 고딕"(Malgun Gothic)을 쓴다.

## 내용을 고칠 때

- 시험 숫자: `build-deck.mjs` 위쪽의 `FACTS`와 해당 슬라이드의 문구·발표자 노트(1·3·5·8~12·14~16번). 숫자와 한계의 정본은 [TEST_FACTS.md](../TEST_FACTS.md)다. 거기 없는 수치는 만들어 쓰지 않는다. 시험 개수(Python 529·프런트엔드 37개 파일, `FACTS`)는 커밋 `457b5f5`(범위 정리, 2026-10-27) 기준이다.
- 사용한 캡처: `demo-01-photo-chosen.png`, `demo-onepage-01-first-score-while-ai-runs.png`, `demo-dialog-1`~`5`, `demo-onepage-07-result-final.png`, `demo-06-final-result-lifting.png`(상자 들기 기준 초안 표만 잘라 씀), `demo-excel-00-summary.png`·`demo-excel-01-input-values.png`(13번. 미리보기 카드 영역까지만 쓴다. 두 파일은 범위 정리 전의 옛 «Excel 만들기 전 확인» 상자 이하를 잘라 둔 것이고, 슬라이드에 쓰는 범위는 그대로다. `입력한 값` 탭은 위쪽 행과 아래쪽 행을 따로 잘라 쓰고 그 사이에 "중간 행 생략"을 적었다). `demo-05-final-result-keyboard.png`와 `assets\obsolete\`의 캡처는 쓰지 않는다. 캡처를 바꾸면 `IMG`를 고친다.
- 시연 슬라이드(8~13번)의 위쪽 표시(`시연 1~3`, `시연 6 ①~④` 등)는 [시연-시나리오.md](../demo/시연-시나리오.md)의 큐카드 번호이고, 노트의 대본·눌러야 할 순서·플랜 B도 그 문서와 맞춘 것이다. 시나리오 문서를 고치면 8~13번 노트와 보이는 글도 같이 고친다. 첫 점수 시간은 이 문서를 따라 "4~10초"(단독 실행 실측 3.6~6.1초, 리허설 두 개 동시 실행 7.4·9.9초)로 쓰고, 조작 횟수는 리허설 18회(체크 1회 포함)와 TEST_FACTS 17회를 구분해 적었다.
- 코드 상태: 커밋 `fcfa0a5`(첫 점수 먼저·체크리스트·high), `f66f103`(입력 한 페이지), `4fb3dc3`(AI 요청 120초 무응답이면 같은 요청 다시 보냄), `457b5f5`(점수에 안 쓰이는 입력 4묶음 제거, 범위 정리)가 원격 브랜치 `fix/quickflow-score-so-far-20261026`에 푸시되어 있다(맨 위 `457b5f5`, 2026-10-27). 슬라이드의 시험 숫자·캡처는 `f66f103` 시점의 실제 앱 실행 기록이고, `4fb3dc3`의 재전송은 실제 AI로 120초 초과를 만들어 시험하지 못했다(실제 SDK와 일부러 느리게 만든 로컬 서버로 확인). 이 한계는 14·15·16번 노트와 `resendNote`에 있다.
- 슬라이드 글·노트: 슬라이드별 블록(`// 1.` ~ `// 16.`).
- 캡처에서 잘라 쓰는 범위: `IMG`의 `[왼쪽, 위, 오른쪽, 아래]` 픽셀. 사진 오른쪽의 떠 있는 단추 줄(맨 위로·홈·폴더)이 나오지 않게 오른쪽 가장자리를 잘라 썼다. 상자 사진 결과 화면에는 같은 안내 문장이 두 번 보이는 줄이 있어, 그 캡처는 그 줄이 나오지 않게 잘라 썼다.
- 슬라이드에 공개 사진이 나오면 [PHOTO_CREDITS.md](../assets/PHOTO_CREDITS.md)의 출처를 작게 표기한다.
- 점수와 해당 여부는 조사자가 검토해 정한다는 문구, "공개 사진 시험이며 현장 사진 시험이 아니다", "시연 점수는 사진이 못 읽는 각도를 시험 스크립트가 임의로 고른 값이라 흐름 확인용"이라는 문구는 지우지 않는다.

## 글자 넘침 점검

PowerPoint가 없는 PC에서 슬라이드를 눈으로 볼 수 없을 때 쓴다. 맑은 고딕 글꼴 파일의 실제 글자 폭으로 어절 단위 줄바꿈을 흉내 내어 칸을 넘는 글자·슬라이드 밖 도형·글상자 겹침을 알려 준다. `python-pptx`와 `Pillow`가 있는 Python(이 저장소의 `.venv`가 아닌 별도 환경 권장)으로 실행한다.

```powershell
python audit_fit.py ..\LOCO-발표.pptx
```

실제 PowerPoint의 줄 나눔과 조금 다를 수 있는 참고용 검사이므로, 발표 전에 PowerPoint에서 한 번 열어 모든 슬라이드를 눈으로 확인한다.

## 만든 시점에 확인한 것과 못 한 것 (2026-10-26)

- 확인함: 파일 구조 검사(OOXML 스키마·관계·내용 형식) 통과, 16장 모두 발표자 노트와 그림 대체 텍스트 있음, `audit_fit.py` 문제 0건, 오픈소스 브라우저 렌더러(`pptx-preview`)로 16장을 이미지로 뽑아 눈으로 확인.
- 못 함: 실제 PowerPoint·LibreOffice에서 열어 보기(이 PC에 없었다). 위 렌더러는 줄바꿈·차트·글머리표를 PowerPoint와 다르게 그릴 수 있다(예: 14번 막대 그래프의 항목 이름·막대 위 숫자·막대 색을 그리지 않았다). 차트(14번)와 글머리표(15번)는 PowerPoint에서 직접 확인이 필요하다.
- 못 함: 실제 앱을 다시 실행해 화면·점수·시간을 대조하기. 슬라이드의 화면은 `..\assets\`의 캡처이고, 숫자는 TEST_FACTS.md를 옮긴 것이다. 법령 원문 대조도 하지 않았다(슬라이드에는 고시 이름만 있고 조항·주기·수치는 쓰지 않았다).
