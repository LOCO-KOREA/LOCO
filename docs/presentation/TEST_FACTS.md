# 발표용 시험 사실 (2026-10-26 실측, 한 페이지 입력 반영본)

발표 자료에 쓸 수 있는 숫자와, 반드시 같이 말해야 하는 한계를 모았다. 여기 없는 수치는 만들어 쓰지 않는다. 이 문서를 만든 시점의 사실이며, 발표 직전에 코드와 `docs/`가 바뀌었는지 확인한다.

## 어떻게 시험했나

- 실제 Electron 앱(숨김 창)을 화면에서 누르는 방식으로 처음부터 끝까지 돌렸다. 뒤쪽은 실제 Python 서비스, 실제 MediaPipe Pose Landmarker Heavy, 실제 외부 AI(`gpt-6-luna`, 추론 강도 `high`)다.
- 입력 사진은 공개 사진이다(`assets/PHOTO_CREDITS.md`). **우리 현장에서 찍은 사진으로 한 시험이 아니다.**
- 사진 4종: 키보드 작업, 상자 들어 올리기, 재봉틀 작업, 두 사람이 함께 나온 사진(사진을 쓰지 않는 경로).
- 모든 시험이 끝까지 가서 **최종 REBA 점수, 법정 11개 기준 초안, Excel 미리보기**가 나왔다.

## 숫자

- **첫 점수가 보이기까지**: 분석을 누르고 3.6초·4.1초·6.1초(세 번 실측). 사진 측정만으로 나오는 1차 점수를 AI가 끝나기 전에 먼저 보여 주고, AI가 일하는 동안 보내는 버튼은 잠긴다.
- **AI가 문장 한 줄과 사진을 정리하는 데 걸린 시간**(같은 키보드 사진·같은 문장)
  - 추론 강도 `xhigh`: 113~170초(세 번 실측: 170초·121초·113초)
  - 추론 강도 `high`로 낮춘 뒤: 55초·73초·73초(세 번). **한 번은 256초**가 걸렸다. 첫 AI 요청이 235초 만에 "불완전 응답"으로 끝났고, 이어진 후속 점검 호출이 같은 값을 채워 결과는 정상이었다. 네트워크·모델 상태에 따라 크게 달라진다.
- **입력을 요구하는 창이 열리는 횟수**: 처음엔 세 번(작업 특징 → 작업 조건 → 결과 후 다시 열림), 중간에 두 번, **지금은 한 번**이다. 한 페이지에서 답하고 저장하면 다시 열리지 않는다(실제 앱 실행 4번에서 확인, 열림 횟수 1).
- **조작 횟수**(키보드 사진 1장 + 한 문장, 실제 AI, 한 페이지 입력): **17회**
  - 새 분석·문장 입력·사진 선택·자르기 확인·분석 5회, "나머지 작업은 모두 안 해요" 1회, 사진 속 물건 선택 1회, 사진 상황("한 사람의 전신이 나온 평소 모습인가요?") 선택 1회, 체크리스트 "확인 끝" 1회, 사진이 못 읽은 각도 고르기 6회, 반대쪽 팔로 복사 1회, 저장 1회
  - 이전 방식(결과를 본 뒤 다시 여는 두 번째 입력 창)은 19회였다. 다만 처음의 칸별 입력 방식과 비교한 측정은 없으므로 "몇 배 줄었다"고 말하지 않는다.
- **시험 규모**(범위 정리 반영, 2026-10-27): Python 시험 529개(알려진 환경 문제 1개: PDF 시험용 `pdfplumber` 미설치. 이 밖에 가끔 실패하는 오래된 시험 2개가 있고 수정 전에도 같았다), 프런트엔드 시험 37개 파일 전부 통과. 독립 검토를 두 번 받았고, 두 번째 검토가 찾은 결함 12건(중요 1·보통 5·사소 6)을 모두 고쳤다.

## 범위 정리 (2026-10-27 소유자 지시: "점수 계산에 안 쓰이면 보여주지마. 받지도 마.")

- LOCO는 REBA 계산과 그 값을 Excel로 주는 것까지만 한다. 점수 계산에 쓰이지 않던 입력 4묶음(수시조사 사유, 작업장 상황, 근로자 참여, 증상조사)은 묻지도, 보여주지도, 받지도 않는다. 예전에 저장된 값은 DB에서 지우지 않고 그대로 두지만 화면·Excel·서비스 응답에는 나오지 않는다.
- Excel 단계의 `Excel 만들기 전 확인` 상자에서 `입력하러 가기` 6개가 사라졌다. 계산에 실제로 빠진 값이 있을 때만 그 줄과 버튼이 나온다. 점수에 쓰이지 않는 보조 표(자세 표시)의 "일부 비어 있어요" 줄도 뺐다.
- 남긴 것: 조사 유형·조사일·이전 조사일·조사자·부서·공정·제목(Excel 머리말에 찍히는 값).
- 실제 앱 + 실제 AI로 시연 흐름을 다시 돌렸다: 첫 점수 4.2초, 전부 끝남 81.9초, 입력 창 1번, 조작 18회, 최종 REBA 1점 · 무시 가능. Excel 단계 상자는 "빠진 항목이 없어요. 그대로 Excel로 저장해도 돼요."였다(한 번 돌린 값이다).
- 이 변경은 커밋 `457b5f5`로 올라가 있다(아래 "코드가 올라간 곳" 참고).

## 시연 흐름(실제로 누른 순서)

1. 새 분석 → 사진 올리고 자르기 확인 → 작업을 한 문장으로 입력 → 분석
2. **몇 초 안에 1차 점수가 먼저 나온다**(`assets/demo-onepage-01-first-score-while-ai-runs.png`). 화면 위에 "AI가 사진과 작업 설명을 정리하고 있어요. 1차 점수는 먼저 보여 드려요."가 뜬다. 못 잰 항목은 부담 없음으로 가정했다고 적혀 있다.
3. AI가 끝나면 **입력 창이 한 번만 열린다**(`demo-dialog-1-work-features.png`). 한 페이지 안에 작업 특징 → 작업 조건 → 사진 확인 → 자세 체크리스트 → 사진이 못 읽은 각도가 차례로 있고, 모두 고르기로 답한다. 숫자 칸에도 선택지(예: 연 220일, 하루 480분)가 있고 직접 입력도 된다. 사진 상황을 고르면 같은 창에 체크리스트가 나타난다.
4. 해당하는 자세만 체크하고 "확인 끝"을 누르면 나머지는 "해당 없음"으로 저장된다(`demo-dialog-2-checklist.png`, `demo-dialog-3-checklist-confirmed.png`).
5. 사진이 못 읽은 각도만 고른다. 한쪽 팔을 정하면 반대쪽으로 복사할 수 있다(`demo-dialog-4-angles.png`).
6. "저장하고 결과 보기" → 최종 REBA 점수 + 법정 11개 기준 초안 + Excel 미리보기(`demo-onepage-07-result-final.png`). 직접 입력한 값에는 근거 문구가 남는다. 저장한 뒤에는 화면이 스스로 다시 묻지 않는다. 비워 둔 칸이 있으면 결과 화면의 "입력 수정하기"를 눌러야만 같은 페이지가 다시 열린다.

## 알려진 한계 (발표에서 숨기지 않는다)

- 사진이 못 읽는 각도(목·몸통·손목 등)는 사용자가 골라야 한다. **시연 캡처의 최종 점수는 시험 스크립트가 그 각도를 임의로 고른 값이라 "흐름을 확인한 것"이지 측정이 아니다.**
- AI가 한 문장에서 "반복 작업" 같은 작업 특징을 넓게 읽어 입력칸이 늘어날 때가 있다(원래 있던 동작).
- AI 응답 시간이 일정하지 않다. 보통 1분 안팎이지만 4분 넘게 걸린 적이 있다. 첫 점수는 AI와 무관하게 몇 초 안에 먼저 보인다.
- **120초 안에 답이 없으면 같은 요청을 다시 보내도록 바꿨다**(처음 포함 최대 3번, 시간 초과가 아닌 오류는 다시 보내지 않는다). 실제 AI가 120초를 넘기는 상황을 만들어 시험하지는 못했고, 실제 SDK와 일부러 느리게 만든 로컬 서버(제한을 1초로 줄임)로 "다시 보낸 두 번째 요청의 답을 쓴다"는 것을 확인했다. 이 변경은 커밋 `4fb3dc3`으로 올라가 있다.
- 상자 사진 결과 화면의 "AI가 사진에서 확인한 모습" 영역에 같은 안내 문장이 두 번 이어서 보인다(이번 수정 범위 밖이라 손대지 않았고 원인은 확인하지 않았다). 그 캡처를 쓸 때는 이 줄을 가리거나 다른 캡처를 쓴다.
- 최종 해당 여부와 점수는 조사자가 검토해 정한다. 의학적 효과나 법적 적합성을 입증하지 않았다(`AGENTS.md`).
