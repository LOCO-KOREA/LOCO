# 요구사항 분석

> 멘토님 「요구사항 분석 템플릿」 형식 · 작성 2026-10-08 (팀 결정 반영판) · 수정 2026-10-12 (개발 동결 10/23, MVP는 사진 분석, 모델은 MoveNet Lightning) · 팀: 한정욱 · 김나리 · 유서하 · 정혁
> 이 문서가 **기능명세서 역할**을 겸한다. 템플릿의 세 열(ID·요구사항·우선순위)에 **화면**과 **확인 방법** 열을 더했다.
> 화면 번호는 화면명세서(`화면명세서_GPT용.md`)의 S01~S09와 같다. API·테스트도 이 FR 번호를 그대로 쓴다.

**구현 원칙: 법적 우선순위 그대로**

1. 산업안전보건법 → 2. 산업안전보건기준에 관한 규칙 제12장 → 3. 고용노동부고시 제2020-12호 → 4. 고용노동부 해설 (고시 각 호의 '주') → 5. KOSHA GUIDE H-9-2022 → 6. REBA (지침 부록 2의 평가도구)

- 판정과 경고는 고시 제3조의 부담작업 11개 기준을 그대로 쓴다.
- 자세의 각도 기준은 고용노동부 해설 값을 기본으로 쓰고, 화면과 엑셀에 출처를 보여 준다. 4호 목·허리 굽힘 20° 이상(허리 젖힘 20° 이상), 비틀림 목 5°·허리 20° 이상, 3호 팔꿈치 들기(위팔) 45° 이상, 5호 쪼그려 앉기는 무릎이 발끝보다 앞.
- 조사 절차는 KOSHA 지침을 따른다.
- REBA는 위험 정도를 보여 주는 데만 쓰고, 경고 기준으로 쓰지 않는다.
- 법과 해설 어디에도 없는 값은 앱이 만들지 않고 조사자가 정한다.

**우선순위의 뜻**

- **Must**: 10/23 서비스 MVP에 반드시 들어간다. 그중 사진 올리기부터 REBA까지는 10/16 Pose MVP에 먼저 동작한다.
- **Should**: 10/23 개발 동결까지 넣는다. 멘토 WBS의 기능 동결(10/27)보다 4일 당겼다 (일정서).
- **Could**: 시간이 남으면 한다.

**범위 결정 (2026-10-12, 한정욱)**

- **MVP의 분석 입력은 사진(스틸샷)이다.** 단위작업마다 작업 중 찍은 사진 여러 장을 올리고, 그 사진들의 비율로 하루 노출 시간을 추정한다 (워크샘플링). 영상은 MVP 이후에 사진을 뽑아 쓰는 방식으로 붙인다 (멘토 10/9: 정지 영상 먼저).
- **관절 모델은 MoveNet Lightning이다.** 관절 17개, 한 사람, 2차원. 발끝·손가락 점이 없어 쪼그림의 '발끝보다 앞'과 REBA 손목은 사람 확인이다.

### 2. Non-functional Requirements

| ID | 요구사항 |
|---|---|
| NFR-001 | 법적 우선순위를 지킨다. 판정·경고는 고시 제3조, 자세 각도는 고용노동부 해설, 조사 절차는 KOSHA 지침, 평가도구는 지침 부록 2(REBA). 아래 규정이 위 규정과 어긋나면 위 규정을 따른다. |
| NFR-002 | 법·고시·고용노동부 해설이 정하지 않은 값은 앱이 정하지 않는다. 조사자가 입력하고, 입력 전에는 "입력 필요"로 둔다. |
| NFR-003 | 판정 기준과 점수표는 원문(고시 제3조, 고용노동부 해설, KOSHA 부록, REBA 워크시트)과 같아야 한다. 원문 예시로 테스트하고, 일부러 망가뜨린 규칙을 테스트가 잡아내는지 확인한다. |
| NFR-004 | 같은 사진과 같은 입력이면 항상 같은 점수와 판정이 나와야 한다. |
| NFR-005 | 모든 점수와 판정은 근거(각도, 시간 비율, 입력값, 적용한 법 조항)를 함께 보여줘야 한다. |
| NFR-006 | 사람을 인식하지 못하거나 전신이 잘리면 이유와 다시 찍는 방법을 안내해야 한다. 여러 명이 찍힌 것은 한 사람 모델이라 앱이 알지 못하므로 촬영 안내로 막고 관절 겹쳐 보기로 조사자가 확인한다. |
| NFR-007 | 사진 30장의 분석이 발표용 노트북에서 1분 안에 끝나야 한다. 참고로 이 PC에서는 MoveNet Lightning이 한 장에 5.2ms였다 (2026-10-08 측정, 사진 읽기 시간 제외). 발표 노트북은 10/12에 실측한다. |
| NFR-008 | 윈도우 PC의 1366×768 이상 화면에서 모든 화면을 쓸 수 있어야 한다. |
| NFR-009 | JPG·PNG 사진과 폰의 회전 정보(EXIF)를 처리해, 누운 사진을 잘못 분석하지 않아야 한다. HEIC는 jpg로 바꿔 올린다. |
| NFR-010 | 원본 사진은 사용자가 고른 위치에만 두고 앱이 복사해 두지 않는다. 앱이 저장하는 사진은 분석마다 대표 사진 1장뿐이다. 재연 사진은 발표 후 삭제한다. |
| NFR-011 | 생성형 AI(GPT)는 설명 문장에만 쓴다. 점수·판정 계산에는 쓰지 않으며, 사진과 개인 신상정보는 보내지 않는다. |
| NFR-012 | 인터넷이 없어도 GPT 문장을 빼고 모든 기능이 동작해야 한다. |
| NFR-013 | 결과 화면과 엑셀에 "근골격계부담작업 해당 여부 결정과 조사 결과의 책임은 사업주와 조사자에게 있다"는 문구를 넣어야 한다. |
| NFR-014 | 조사 기록의 보존 기간(새 조사가 끝날 때까지, 신상정보가 있으면 5년, 개선계획은 해당 설비가 있는 동안)을 안내해야 한다. |
| NFR-015 | MoveNet Lightning의 각도 오차와 속도, REBA 일치율, 판정 일치율, 자동 확정 비율과 그중 오류율, 조사 1건 작성 시간을 재서 evaluation.md와 발표에 공개해야 한다. 목표치는 10/17 기술 검토에서 첫 측정값을 보고 정한다. |
| NFR-016 | 설치 파일 하나로 설치되어야 하고, 팀원 PC 2대 이상에서 동작을 확인해야 한다. |

### 3. Constraints

- **개발 기간**: 2026-10-07 ~ 10-30. 요구사항·설계 1차 10/14, Pose MVP 10/16, 서비스 MVP와 개발 동결 10/23, 멘토 기능 동결 10/27, 최종 발표 10/30. 멘토링 10/9 · 10/17 · 10/24.
- **개발 인원**: 4명 (한정욱 · 김나리 · 유서하 · 정혁). AI 코딩 도구를 쓰고 총괄이 검토한다.
- **사용 가능한 장비**: 개발 PC(i7-10700K, RTX 2070 SUPER, 32GB), 발표용 노트북(사양 확인 중), 재연 도구(상자, 선반, 수레, 각도기. 촬영 공간 요청 중), 사진을 찍을 휴대폰.
- **사용할 수 없는 것**:
  - 실제 사업장 촬영과 실제 근로자 사진
  - 힘·진동 측정 장비
  - 전문가가 판정한 정답 데이터 (팀원 두 명의 독립 채점과 공개 데이터로 대신)
  - GPT는 API 키가 있어야 하고 사용량만큼 비용이 든다
- **각도 기준의 출처**: 고시 본문에는 각도가 없고, 고용노동부 해설(고시 각 호의 '주')에 있다. 고시 본문(제2020-12호, 2020.1.16 시행)은 2026-10-12에 국가법령정보센터 원문과 대조했다. 해설의 각도 값은 같은 값을 싣는 글 3건으로 확인했다 (이동경·김증호, 인간공학회지 2010.8 · 이동경, 인간공학회 2011 춘계 · 정진우 성남지청장, 「산업보건」 2014년 11월호). 고용노동부 해설 원문 문서는 공개 사이트에서 찾지 못해 보지 못했다 (10/14까지 문의). 2004년 구판 해설은 굽힘을 30°로 풀이했고 현행 값(20°)과 다르다.

### 4. Out of Scope

이번 프로젝트에서는 구현하지 않는다.

- 실시간 카메라나 CCTV 상시 분석 (찍어 둔 사진만 분석)
- 영상 올리기와 프레임별 분석 (MVP 이후. 영상에서 사진을 뽑아 쓰는 방식으로 붙인다)
- 여러 사람이 찍힌 사진에서 분석할 사람을 고르기 (MoveNet 한 사람 모델)
- 모바일 앱 (안드로이드·아이폰), 웹 서비스, 클라우드 서버
- 판정 자동 확정 (확정은 항상 조사자)
- REBA 외 평가도구 (RULA, OWAS, NLE, Snook, Strain Index, WAC, 진동 기준)
- 손목 각도와 목·허리 비틀기, 쪼그림의 발끝 위치의 자동 측정 (MoveNet에는 손·발끝 점이 없어 조사자가 입력하거나 '사람 확인')
- 법과 고용노동부 해설이 정하지 않은 기준값을 앱이 정하는 것
- 실제 사업장 현장 검증, 부상 위험을 줄였다는 주장
- 의학적 진단, 근로자 개인 평가
- 여러 사업장·계정·권한 관리, 결제
- 자체 포즈 모델 학습

(법정 서식 자동 작성, 증상조사표, 근로자 안내문, 표본 수 도우미, 이전 조사 비교는 제외가 아니라 "시간이 남으면" 하는 Could 항목이다.)

### 5. 주요 Use Case

#### UC-001 작업 사진 분석하기

- **Actor**: 유해요인조사자
- **목적**: 단위작업의 사진 여러 장에서 REBA 점수와 법 기준 판정 근거를 얻는다.
- **사전조건**: 조사와 단위작업이 등록돼 있다(FR-001, FR-004). 하루 작업시간이 입력돼 있다(FR-005). 촬영 대상자가 동의했다(FR-010).

**기본 흐름**

1. 조사자가 단위작업을 고르고 사진 올리기 화면을 연다. (S04)
2. 앱이 촬영 안내를 보여준다. (FR-009)
3. 조사자가 작업 중 찍은 사진 여러 장을 고르고 동의를 확인한 뒤 분석을 시작한다. (FR-008, FR-010)
4. 앱이 진행률을 보여주고 관절을 찾는다. (FR-011, FR-012)
5. 앱이 대표 사진, REBA 점수, 법 문구의 자세별 비율(표본 비율), 판정 초안과 경고를 보여준다. (FR-015 ~ FR-021)
6. 조사자가 손목·손잡이·비틀림·지지 여부를 입력하면 결과가 바로 다시 계산된다. 각도 기준은 고용노동부 해설 값이 기본이고 출처가 함께 보인다. (FR-017, FR-018, FR-022)

**예외**

- 사람이 안 보이거나 전신이 잘렸다 → 이유와 다시 찍는 방법을 안내한다. (NFR-006)
- 사진에 회전 정보가 있다 → 바로 세워서 분석한다. (NFR-009)
- 사진이 5장보다 적다 → 알림을 보이고 자세 비율로 정하는 호를 "사람 확인"으로 둔다. (FR-016)
- 비틀림이나 지지 여부가 비어 있다 → 그 판정을 "입력 필요"로 둔다. (FR-017)
- 조사자가 해설 각도를 바꾸려 한다 → 사유를 받고 수정 이력에 남긴다. (FR-017, FR-025)
- 각도가 기준 경계 근처다 → 그 칸을 "사람 확인"으로 표시한다. (FR-023)

#### UC-002 부담작업 판정 확정하기

- **Actor**: 유해요인조사자 (근로자가 면담에 참여)
- **목적**: 단위작업마다 11개 기준의 해당 여부를 확정한다. 법이 모든 단위작업마다 결정하도록 요구한다.
- **사전조건**: UC-001의 분석 결과가 있다. 무게·횟수 등 입력값이 있다(FR-005, FR-006).

**기본 흐름**

1. 앱이 11개 기준별 초안과 근거를 보여준다. 예: 허리 20° 이상 굽힘 35% × 하루 6시간 = 2.1시간 → 4호 해당(초안). (FR-020)
2. 조사자가 근거를 확인하고, 필요하면 수정하면서 사유를 적는다. (FR-024)
3. 조사자가 확정한다.
4. 시스템이 수정 이력을 남긴다. (FR-025)

**예외**

- 입력값이 빠졌다 → "입력 필요"로 표시하고 그 기준은 확정할 수 없다.
- "사람 확인" 칸이 남아 있다 → 확정 전에 경고한다.

#### UC-003 엑셀 보고서 내보내기

- **Actor**: 유해요인조사자
- **목적**: 조사 결과를 엑셀로 받아 보고와 보존에 쓴다.
- **사전조건**: 단위작업 분석과 판정 초안이 있다.

**기본 흐름**

1. 조사자가 내보내기 화면에서 작업별 결과를 확인한다. (S08)
2. "엑셀로 내보내기"를 누른다. (FR-026)
3. 앱이 요약, 작업별 결과, 경고 기록, 판정 초안 시트로 파일을 만들고, GPT 요약 문장을 넣는다. (FR-027)

**예외**

- 확정되지 않은 칸이 있다 → "초안"으로 표시해서 내보낸다.
- GPT를 쓸 수 없다 → 요약 문장 없이 내보낸다. (FR-028)
