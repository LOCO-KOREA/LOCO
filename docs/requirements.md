# LOCO 요구사항

> 문서 ID ERGO-REQ-001 · 설계 버전 2.0 · 개정일 2026-10-16 · 완성 목표 2026-10-23(Asia/Seoul)

## 1. 프로젝트의 의의와 완성품

LOCO는 현장 조사자가 근골격계 부담작업의 근거를 빠짐없이 모으고, 11개 기준에 대한 계산 초안을 검토하고, 개선 전후를 같은 형식으로 설명·보관하는 데스크톱 도구다. 의미 있는 성과는 포즈 인식 시연보다 조사 기록의 누락을 줄이고 같은 입력에서 같은 계산 근거를 재현하는 것이다.

11개 호는 서로 겹칠 수 있는 부담작업 조건이다. 한 작업이 여러 호에 해당할 수 있고, 작업 이름만으로 호가 정해지지 않는다. 상자 들기·사무 작업·조립 작업을 모두 같은 일반 작업 모델로 처리한다. LOCO의 초안은 조사자의 사실 확인과 판단을 지원한다. 법정 조사 완료, 질환 진단, 자동 법률 판정, 개선의 임상 효과를 제품 성과로 주장하지 않는다.

10월 23일 완성품은 Windows에서 실행해 조사 생성 → 일반 작업 입력 → 11개 기준 초안 → 선택적 사진/REBA → 설명 작성 → 조사자 검토 → 저장·재열기 → 한글 Excel 출력 → 개선 전후 비교까지 이어지는 MVP다. “11개 지원”은 각 기준의 입력·누락·비교값·초안·조사자 결론·출력이 모두 연결되었다는 뜻이다. 성과 가설은 같은 현장 사례의 입력부터 보고서까지 걸리는 중앙값을 수기 과정 대비 30% 이상 줄이는 것이다. 이 수치는 실제 조사자 사례로 측정하기 전까지 목표이지 성과 주장이 아니다.

## 2. 역할과 지원 범위

| 주체 | 입력·출력 | 맡는 역할 |
|---|---|---|
| 사용자 | 작업 조건, 하루 노출량, 조건별 중량·힘·횟수, 근거, 관찰값 | 영상에서 알 수 없는 사실을 기록하고 계산·설명을 검토한다. |
| MoveNet | 선택 사진의 17관절, 신뢰도, 각도 후보 | 보이는 자세의 측정 보조. 물체 무게·힘·하루 시간·손가락 쥐기·실제 충격을 판별하지 않는다. |
| 규칙 엔진 | 확인된 입력 → 11개 기준 초안 및 별도 REBA | 버전이 고정된 결정적 계산, 누락·모순·해석 쟁점 표시 |
| GPT API | 허용 수치 요약 → 설명·추가 확인·개선안·호별 비구속 참고 선택 | 계산 근거를 설명하며 부족한 근거는 판단 보류로 둔다. 점수·계산 판정·원사실은 바꾸지 않는다. |
| 조사자 | 계산 초안 + 근거 → 결론·사유·검토 기록 | 책임 있는 최종 검토와 결과 적용 |

사진은 선택 기능이다. 11개 기준은 직접 입력만으로 모두 평가할 수 있다. 사진이 없을 때 사진 분석·REBA를 미요청으로 표시하며, 직접 입력의 완전성에 따라 기준 초안을 계산한다.

입력 템플릿 GENERAL/OFFICE/REPETITION/POSTURE/HAND_FORCE/LIFTING/IMPACT는 질문 순서와 도움말만 다르다. 상자 들기도 GENERAL_TASK와 GENERAL_STILLS_V1을 사용하며, 신규 작업에는 사진 15장·3회차·5순간·사건별 자동 하중을 요구하지 않는다.

## 4. 기준과 불확실성

조사 유형의 선택 provenance는 따로 보존한다. 사용자가 다른 조사 정보를 수정하면서 QuickFlow가 기존 조사 유형을 함께 보낸 경우, 값이 그대로면 UNKNOWN provenance를 USER로 승격하지 않는다.

부담작업 기준 계산은 MOEL_2020_12_GENERAL_V2로 고정한다. LOCO는 REBA 계산과 그 값을 Excel로 주는 것까지만 한다(2026-10-27 소유자 지시). 점수 계산에 쓰이지 않는 수시조사 사유·작업장 상황·근로자 참여·증상조사는 묻지도 보여주지도 받지도 않는다. Excel은 실제 기록한 입력과 계산 결과만 담으며, 고시 별지 1·2의 빈 서식이나 법정 서식 완성본을 만들지 않는다. LOCO Excel은 기록 요약이며, 법정 조사의 적용 여부와 방법은 담당자가 확인한다. 근거는 [안전보건규칙 제657조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030668407), [제658조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020911757), [고용노동부고시 제2020-12호](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000185793)다. 11개 수치 조건과 단기간·간헐적 작업 제외를 구현한다. 최신 개정·현장별 적용 해석은 별도 확인 사항이며, 이 설계만으로 현행 법률 검토 완료를 주장하지 않는다.

4·5·9호의 서로 다른 자세를 합산해야만 문턱을 넘는 경우, 법령에 정량 각도가 없는 자세를 기술각도로 단정하려는 경우는 검토 필요로 남긴다. REBA는 별도 자세 평가 방법이다. 높은 REBA를 곧바로 법정 해당으로, 낮은 REBA를 비해당으로 변환하지 않는다.

표본 사진의 자세 비율을 하루 노출시간·횟수로 확대하지 않는다. 기준별 조건 행에 실제 시간·횟수를 기록한다. 측정·관찰·면담·문서 출처를 남기며, 모르는 값을 0으로 채우지 않는다.

## 5. 설계 출발점과 현재 검증

설계 출발점은 main e7b0cf1205b7860fc4b755e43176ede77dc517d8이다. 아래 표는 당시 코드와 2.0 변경 범위의 이력이다. `feat/loco-2.0-oct23`의 현재 구현·실행 증거와 남은 제약은 [검증 대조표](local-verification.md)를 따른다.

| 영역 | 설계 출발점의 코드 | 2.0 변경 범위 |
|---|---|---|
| 작업/사진 | 상자 작업 종류와 15슬롯 전제 | 모든 작업의 일반 입력·가변 사진으로 변경 |
| 11개 기준 | 기존 입력·규칙 골격, 단일 작업 전제 | 조건별 행·직접 집계·누락/해석 상태로 재설계 |
| GPT | 고정 텍스트 생성 | 실제 API, 허용 요약, 실패 대체, 편집·적용 이력 |
| 저장 | 여섯 JSON 테이블·분석 snapshot | 계산/AI 부분 저장, 재연결 관찰 보존, 버전 호환 |
| 실행 | 루트 통합 서비스와 frontend의 이전 기본 adapter 공존 | 배포에서 공통 Application Service로 단일화 |

| 검증 | 기존 시험·샘플에 이전 가정 포함 | 기대값 검토 후 새 경계·실패·반례 검증 |

코드 정적 검토에서는 사진 경로 재연결 시 관찰·수동값 소실, 분석 저장 시 AI 편집 덮어쓰기 경로를 확인했다. 사진 경로 재연결과 AI 편집 충돌 경로는 현재 코드에서 수정하고 자동 회귀 사례를 추가했다. 남은 날짜는 독립 검토·깨끗한 PC·현장 검증에 사용한다.

다른 원격 브랜치는 대부분 main에 포함되어 있다. codex/db-storage-integration의 미병합 변경은 의존성·부분 저장 개선을 개별 검토해 가져오며, 브랜치 전체를 무조건 병합하지 않는다. 해당 브랜치의 문서/출력 버전 차이도 재확인한다.

## 7. 수용 기준과 전달물

- 11개 기준 각각 정상 해당·정상 비해당·누락·모순/해석의 최소 4종, 합계 44개 기준 사례와 각 수치의 바로 아래/같음/바로 위 경계를 검증한다. 제외 조건·OR·중복 제거·망라성은 추가 사례다.
- 가벼운 물체 99회와 무거운 물체 1회를 합쳐 무거운 물체 100회로 판정하는 반례를 잡는다. 미확인 행의 존재만으로 비해당을 확정하지 않는다.
- 사진 0건, 요청/미요청, 가림·EXIF 회전·비정방형 사진·모델 실패·불명 하중·동일 파일 재연결을 확인한다. 미완성 사진을 분모에서 빼 완성으로 만들지 않는다.
- GPT 실패·거절·불완전/모순 응답, 생성 중 편집·삭제·재분석을 확인한다. GPT 문장이 계산 결과를 변경할 수 없어야 한다.
- 임계값 변경 또는 null→0 같은 의도적 mutation을 독립 기대값이 잡는지 확인하고 되돌린다. 검증 결과는 실제 수행한 환경·입력·기대값·관측값으로 남긴다.
- 직접입력 작업, 사진으로 보완한 작업, 동일 작업의 개선 전후를 실제로 저장·재열기·출력한다. 시연용 값만으로 현장 검증을 했다고 표현하지 않는다.
- 최초/정기/수시 조사의 유형 경로를 각각 검증한다. Excel에는 사용자가 확인해 기록한 조사 유형만 출력하고, 어떤 유형에도 빈 별지 1·2를 붙이지 않는다. 수시조사는 사유 없이 저장된다. LOCO Excel은 법정 서식 완성본이 아니다.
- 수시조사 사유·작업장 상황·근로자 참여·증상조사는 어떤 화면에서도 묻지 않고, API가 받아도 저장하지 않으며, 미리보기·Excel·PDF 매핑에 나오지 않는지 확인한다. 이 값이 남은 옛 행도 읽힌다(tests/test_scope_cut.py, tests/frontend-scope-cut.cjs).
- 개발 환경 없는 Windows PC 실행 기록, 소스 커밋·모델/규칙/문서 버전, 설정 안내, 샘플 Excel, 검증 기록, 남은 결함·미검증 가정을 전달한다.

기본 판정은 NOT ACCEPTED다. 독립 검토의 P0/P1 반례가 해소된 범위만 제한적으로 수용한다. 미실행 시험·미확인 법 해석·표본의 대표성·GPT 내용의 정확성을 완료 보고에 포함한다. 단기 범위에서 영상 추적·자동 하루 시간 추정·자체 모델 학습·다중 인물 분리·클라우드 협업·의학적 예측은 구현하지 않는다.

## 적응형 추가 확인 (2026-10-22)

간편 입력은 사진·작업 설명에서 확보한 값을 자동 저장하고, 계산에 영향을 주는 누락·모호함·충돌만 추가 질문한다. 알려진 값과 모름 응답을 반복 질문하지 않으며, 미언급 항목은 UNKNOWN으로 유지한다. 현재 정보로 결과를 생성할 수 있다. 계약·검증 대상은 [적응형 추가 확인](adaptive-intake.md)을 따른다.

사용자 기본 동선은 AI와의 대화 팝업이다. 기존 설명·MoveNet 정보를 AI가 먼저 정리하고 정말 부족한 내용만 한 번에 하나씩 물으며, 사용자는 항목별 입력 폼을 채우지 않는다. 답변 정리·저장·계산 연결은 앱이 처리하고 실제 AI 응답 성공/실패를 화면에 표시한다.

AI 입력 정리·후속 질문·설명·사진 관찰은 공통 설정 계약(backend/ai_config.py, API 계약서 §6)과 같은 프로세스의 OpenAI client/HTTP 연결 풀을 공유한다. 모델·추론 강도·토큰 한도는 변수이며, 설정 화면은 서버 필드 정의로 렌더링한다. 앱은 AI 요청에 임의 대기 제한을 두지 않고 한 번 보낸 요청의 응답을 기다린다(2026-10-27 사용자 지시). 같은 입력을 자동으로 재송신하지 않으며 SDK timeout=None/max_retries=0을 공통 적용한다. 외부 오류가 발생하면 원인을 표시하며 자동 재송신하지 않는다. 구버전 timeout 값은 무시하며, APP_SETTINGS의 기존 JSON·테이블·이전 분석 snapshot 형식은 변경하지 않는다.

2026-10-23 표현 보완: `및`·연결어 없는 나열·“총 작업은…”과 복합 단위 `1시간 30분` 때문에 올바른 AI 값을 버리지 않는다. AI가 선택한 작업별 원문·분 환산값·합계를 공통 숫자 근거 모듈에서 검증한다. 겹치는 시간·휴식·중복 환산은 합산하지 않으며 사용자 직접 값과 과거 snapshot을 보존한다.

## 최신 main 통합과 재질문 방지 (2026-10-23)

최신 main의 Excel 출력·사진 크롭·공통 이동과 당시 2단계 묶음 확인(2026-10-26부터 한 페이지)을 기준으로 MediaPipe 및 저장 보완만 추가한다. 이미 KNOWN인 값과 USER가 모름으로 확인한 항목은 새 질문/질문 묶음에 넣지 않는다. 간편 묶음 서식에서도 기본 추가 입력에서 제외하고 닫힌 ‘이미 확인한 정보 · 수정하기’에서만 수정한다. 조건별 행과 좌우 사진의 identity를 유지하며 한 조건의 답을 다른 조건에 복사하지 않는다. ESTIMATED·CONFLICT 및 새 사진에 연결되지 않은 정보는 확인할 수 있다.

사진과 같은 물건이라고 확인한 유일 중량은 photo_load의 공통 해석으로 계산과 질문에 함께 사용한다. 이 파생값을 새 사실로 저장하거나 조회 revision을 올리지 않는다. 여러 중량, 확인하지 않은 연결, 명시적인 모름·무하중·직접 중량은 구분한다. 자동 저장과 수동 임시 저장이 같은 작업/생성시각을 가리키면 홈의 이어서 하기 카드는 수동 저장 하나로 표시한다. 별도 작업 초안은 보존한다.

사용자에게 보이는 시스템 용어는 frontend/user-language.json을 공통 사전으로 사용한다. 화면의 AI 본문·처리 상태·계산 근거 및 Excel 설명은 같은 뜻의 한국어로 표시한다. 과거 저장된 원문·직접 입력 근거·계산 코드·수치·단위·snapshot은 바꾸지 않는다. 새 AI 설명 지침에도 같은 사전을 제공하며 근거 참조 코드는 유지한다. 묶음 입력에서 미전송한 추가 설명은 다음 단계 저장과 함께 처리하고, 입력 단계와 수정 중 선택값은 초안 복원 대상이다.

검증 범위와 실제 호출 증거는 [최신 main 재질문 점검](verification/2026-10-23-main-no-repeat.md)에 기록한다. 외부 호출 없이 검사한 계약 조합과 실제 모델·앱·DB·Excel 실행은 구분한다.

## 실제 원문 인용과 반 시간 경계 정정 (2026-10-23)

AI가 실제 원문의 떨어진 완전한 문장들을 순서대로 인용했으면 이미 말한 정보를 다시 묻지 않는다. 임의 단어 조합·의역·역순·숫자/단위 변경은 허용하지 않는다. "3시간 반복"을 "3시간 반"으로 읽지 않으며 실제 반 시간 표현은 유지한다. 원본 AI 제안, 저장 근거, 사용자 직접 값과 과거 snapshot을 보존한다. 자세한 허용/거절 경계는 [추가 확인 계약](adaptive-intake.md#원문-문장-인용과-반-시간-경계-2026-10-23)을 따른다.

## 명시적 모름 표현 보존 정정 (2026-10-23)

자연어의 명시적 모름은 grounding.UNKNOWN_POLICY/unknown_evidence에서 공통 검증한다. "모릅니다"·"몰라요"·"알 수 없어요"·"미확인/확인 불가" 등은 UNKNOWN으로 보존하며 부정문이나 무관한 표현은 모름 근거로 사용하지 않는다. 숫자 0·무하중·NO를 대신 넣지 않는다. 원본 제안/출처, USER 우선권, 지연 재조정, 기존 snapshot은 보존한다. 자세한 표현과 반례는 [모름 표현 검증](verification/2026-10-23-unknown-evidence.md)을 따른다.


## 추가 질문 최소화 (2026-10-23)

계산기가 이미 완료한 범위의 작업 특징은 후보와 묶음 서식 모두에서 제외한다. 원래 미확인 값을 NO로 저장하지 않는다. 작업 설명을 먼저 보이는 답변 칸에서 한 번에 정리하고, 개별 수정은 접힌 영역에서 제공한다. 화면에 열거된 남은 작업 특징은 사용자가 명시적으로 한 번 확인하여 NO로 저장할 수 있다. 먼저 작성 중 설명과 직접 선택을 저장하며 새로 알려진 YES, 이전 USER 모름, 이미 확인된 값은 일괄 확인으로 덮지 않는다.

공통 intake POLICY.optional_photo_destinations는 사진 상황·방향·하중·자세를 결과의 선택 보완 서식에서 편집할 수 있음을 뜻하며, 그 자체로 모두 질문에서 제외한다는 뜻은 아니다. 사진 사용 여부·촬영 방향·하중 연결은 계산 또는 소유권에 필요한 경우 질문한다. MediaPipe/AI 사진 결과가 있는 동안 자세 수치·항목을 다시 묻지 않고 결과 단계에서 편집할 수 있게 한다. 사진을 사용하지 않기로 했거나 모름이면 필요한 자세 정보는 대체 입력으로 질문한다. 질문은 form_prompt_limit 범위에서 하나씩 보여준다. 미전송 설명/직접 수정은 결과 이동 전에 저장한다.

회귀는 test_question_minimization.py와 frontend-question-minimization.cjs에서 계산 완료 시 9개→0개, 남은 특징 한 번 확인, USER 모름/직접 YES 보호, 미전송 설명 우선 처리와 실패 보존을 검사한다. 실제 질문 수는 저장 필드 수 또는 접힌 사진 보완 수와 구분하여 사용자 답변 동작으로 검증한다.

## 질문 전 원문 교차확인 (2026-10-23)

새 자연어를 저장한 회차는 질문을 보여 주기 전에 FOLLOWUP 원문 교차확인을 한 번 수행한다. 다른 유효 질문이 있어도 앞선 제안·거절사유·현재 사실·원문 당시 사진 범위를 대조하여 빠진 명시 사실을 추가한다. 조회/중복 읽기, 직접 선택 답변만의 저장, plan=false에는 추가 호출하지 않는다. 기존 원문 검증·USER 우선권·지연 재조정·불변 snapshot을 유지하며 만료 조건을 추가하지 않는다. 상세 계약은 [원문 교차확인](verification/2026-10-23-source-coverage.md)을 따른다.


## 사진별 관측값 소유권 (2026-10-23)

사진 자세 값은 같은 원본 사진·신체 부위에만 적용한다. `manual.<scope>.<field>@photo:<photo_id>`가 정식 식별자이며 `photo_id`, 사진 방향, 원래 각도·신뢰도·측정 정책·엔진 근거를 함께 보존한다. 대표가 아닌 사진에서 읽은 값도 저장하지만 대표 사진의 빈 자세를 대신 채우지 않는다. 같은 사진에서 이미 확인한 값과 직접 모름으로 남긴 값은 다시 묻지 않는다. 남은 질문·묶음 서식에는 ‘왼쪽에서 찍은 사진 · 오른팔’처럼 사진 방향과 신체 부위를 표시하고 내부 식별자는 노출하지 않는다.

기존 `@default` 자세 값은 당시 대표 사진에만 연결하는 호환 별칭이다. 이미 저장된 사진별 USER 값·모름을 옛 자동 추정 별칭으로 덮지 않는다. 사진 교체·삭제 시 다른 사진의 사용자 값과 원문·시각을 보존하고 제거된 사진 값은 현재 계산에 투영하지 않는다. 동일 원본·모델 설정·근거를 반복 조회하거나 재시작하면 저장 JSON·revision·근거 시각은 변하지 않는다.

정면·후면의 몸통·목 기울임과 팔 벌림 관측은 원래 사진·신체 좌우별로 보존한다. 한쪽 팔의 최대 각도를 양팔에 복사하지 않으며 확실한 양성 측정만 자동 변환한다. 낮은 신뢰도·점수 경계·손 가림·손바닥 방향 불명확은 확인 대상으로 남긴다. 참고용 목 각도와 추정 3D 좌표는 기존 REBA 확정값으로 승격하지 않는다. 하루 시간·하중 추정, 대표 사진 선택, 양팔 REBA 완성·최댓값 계산은 유지한다.

기존 여섯 테이블과 TaskInput 2.0을 유지한다. `TASK.conditions.intake_session`의 선택 `photo_observations`와 fact 소유권·근거 메타데이터로 저장하며 물리 migration은 없다. 분석·출력 snapshot은 불변이고 Excel 입력 근거는 각 행의 실제 사진 식별자로 조회한다. 같은 범주값인 두 사진도 각자의 각도·인용을 유지한다. 세부 계약과 검증 한계는 [사진별 검증](verification/2026-10-23-photo-ownership.md)을 따른다.

### 명시 총시간과 불필요 계산 메타데이터 (2026-10-23)

원문을 그대로 복사한 단일 확정 하루 총시간과 제안 수치의 단위 환산이 직접 일치하면, AI가 함께 붙인 불필요한 합산 메타데이터 때문에 그 값을 거절하지 않는다. `grounding.DIRECT_TOTAL_POLICY`가 이 우선순위와 부정·불확실 경계를 관리한다. 예: “하루 전체 실제 작업시간은 5시간입니다”의 300분은 직접 저장하며, 별도 작업 피연산자가 인용에 없다는 이유로 재질문하지 않는다. 원 AI 제안의 calculation과 결정·원문 연결은 이력에 그대로 보존하고, fact에는 검증하지 않은 합산 근거를 저장하지 않는다. 틀린 총값·단위·잘린 복합 시간·범위·부정·불확실 총시간은 이 우선 규칙으로 허용하지 않는다. 단일 명시 총시간이 없는 합산은 기존 원문 피연산자·단위·순서·중복·산술 검증을 계속 거친다. DB 스키마·기존 snapshot·USER 우선권은 바꾸지 않는다.

### 실제 사진의 AI 관찰 (2026-10-23)

사용자가 사진 분석을 요청하는 기존 intake_turn 계획 실행에서 등록된 현재 크롭 사진을 실제 Luna 이미지 입력으로 보낸다. 계약은 `backend.vision.contract`, 서비스는 `service.photo_vision`이며 모델·추론 설정은 기존 ai_config를 공유한다. 사진별 동작·몸통·목·무릎·좌우 팔·좌우 손목·잡은 모습 9개 관찰과 보이지 않거나 모호한 이유를 보존한다. MediaPipe의 수치 각도와 구분한다. `conditions.intake_session.photo_vision` 및 동일 응답 경로에 사진별 원본/전송 JPEG SHA, task/photo 소유권, signature, raw_response, 연결·진단을 저장하고 base64/EXIF를 DB에 넣지 않는다. 여섯 테이블과 과거 snapshot은 유지한다.

등록 이미지/view/소유권·모델/추론/프롬프트·이미지 정책으로 캐시하며 읽기·재시작·직접 선택 답변·plan=false에는 이미지 API를 호출하지 않는다. 변경된 사진의 최초 요청은 사진별 병렬 실행하며 지연 응답을 시간으로 폐기하지 않는다. 다른 사진이나 삭제·교체된 작업에 이전 결과를 적용하지 않는다. 불확실/안 보임은 NO가 아니다. 허용된 분명한 boolean 자세와 4개 작업 특징의 YES만 별도 검증 경로로 source=VISION에 반영할 수 있다. USER(직접 모름 포함), 텍스트 AI, SAVED, 유효한 POSE를 우선한다. 사진에서 무게·힘·시간·횟수·정밀 각도·법정/의학 판정을 만들지 않는다. 상세는 [photo-vision.md](photo-vision.md)를 따른다.

### 사진 등록 세대와 사용자 사진 상황 우선권 (2026-10-23)

`photo_identity.REGISTRATION_KEY`는 새 PHOTO.metadata_json 행에 UUID를 부여하며 update로 교체하지 않는다. 물리 스키마는 유지한다. legacy 행은 경로/소유 ID로 결정되는 토큰을 읽고 조회 중 metadata를 쓰지 않는다. 사진 signature는 [view,photo_id,원본SHA,등록세대]이며 과거 triple을 호환한다. 같은 SQLite ID·파일경로·바이트·view로 재등록해도 이전 이미지 및 텍스트 사진 응답이 새 등록에 적용되지 않는다.

사용자가 context=NO로 사진 상황을 부정하면 raw 관찰과 캐시는 보존하되 VISION 소유 manual/작업특징 입력은 UNKNOWN으로 돌려 실제 투영값도 해제한다. USER·텍스트 AI·SAVED·POSE 소유 값은 건드리지 않는다. context=YES로 직접 정정하면 같은 이미지 관찰을 재사용하며 추가 이미지 API를 호출하지 않는다. 같은 turn의 텍스트 추출 뒤 저장에도 이 우선권을 적용한다.

### 현재 원문이 사진 AI 추정을 정정하는 경우 (2026-10-23)

원문 인용·대상·단위·사진 소유권 검증을 통과한 현재 텍스트 제안은 이전 source=VISION의 KNOWN/CONFLICT 추정보다 우선해 source=AI,state=KNOWN으로 저장한다. 다른 값은 충돌 재질문으로 만들지 않고, 같은 값도 텍스트 근거로 승격하여 사진 삭제 때 명시한 작업 특징이 사라지지 않게 한다. 과거 원문 인용만으로는 이 승격을 하지 않는다. USER(직접 모름 포함), 기존 텍스트 AI/SAVED/유효 POSE 값과 사진 변경·지연 보호는 유지한다. 사진별 manual 정식 조건과 대표 호환 alias는 같은 사진의 AI 근거를 가리키며 원래 사진 관찰 raw/cache는 수정하지 않는다.

context=NO이면 public 사진 관찰은 계속 보관·표시하되 계산·추출용 known_visual_observations는 빈 목록이다. YES로 직접 정정하면 기존 사진 캐시를 다시 사용할 수 있다. 사진과 무관한 직접 설명값은 유지한다.

## 결과 우선과 재질문 (2026-10-26)

- REBA가 미완성이어도 근거가 있으면 ‘확정 전’ 점수와 가정한 항목 수가 결과 화면·Excel·AI 설명에 같은 값으로 나타나야 한다. 등록한 분석대상 사진에 측정 근거가 없으면 가정 기준 점수와 관절 0/33개·측정 신뢰도 부족을 함께 보여 주며, 실제 측정값으로 부르지 않는다.
- 사진 상황 확인을 거부하거나 모른다고 답해도 REBA를 끝낼 질문 경로가 있어야 한다(막다른 길 금지).
- 사진을 바꾸거나 교체하면 사진에 묶인 답만 다시 묻고 그 이유가 보여야 한다. 작업 종류·시간·횟수 답을 다시 묻지 않는다.
- 검증 범위: 합성한 자세 좌표와 임시 DB로 서비스·질문·Excel·AI 요약 입력을 확인했다. 실제 사진, 실제 AI 호출 결과의 문장, 화면 클릭은 이 변경으로 확인하지 않았다.

## 자세 체크리스트와 한 번에 채우기 (2026-10-26)

- 사용자는 사진 자세 보완의 예/아니오 항목 18개를 체크리스트 한 장에서 해당하는 것만 체크할 수 있어야 한다. 체크하지 않은 항목은 사용자가 “확인 끝”을 눌러야만 해당 없음으로 채워지며, 누르지 않고 저장하면 미확인으로 남는다. 채우기는 칸만 바꾸고 저장하지 않는다.
- 이미 고른 칸, 사진 추정이 남은 칸, 확인을 기다리는 충돌 칸은 채우기·확인 끝·복사가 덮어쓰지 않는다. 이런 칸과 사진이 읽지 못한 각도 구간은 선택칸으로 직접 정하게 한다.
- 사진이 이미 잰 값은 묻지 않고 개수를 알려야 한다.
- 한쪽 팔·손목 항목을 반대쪽 값과 같게 채울 수 있어야 한다. 서식에 입력했거나 확인된(KNOWN) 값만 복사하고 추정·모름은 복사하지 않으며, 복사한 때의 값임을 근거 문구에 남긴다.
- 정면·후면 사진에서 읽은 값은 기준 사진 질문 옆에 ‘제안’으로만 보이며, 사용자의 선택과 저장 전에는 입력값·REBA 입력이 되지 않는다. 이 값은 AI 모델 요청에 싣지 않는다.
- 체크·채운 값은 사용자가 직접 선택한 값으로 저장하고, 선택 경위(체크·확인 끝·반대쪽·정면 사진)를 입력 근거 문구에 남긴다. 안내는 대화상자 안에서 보인다.
- 검증 범위: 합성한 판독과 서비스 코드로 질문 계획·체크·확인 끝·복사·근거 문구·모델 요청 내용을 확인했다(한 장 사진 기준 입력 접촉 약 31번이 약 12번). 실제 사진의 판독, 실제 앱 화면 클릭은 이 변경으로 확인하지 않았다.
