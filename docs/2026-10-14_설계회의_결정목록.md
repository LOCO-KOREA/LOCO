# 10월 14일 설계 회의 결정 목록

**목표:** M2 요구사항·화면·ERD·API 계약의 1차 확정. 아래 기본안은 회의 전 제안이며 팀 결정이 아니다. 결정 결과와 담당자를 적은 뒤 해당 문서의 담당자가 반영한다.

| ID · 결정할 것 | 회의 기본안 | 지금까지 보류한 이유 · 회의에서 확인할 것 |
|---|---|---|
| **D-API-01 화면 도구** | **제안: PySide6**로 로컬 Windows 앱을 만든다. 웹 주소 배포가 필수라면 Streamlit을 재검토한다. | 기존 문서는 PySide6·Streamlit+Edge·Flet을 후보로 두었다. 실제 화면 구현·설치·배포 형태를 정하지 않았고, 멘토의 웹 주소 요구 여부도 10/17 확인 예정이다. **회의 질문:** 발표와 배포가 설치 파일이면 되는가? 도구 담당은 누구인가? |
| **D-API-02 엑셀 라이브러리** | **제안: openpyxl**로 4시트 보조 보고서와 얼굴을 가린 대표 사진을 생성한다. | 현재 `ergo/report/excel.py`는 인터페이스만 있고 구현이 없다. openpyxl과 XlsxWriter 모두 후보이며 실제 사진 삽입·서식·파일 열기 검증 전이다. **회의 질문:** 기존 엑셀 템플릿을 읽어 수정할 계획이 있는가? 없으면 새 파일 생성 예제로 빠르게 선택한다. |
| **OI-01 자세·횟수 합산** | 4·5·9호의 조건을 **자세·위치별로 따로 판정**한다. 합산하면 결론이 달라지는 경우 `사람 확인`으로 남긴다. | 팀 문서는 3호 외의 합산 근거를 확정하지 못했다. **회의 질문:** 자동 합산 근거가 확인됐는가? 없다면 추정으로 합산하지 않을 것인가? |
| **OI-02 공동 들기 인원 보정** | 명시된 **8호에만** 인원수로 나누는 규칙을 적용한다. | 9·10호까지 같은 규칙을 넓힐 근거를 확인하지 못했다. **회의 질문:** 다른 호에 적용할 원문 근거가 있는가? |
| **OI-04 증상설문조사 범위** | LOCO는 자세 분석·판정의 **보조 자료**를 만들고, 별지 제2호 증상조사표는 조사자가 별도로 실시하도록 안내한다. 서식 전체 자동 작성은 이번 MVP의 완료 조건에 넣지 않는다. | 기존 FR-032는 Could이고 증상조사 화면·건강정보 보관 범위가 정해지지 않았다. **회의 질문:** 이 경계에 팀이 동의하는가? 화면·엑셀 안내 문구의 담당은 누구인가? |
| **OI-09 각도 근거** | 해설 원문을 받을 때까지 기존 2010·2011·2014년 자료의 값을 **출처를 밝힌 잠정 기준**으로 사용한다. 측정 불가·해석이 갈리는 자세는 `사람 확인`으로 둔다. | 고용노동부 해설 원문과 현행 판본을 아직 확보하지 못했다. **회의 질문:** 문의 회신이 있는가? 목 뒤로 젖힘 등 문구가 갈리는 사례를 어떻게 표시할 것인가? |
| **OI-11 확정 후 수정** | 확정을 풀고 `작성 중`으로 돌린 뒤 수정 사유와 이전 값을 이력에 남긴다. | 확정된 결과가 수정 후에도 그대로 유효한지, 재확정 책임을 어떻게 보일지 팀 합의가 남았다. **회의 질문:** 재확정 전 엑셀에는 `초안`으로 표시할 것인가? |

**회의 종료 전에:** 각 행의 결론(채택·수정·보류), 근거, 담당자를 적는다. 보류 항목은 임시 규칙과 다시 결정할 날짜를 남긴다. 화면 도구·엑셀 도구의 제안은 구현 가능성을 확인한 뒤 확정한다.
