# LOCO Electron 화면

실제 진입점은 `desktop.html`과 네이티브 ES module `desktop.js`다. 개발 실행·의존성·모델·패키지 안내는 루트 [README](../README.md)를 따른다. `electron/main.cjs`는 공통 Python JSON Lines 서비스를 실행하고 `preload.cjs`는 파일 선택과 서비스 호출을 제공한다.

| 모듈 | 책임 |
|---|---|
| `task-workspace.js`, `task/` | 작업 defaults·편집 상태·11개 기준 view·저장·이벤트 |
| `photo-workspace.js`, `photo/` | 가변 사진·배정/관찰·재연결·상세 기록·단계 이동 |
| `survey-intake.js`, `survey/` | 조사 상황·근로자 참여·익명 증상 응답의 입력/표시/이벤트 |
| `dashboard.js` | 저장된 조사 목록·현재성 요약과 이동 |
| `analysis-workspace.js`, `analysis/` | workspace 조립·공유 labels/DOM/state·진행/REBA/판정/설명/출력/설정 view·canvas·actions·navigation |
| `review-links.js` | 누락 필드 이동·GPT 계산 근거·상세 전후 비교 표시 |

전역 가짜 API와 이전 SVG 목업·별도 저장 adapter는 제거했다. 각 workspace는 자기 편집 상태를 갖고, 작업 편집기는 소유 필드만 최신 DTO에 합치며 `expected_revision`으로 충돌을 확인한다. 사진/수동값·불변 분석 snapshot·설명 목적별 적용 이력을 보존한다.

```powershell
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
npm.cmd --prefix frontend run test:electron
npm.cmd --prefix frontend run test:explanation
```

`build`는 실제 페이지의 자산·ES module import·문법을 검증한다. 배포 폴더 생성은 루트 `scripts/build_windows.py`가 담당한다. E2E는 별도 SQLite와 공개 예제 사진·합성 조사를 사용한다. 실제 외부 계정·현장 검증의 대체 증거가 아니다. [모듈 지도](../docs/module-map.md)와 [검증 대조표](../docs/local-verification.md)에 실행 범위와 남은 제약을 기록한다.

## 화면설계서 2.0 탐색 정렬

상단 메뉴는 S01 대시보드, S02 조사 목록·생성, S03 작업 목록·개요, S04 작업 조건·11개 기준, S05 사진 등록·배정, S06 자세 결과·REBA, S07 조사자 검토·GPT, S08 출력·전후 비교, S09 분석 진행까지 표시합니다. S10 설정은 내부 화면으로 유지하되 사용자 메뉴에서는 숨깁니다. `screens.js`가 메뉴와 작업 단계의 공통 기준입니다. 작업 개요와 기준 입력은 같은 작업 편집 상태를 공유합니다. S04의 저장 후 기준 초안 계산은 사진 없이 고시 초안만 재계산하고 S07로 이동합니다. 사진 분석은 S09로 이동하며 사진·태그·REBA를 요청합니다.

`npm run test:navigation`은 문서 화면 ID, 분석 진행/설정 화면 분기, 입력 화면 복귀 대기, 사진 없는 저장 후 계산, 로코 안내를 확인합니다.

## N01 삭제 확인

조사·작업 삭제는 이름과 ID, 삭제되는 DB 기록과 보존되는 원본 파일을 확인한 뒤 실행합니다. 취소·Esc는 삭제 요청을 보내지 않습니다. 삭제 중에는 확인창을 유지하고 중복 확인·취소를 막으며, 서비스 실패 시 편집 상태를 보존합니다. 작업 삭제는 기존 조사 출력 기록을 지우지 않습니다. 백업 선택은 서비스 연결 후 추가할 예정입니다. `npm test`에 삭제 확인 회귀 시험이 포함됩니다. 실제 Electron 화면·DB 사본 대조와 지정 교차 검증자의 확인은 별도 수행이 필요합니다.

## N02 데이터 저장 위치 확인

DB 경로는 작업 화면에 상시 표시하지 않습니다. 저장 연결에 문제가 있을 때만 상단 안내와 다시 확인 동작을 표시하고, 연결이 확인되면 안내를 숨깁니다. 간편 홈 설정 영역과 상단 S10 설정 탭은 사용자 화면에 표시하지 않습니다. 내부 S10의 “데이터 저장 위치” 창에서는 현재 Electron이 사용하는 DB 경로와 연결 확인 상태, 경로 복사·폴더 열기·다시 확인 버튼을 볼 수 있습니다. 긴 경로·한글·공백은 줄바꿈으로 전부 표시합니다. 실패하면 지정 경로는 유지하되 연결 실패를 표시하고 복사·열기를 막습니다. 브라우저 미리보기는 경로를 추정하지 않습니다. 메모리 DB에는 파일 작업을 제공하지 않습니다. 연결 상태는 마지막 확인 시점 기준이며, 위치 기능의 조회는 8초 뒤 실패 상태로 풀려 재확인할 수 있습니다. 늦게 도착한 응답으로 파일 작업을 실행하지 않습니다.

Electron은 시작 시 worker 작업 폴더 기준으로 DB 경로를 절대경로화하고 동일 값을 Python의 `LOCO_DB_PATH`에 전달합니다. 기본 경로와 통합 실행의 DB 지정은 유지하며 기존 파일을 자동 복사하거나 병합하지 않습니다. 확인은 기존 `list_surveys` 조회를 사용하며 Python 서비스와 저장 코드는 변경하지 않습니다. DB 선택·실행 중 전환·미저장 입력 처리는 S05 협업 후속 범위입니다. `npm test`는 경로·오류·버튼 상태를 확인하고 `npm run test:database`는 실제 main/preload 코드와 Python·SQLite의 경로 일치를 새 검증 DB에서 대조합니다. 후자의 네이티브 창·클립보드·폴더 열기는 mock이며 실제 GUI 검증은 별도입니다. `LOCO_VERIFY_PYTHON`으로 검증 Python을 지정할 수 있습니다.

## Windows 앱 아이콘

창과 실행 중 작업표시줄에는 기존 LOCO 로고의 원형 심볼을 사용합니다. `assets/app-icon.svg`가 원본이며 PNG와 여러 크기의 ICO를 함께 둡니다. 아이콘 변경은 화면 새로고침이 아닌 앱 종료 후 재실행으로 반영됩니다. Windows 앱 ID는 `kr.loco.desktop`입니다. 포터블 빌드는 출력 복사본의 `LOCO.exe`에도 같은 ICO를 넣고 아이콘 파일 해시를 manifest에 기록합니다.

## 공통 디자인

`design-system.css`는 마지막에 로드하는 공통 시각 기준입니다. 로고의 보라색, 상태 색상, 카드·컨트롤·입력 크기와 선택 표시를 한곳에서 관리합니다. 화면별 CSS는 공통 색상 토큰을 참조하며 그리드와 사진·표 전용 배치를 유지합니다. Pretendard는 기존 로컬 폰트를 사용합니다. 사진 관절 범례의 좌우 색상은 분석 의미를 보존합니다.

## 조사 편집과 TOP

S02의 새 조사·목록 항목·선택 조사 수정에서 중앙 편집창을 엽니다. 좌측 5개 항목은 같은 폼의 표시만 전환하므로 입력과 익명 응답을 유지합니다. 닫기·Esc는 임시 입력을 유지하며 DB 저장은 하지 않습니다. 저장 성공 후 작업 등록 화면으로 이동하고 실패 시 편집창에 오류를 표시합니다. 화면 내부의 중복 단계 탭을 제거하고 상단 메뉴로 이동을 통일했습니다. 각 페이지 오른쪽 아래에 TOP 버튼이 있습니다. 고급 편집의 로코 안내 캐릭터는 TOP 버튼 위에 간격을 두어 기본 배치합니다. 생성·수정 편집창에는 TOP 버튼을 두지 않습니다. 자동 시험은 편집 상태 유지·저장 중 닫기 방지를 확인하며 실제 창의 배치와 전체 Electron 흐름은 별도 시각 검증이 필요합니다.

버튼 간격은 일반 묶음 12px, 사진 행·후보의 작은 묶음 8px, 입력·본문에서 실행 버튼 묶음까지 20px입니다. 새 버튼 묶음은 `button-group` 또는 분석 영역의 `toolbar`를 사용하고, 본문 아래에는 `section-actions`를 함께 지정합니다. 좁은 폭에서는 줄바꿈하며 상단 메뉴·행 선택 버튼에는 본문 여백을 추가하지 않습니다.

입력칸 placeholder는 입력 예시·안내 문구입니다. 예시를 기본값으로 저장하지 않으며, 예시·작성 방법이 필요한 필드에 “작성하세요. 예: …” 형식으로 문구를 지정합니다. 서술형 textarea는 안내와 예시를 줄바꿈하고 두 내용이 보이도록 최소 높이를 확보하며, 숫자칸·이름칸과 지정하지 않은 항목에는 반복 안내를 넣지 않습니다. 날짜·선택 항목은 기존 브라우저 입력과 미입력 선택을 유지합니다. 공통 문구는 `input-placeholders.js`에서 관리합니다.

## 간편 흐름과 시험 실행

첫 화면은 홈 → 사진 넣기 → 1차 점수 → 로코 질문 → 결과 → 검토·설명 → Excel의 한 흐름(`quick-flow.js`)입니다. 질문 화면 맨 위에 작업을 한 문장으로 쓰면 AI가 질문 칸을 근거 구절과 함께 채우는 "한 줄 입력"이 있고, Excel 화면은 저장 전에 시트(유해요인조사표·부담작업 해당 여부·체크리스트 등)를 탭으로 미리 보여 줍니다. 옛 10개 화면은 오른쪽 위 "고급 편집"으로 엽니다.
작성 중인 분석은 브라우저 저장소(`loco.quick.draft.v1`)에 보관되어 홈의 "이어서 하기"로 이어 갑니다. 같은 기록인지 조사 번호·제목·생성 시각으로 확인합니다.
질문 화면에서 Ctrl+Enter는 "다음", 고급 편집의 작업 화면(S03·S04)에서 Ctrl+S는 저장입니다.

1차 REBA와 최종 REBA 점수 아래에는 1~15 색상바가 표시됩니다. 녹색부터 빨강까지 1점 무시 가능, 2~3점 낮음, 4~7점 보통, 8~10점 높음, 11~15점 매우 높음을 나타내며 현재 점수를 테두리와 삼각형으로 표시합니다. 큰 점수 숫자도 해당 구간과 같은 색으로 표시합니다. 점수 범위와 위험명은 실제 색상 구간 바로 아래에 정렬합니다. 미계산이면 위치를 표시하지 않고, 1차 점수의 부담 없음 가정은 그대로 안내합니다.

검토·출력의 “③ 쉬운 설명”은 요약과 확인할 항목을 먼저 보여 줍니다. 기준별 상세 설명·개선 제안·원문 편집은 필요할 때 펼칠 수 있으며, 편집과 적용에는 기존 전체 원문을 그대로 사용합니다.

E2E 시험 창이 화면에 뜨지 않게 하려면 `LOCO_HIDDEN=1`을 설정합니다. 창을 화면 밖으로 보내고 작업표시줄에서도 숨기며(완전히 숨기면 화면 캡처가 멈춥니다), 일반 실행에는 영향이 없습니다.

## N05 포터블 서비스 사전 점검

`requirements-build.txt`의 CPython 3.12 x64 환경으로 `scripts/build_windows.py`를 실행합니다. 모델은 공식 해시를 확인한 파일만 `models/movenet_lightning.tflite`에 배치하며 사용자 DB·사진·키를 패키지에 넣지 않습니다. 새 패키지 경로는 `.local/latest-package.txt`에 기록됩니다.

`python -B tests/portable-service-smoke.py`는 최신 패키지의 frozen 서비스 EXE를 Windows 기본 PATH만 남겨 실행합니다. 새 임시 한글·공백 DB와 흰 합성 PNG를 사용하며 실제 CPU 추론의 17개 유한 좌표, 직접입력·저장 재실행·오프라인 설명·공식 서식 구성 Excel(설명을 적용한 조사 7시트, 작업 없는 조사 6시트)·잘못된 모델 실패를 확인합니다. 외부 GPT 키를 자식 프로세스에서 제거하므로 실제 계정 호출은 없습니다. `LOCO_VERIFY_PACKAGE`로 점검할 패키지 폴더를 지정할 수 있으며 manifest의 코드·모델 해시와 현재 소스가 일치해야 합니다.

이 검증은 개발 PC의 서비스 EXE 사전 점검입니다. 별도 Windows PC·실제 Electron 창 조작·현장 사진 정확도·인쇄·실제 외부 GPT 검증을 대신하지 않습니다. 소스가 미커밋이면 manifest에도 미커밋 상태로 남기고 최종 전달 전 커밋 버전으로 다시 빌드합니다.

## 적응형 간편 입력 (2026-10-23)

사진·작업 설명 → 자동 정리 → 추가 확인 → 결과·검토·Excel 흐름이다. `intake/client.js`가 서버의 `intake_contract`를 조회하고 메서드·정책·필드 정의를 재사용한다. `intake/view.js`는 해당 계약의 선택지·단위로 필요한 필드만 그린다. 값은 SQLite에 자동 저장하고 localStorage는 이어서 열 작업의 위치와 보내기 전 문장만 보조 보관한다. 실제 Electron/Python/SQLite/MoveNet/Excel과 loopback SDK 검증은 `node tests/adaptive-intake-e2e.cjs`로 실행한다.

기본 추가 확인은 `intake/dialog.js`의 대화 팝업이다. AI 자동 정리 직후 열리며 한 번에 질문 하나를 제공한다. 선택지가 있으면 선택지와 ‘모르겠어요’를 기본 표시하고 답변창·전송 버튼은 렌더링하지 않는다. ‘직접 설명하기’를 선택하면 문장 입력을 열며, 숫자·텍스트 질문은 답변창을 기본 제공한다. 같은 질문의 초안은 유지하고 답변이 정상 처리되어 다음 선택형 질문으로 넘어가면 작성 영역을 다시 접는다. 초기 작업 설명이나 답변이 AI 실패로 미처리 문장 초안으로 남으면 질문이 달라져도 작성란을 열어 유지한다. 선택형의 ‘모르겠어요’는 선택지에만 두고 AI 오류 재시도 버튼은 접힌 작성 영역 밖에 제공한다. 답변 뒤 정리·저장·다음 질문 계획을 진행하고, 기본 페이지에 전체 필드나 숫자 입력 목록을 표시하지 않는다. 팝업에는 처리 중·실패만 일반 안내로 표시하며 모델·추론 강도·연결 성공 상태는 노출하지 않는다. 숫자 등 직접 편집은 요약의 ‘수정’을 선택할 때만 열린다.

`npm --prefix frontend run test:adaptive:full-live`는 실제 외부 OpenAI까지 연결해 입력 → 후속 답변 → 저장값 수정 → 모름 → 재실행 → 결과 → AI 설명 적용 → 검토 → Excel → 재실행을 검증한다. 기존 프로세스의 `OPENAI_API_KEY`, 시험용 `LOCO_LIVE_AI=1`, `LOCO_LIVE_MODEL`이 필요하며, DB/프로필은 `.local/full-live-e2e-*`에 따로 만든다. 항상 화면 밖·초점 불가 Electron 창으로 실행하여 사용자의 마우스·키보드·기존 앱 창을 조작하지 않는다. 사진/저장 경로를 선택하는 네이티브 파일 대화상자만 자동 지정한다. 성공 후 `python tests/verify_local_artifacts.py <검증 폴더> 1`로 SQLite와 실제 Excel을 독립 대조한다.

AI 모델·추론 강도·시간/토큰 한도는 내부 설정 기능에서 바꾸며 공통 계약 `ergo/ai_config.py` → `get_settings.gpt_contract` → `ai-settings.js`를 쓴다. 초기 환경변수는 `LOCO_AI_MODEL`, `LOCO_AI_REASONING_EFFORT`, `LOCO_AI_TIMEOUT_SECONDS`, `LOCO_AI_MAX_OUTPUT_TOKENS`이고 저장된 설정이 우선한다. 현 기본값 gpt-6-luna/xhigh를 입력 정리·추가 질문·설명 생성 모두 공유한다. Live 시험의 `LOCO_LIVE_MODEL`과 `LOCO_LIVE_REASONING_EFFORT`로 요청 조합을 명시하고 실제 응답 모델/effort를 receipt에서 확인한다.

## 내부 PDF 구현과 사용자 출력

사용자 출력은 Excel 미리보기·저장을 유지합니다. 간편·고급 화면에는 PDF 모드·카드·버튼·미리보기 진입을 표시하지 않습니다. PDF 모듈과 `preview_pdf`/`export_pdf` API는 호환을 위한 내부 구현으로 유지합니다. 내부 PDF 구현을 실행하는 개발 환경에는 `requirements-desktop.txt`의 reportlab/pypdf와 `ergo/report/templates`, assets가 필요합니다. 내부 PDF는 원본 칸을 넘는 긴 작성 내용만 별첨에 보존하고, 분석 상세·빈 사진 슬롯·보완사항은 자동으로 붙이지 않습니다.

추가 확인 팝업은 서비스의 `progress`로 가로 막대·퍼센트와 확인한/전체/남은 항목을 표시합니다. 질문 배열 길이나 저장 fact 개수로 전체 질문 수를 추정하지 않으며, 답변에 따라 대상 수가 달라질 수 있음을 안내합니다. 100%는 질문 확인 진행이며 계산 완성과 별개입니다. 팝업 제목·하단 버튼은 고정하고 본문만 스크롤하며 답변창은 16px·최소 높이 120px입니다.

좌우 짝 질문(2026-10-23)은 서비스의 `questions[0].paired_question`을 사용해 같은 자세 항목의 좌우 또는 좌우 사진 방향을 한 화면에서 선택한다. 두 선택 영역은 기본 두 열이며 좁은 폭에서는 한 열이다. 각각의 ‘모르겠어요’와 선택 상태를 유지하고 양쪽 응답이 모두 있으면 ‘선택한 답변 저장’으로 두 `answers`를 한 번 저장한다. 알려진 쪽·USER 모름은 재질문하지 않으며 미선택 쪽에 0·NO·반대쪽 값을 채우지 않는다. 선택형 직접 설명·실패 초안 보존·필드 수 기준 진행률을 유지한다.

관련 항목 묶음과 대기 표시(2026-10-23): `questions[0].answer_questions`와 `group_title`이 있으면 `intake/dialog.js`가 현재 미확인인 관련 항목을 선택 상자 행으로 표시한다. 몸통·목 6개, 다리 3개, 움직임·힘 4개, 양팔·손목 추가 자세 8개, 작업 특징 최대 9개를 묶으며 하나 이상 선택하면 선택한 member만 `answers`로 보낸다. ‘선택 안 함’은 명시적 모름·NO·0과 다르며 답변으로 만들지 않는다. `answers`만 있고 `text`가 비면 외부 AI 없이 저장·다음 질문을 계획한다. 자유문장과 빈 재시도는 AI 경로를 유지하며 미처리 문장 초안은 별도로 보존한다. 진행률은 화면 수가 아닌 확인 필드 수이므로 남은 40개가 질문 화면 40개를 뜻하지 않는다.

`intake/activity.js`는 일반 페이지·팝업의 처리 중 회전 표시·이동 막대와 실제 경과 초를 제공한다. 경과 숫자를 매초 갱신하고 15초/45초부터 대기 안내를 바꾸며 전체 폼을 다시 렌더링하지 않는다. 처리 중 막대는 임의 완료율·예상 잔여 시간이 아니다. 움직임 줄이기 설정에서는 두 애니메이션을 멈추고 경과 시간은 유지한다. 사용자 화면에 모델·추론 강도·연결 성공 상태는 노출하지 않는다.
